> **本章命题**：官方允许你改的那一层，停在「新的交互方式」之前。数据包能让你在不改游戏程序的情况下当关卡设计师，不能让你发明第二种挖掘、第二种使用。这条边界不是文档没写完，是收编：把改内容的人请回世界目录，把加新系统的人留在模组加载器那一侧。

## 问题

下载一张宣传「纯原版 RPG」的地图，用未改装的客户端就能进世界。职业、任务、副本都在，不用装 Forge。打开世界文件夹才看见：职业写在计分板上，任务是函数和命令方块，掉落是战利品表。[《命令、数据包与地图》](/design/commands-datapacks) 玩起来像模组。拆开看，它仍骑在官方那套挖、放、合成上。

要回答：官方承认的扩展面，边界画在哪？可被证伪的说法是：数据包再长几年就能替代 Forge，今天加不出新系统只是工期。只要还存在「能改配方、不能把挖掘改成另一种交互」、只要自定义物品仍只能往现有组件上贴字段、只要 Bedrock 的行为包进不了 Java 模组加载器，这句话就不成立。

上一章把模组写成：正作没签稳定接口时，往程序里打补丁就变成接口。[《模组与插件架构》](/impl/mod-architecture) 数据包是官方承认的那一层。承认了，就有边界。边界要画成能核对的表，不能画成情怀。物品那一章已经预告过：JSON 能规定这件东西长什么样、合成出什么，规定不了官方组件清单以外的新交互。[《物品、库存与合成》](/impl/items)

## 为什么有了数据包还是要写 Java

因为数据包改的是数据，不是程序。数据能说：这个合成形状产出这把剑，这张表掉这个战利品，这只进度何时触发，这片噪声长成哪种地形。程序才能说：世界上多一种会自己走动的方块行为、多一种新窗口、多一种现有物品组件里没有的因果。命令和函数把服务器运营者变成关卡设计师。关卡设计师调度的是已经存在的交互：传送、给物品、改计分板、触发进度。调度不是发明。发明新交互，必须改游戏启动时加载进来的那些类。

1.13 把数据包做成世界目录里的文件夹，原版自己也是一份内置包。[^dp] 这是产品上的让步：以前要模组才能改的掉落和配方，现在跟着存档走，不必改启动器里的游戏文件。让步很实。让步的尽头写在同一份产品里——实验性功能常常再塞一份包，仍然加不出第二种挖掘。物品改成组件之后，数据包能往一件东西上贴官方已经提供的字段，比如食物、工具规则、自定义数据。[《物品、库存与合成》](/impl/items) 贴的是模式以内的字段。模式以外的交互，还是要写系统。系统在 jar 里。jar 属于上一章那条模组河。

所以「有了数据包还要写 Java」不是程序员舍不得 JSON。是两层作者席。一层住在世界目录的 `data/` 里，改完可以热重载，出错往往卸包就能回到昨天。一层住在字节码里，能给游戏加新的行为类型。新行为加不进热重载：必须重启，常常还要等大版本。官方把第一层做成产品承诺，把第二层继续留作未承认。承诺与未承认之间，就是边界。

边界还能从「出错炸到哪」反着读。数据包写错一张表，世界可能加载失败，拿掉这份包，存档多半还在。模组切错一个方法，游戏拒绝启动；卸掉模组，仍可能留下半份映射、半份 Mixin 配置、半份「我以为这一版已经兼容」。失败容易退回，是官方愿意把数据层做成产品的原因之一。失败很难退回，是加系统的作者必须熬过「每个大版本模组全断」的原因。可逆与不可逆，比「JSON 好写、Java 难写」更接近这条边界。好写是表面。炸到哪一层，才是产品选择。

Bedrock 的行为包看起来更宽：JSON 能定义实体行为，脚本 API 能跑 JavaScript。[^bp] 宽，仍是沙盒。沙盒进不了任意渲染后端，也进不了 Mixin 那种「切开正作方法」的补丁。不要把行为包听成 Forge。它是另一条产品线上的温和扩展，后面 Marketplace 那一章会写审核怎么反过来限制能做什么。

## 命名空间世界

1.13 扁平化之前，方块和物品用数字号。扁平化之后改成带前缀的名字：`minecraft:stone` 是官方的石头，`某张地图:铜锭` 是第二作者的铜。[^ns] 冲突从「87 号到底是谁的」变成「这个前缀是谁的」。前缀能随包热更新，所以数据包能活在世界目录里。前缀仍要唯一，所以两个包抢同一名字仍会失败——失败发生在加载时，而不是玩到一半才发现 17 号被占用。失败得早，是进步。进步没有取消产权问题：谁拥有 `minecraft:` 以外的那些词。

标签把许多名字收成一组。`#minecraft:logs` 是官方的「所有原木」。模组曾经用「矿辞」（Ore Dictionary）做同类事：告诉配方「凡是原木都收」。正作把这件事收成标签，是追随模组。[《物品、库存与合成》](/impl/items) 追随之后，数据包能写「这个配方吃所有原木」，不必列举每一种。列举是内容。分组是规则。规则仍停在「哪些已经存在的对象算一类」，不是「世界上多一种新的物理种类」。

命名空间也改变了作者怎么撞车。以前抢数字号，常常进了世界才发现：箱子里的东西变成另一件。现在抢前缀，冲突提前到进世界之前。提前是文明。文明没有取消产权：`minecraft:` 仍是第一作者的词根，自定义前缀仍是社区口头约定，没有中央登记处。约定能活，因为撞车还不太多。撞多了，就会出现「请改你的 id」这种交涉。交涉是数据包这条河上的政治，比 Mixin 抢同一个方法温和，仍是政治。温和，因为改 id 不必切开程序。仍是政治，因为两张地图想放进同一个世界时，名字就是边界。

世界生成后来也进了数据包：噪声、生物群系、结构配置。进了，不等于你能写一个新的洞穴算法引擎。你在调官方生成管线的旋钮。[《世界生成管线》](/impl/worldgen-pipeline) 旋钮很深。深，仍是数据。数据换不了「区块必须按固定阶段走完生成」这份程序。程序一换，那是模组或正作自己的大版本，不是热重载一张 JSON。

每份包还带一个格式号（`pack_format`）。游戏版本一涨，号跟着涨，旧地图要改文件才能继续用。改文件比 Mixin 对不上方法轻，仍能让一张旧冒险图卡在某一版。轻，是产品上的优待：优待关卡作者，不优待加新系统的人。优待要写进边界，免得「数据包每年都更强」被听成「边界在消失」。更强的是旋钮。旋钮拧尽，管线还在。管线在程序里。

## 能做 / 必须写代码 对照表

表是验收，不是百科。「能」指：只改官方数据层、不改游戏程序就够。「必须写代码」指：要新的行为类型、要往程序里打补丁，或要改网络包的形状。

| 你想做的事 | 走哪一层 |
| --- | --- |
| 改配方、战利品、进度、谓词、物品标签 | 数据包 |
| 换贴图、模型、声音、语言、部分着色器 | 资源包 |
| 用函数和命令方块做任务、副本、倒计时 | 数据包 + 命令（仍是调度已有交互） |
| 调噪声、生物群系、结构放置的数据 | 数据包（调管线，不换管线） |
| 给物品贴上已有组件（食物、工具规则、自定义数据） | 数据包能贴；新的组件类型要写代码 |
| 新的方块每刻行为、新的碰撞形状、新的红石元件 | 必须写代码 |
| 新的窗口、新的网络字段、新的客户端预测规则 | 必须写代码 |
| 改方块更新顺序、改渲染批处理、改主循环怎么排班 | 必须写代码（常是 Mixin） |
| 领地、权限、小游戏重置、进服规则 | 服务端插件（改这台服的法律，不是新的物理） |
| 任意新交互（第二种挖掘、第二种使用） | 必须写代码 |

对照不是羞辱数据包。对照是：这条温和通道已经很宽。宽到能养活冒险地图、解谜、RPG 图。宽到替代不了模组加载器。替代不了，是产品选择：没装模组的人仍能打开那张 RPG 图。打开的那一刻，游戏还叫 Minecraft。骨头——挖、放、合成这些交互本身——还是官方的。

1.20.5 之后物品组件更富，表的中缝会往下移一格：更多「这件东西长什么样、吃起来怎样」能写进 JSON。中缝移了，底线还在。底线是新的交互方式。交互写在类里。类不进 `data/`。

函数看起来像程序。它是命令的批处理：按游戏刻调用已经存在的指令，改计分板，传送，给物品。批处理能做出倒计时和职业。批处理加不出「这把镐走另一套硬度公式」——除非这套公式已经被收成官方组件。未收编的行为，函数只能假装：用粒子假装特效，用传送假装击退，用替换方块假装新方块。假装是地图作者的美德。美德到头，就是表上「必须写代码」的那些行。玩家拆穿假装时，会去装模组。装模组，不是数据包失败。是边界被摸到了。

## 资源 vs 数据

资源包改看见和听见。数据包改规则和内容表。分工是故意的。贴图可以关，规则关了世界会换掉落和法律。于是资源包最容易进教育版、进「安全的用户内容」；数据包次之，因为它能改掉落和配方，已经开始碰财产；模组最危险，因为它能改下一游戏刻发生什么。危险不是道德评判。危险是：出错会炸到哪，审核要管到哪。

同一件事会跨两包。自定义方块若只换外观，资源包够。若要让这副外观对应一种新的熔炉行为，数据包不够，必须写代码，再让资源包去画。完整模组日常就是这样跨层。官方把资源包和数据包拆开，是为了让只换皮的人不必卷入「每个大版本模组全断」的兼容矩阵。拆开成功。成功的代价是：口语里的「资源包」常常被拿去形容一切用户内容。形容错了，边界会糊。糊了，有人会以为装一个包就能加上工业模组那种电网。加不了。电网是新系统。新系统在上一章。

资源包还能换核心着色器和音效事件名。换，仍是皮肤：石头碎的声音可以变成玻璃，挖掘怎么计算不变。数据包能改这格石头掉什么。掉什么是财产规则。财产规则已经比皮肤硬，仍不是新的挖掘。硬规则和新行为之间，就是官方愿意收回的最大范围。范围以内，世界目录就是作者席：地图跟着存档走。范围以外，必须改启动器里的游戏，才当得了作者。范围画清楚，地图作者才知道自己在哪条通道上。通道混了，整合包会把数据包当模组卖，玩家在崩溃日志里找不到 Mixin——因为根本没有往程序里打补丁，只有一份格式号写错的包。

Java 版的资源包和数据包各有格式号，涨一次，旧包要改文件。改文件按份计，比给二十年存档做物品迁移轻，仍会让地图卡在某一版。Bedrock 把外观和规则做成附加包配对，上 Marketplace 还要过审核。配对不是 Java 世界目录里那两个文件夹。配对是另一条产品线的扩展面。两边能合写的是：皮肤和规则分开，比全塞进一个 jar 更容易分发。必须分开写的是：谁有权把包发给别人。

<Note>
资源包能让石头换一张脸。数据包能让这张脸掉另一张战利品表。脸和表都换不了挖掘。挖掘还是官方那只手。
</Note>

## 政治含义

所谓「数据驱动」，是温和模组的产品政治。政治有两面。一面给地图作者官方通道：规则写在世界目录里，玩家不用改装客户端。一面把加新系统的人明确关在门外：你要新的方块行为、新窗口、新因果，去加载器，去大版本发布夜，去兼容矩阵。门外不是惩罚。门外是：默认世界必须仍能被没选择工业模组的人打开。默认生存一旦被内容塞满，空出来给玩家发明目标的那截循环会变成必须跟产线走的关卡。[《模组作为设计方法》](/design/mods-as-method)

官方因此可以收编内容，而不提供真正的模组接口。收编配方、进度、世界生成旋钮，看起来每年都更开放。开放的是数据。数据越开放，越能说「你们要的内容已经能做」。这句话会挡住「请给十年稳定的模组 API」。挡住，对正作是迭代速度：快照里可以改物品结构、改渲染，不必先给第二作者开两年意见征集。对第二作者是：改内容的人被请回世界目录，加系统的人继续往程序里打补丁。补丁就是未承认的接口。未承认的利息，上一章写过。

实验性数据包把这层意思写得更直：新功能先以包的形式进来，开关开在世界里。开关能关，说明还不是默认行为。变成默认之前，可以撤回。撤回对数据作者是版本风险。风险比 Mixin 对不上方法小，因为包可以卸。卸不掉的是期待——期待「再过几年，包也能加新交互」。期待落空，不是工期没做完。是边界。边界在对照表里。表上必须写代码的那些行，就是官方扩展面的墙。

墙还有教学上的用处。教程可以说「不用模组也能做 RPG」，把新玩家留在官方通道里。留，是品牌还叫 Minecraft。留，也会训练错一种期待：所有好想法都应该能写进 `data/`。好想法若是新的交互方式，进不去。进不去时，社区会发明更多假装。假装堆厚，性能和可维护性会先垮，然后有人写模组把假装收成真正的新行为。收成新行为之后，正作偶尔再收编一勺——漏斗、合成器。一勺是一种新的官方交互。一勺不是工业模组那种整套电网。电网留在门外，默认生存才还留得住「目标由玩家自己发明」这一截。

<Constraint name="扩展面停在新交互前" verdict="地基" chain="数据可热更 → 程序才有新行为 → 官方只承诺数据层">
抄走命名空间、标签、配方 JSON，丢掉「新交互必须写系统」，你会得到能换内容的演示，失去十年地图工业与模组河并存的产品。温和是收编。收编不是模组 API。API 若承诺十年稳定，正作会变慢。变慢可以。变慢是另一份合同。这份合同把新行为留在门外。
</Constraint>

进世界没有加载器。职业是计分板。玩完仍是挖、放、使用那几只手。口令「原版能做」能当广告，因为广告说的是调度已有交互。调度可以很强。强，不等于游戏里多出了一种新的挖掘。

<Alternative title="若数据包能注册新的方块行为类">
地图和模组的边界会再糊一截。热重载会碰到类加载。出错会从「卸包」变成「进程起不来」，审核也会变难。你得到更完整的官方通道。你失去的是：没装新系统的人仍能安全打开任意世界目录。安全是产品选择。选择了窄门。
</Alternative>

下一章把镜头对准这扇门为什么是 Java 写的：2009 年选这门语言证明了什么，又卡住了什么。语言是历史偶然。偶然能证明可移植与模组性，不能证明必须永远用它。

## 这一章留下什么

- **爱好者**：数据包能改掉落、配方、任务，改不了「挖」变成另一种游戏。资源包只换外观和声音。换完皮的世界，交互仍是官方那几只手。原版 RPG 是调度已有指令，不是长出新骨头。
- **开发者**：能抄走的是命名空间加标签、数据与资源分家、把温和扩展做成可随世界分发的包。能一起抄走的还有对照表：内容与规则走数据，新交互、新窗口、新因果走代码。抄不走的是扁平化之后的包格式号、Java 包与 Bedrock 附加包各自的审核范围；以及地图工业已经把函数当关卡语言。你若宣称数据层能替代模组 API，是在把调度说成发明。调度可以很强。发明仍发生在游戏启动、类被加载的那一层。

[^dp]: Java 1.13 引入数据包，用于进度、配方、战利品、函数、标签等；原版自身以数据包形式加载。见 [Data pack](https://minecraft.wiki/w/Data_pack)、[Java Edition 1.13](https://minecraft.wiki/w/Java_Edition_1.13)。

[^bp]: Bedrock 行为包用 JSON 定义实体与世界规则，并可包含脚本 API 的 JavaScript。见 [Behavior pack](https://minecraft.wiki/w/Behavior_pack)；Microsoft Learn，《Differences between Bedrock and Java》，<https://learn.microsoft.com/en-us/minecraft/creator/documents/differencesbetweenbedrockandjava>。

[^ns]: 扁平化之后，方块与物品使用 `命名空间:路径` 标识符。见 [Java Edition 1.13](https://minecraft.wiki/w/Java_Edition_1.13)、[Resource location](https://minecraft.wiki/w/Resource_location)。
