> **本章命题**：语义差异比性能差异更致命。Bedrock 不是「优化过的 Java」。它是另一次实现：换了语言、换了扩展面、换了一部分因果。因果一换，同名的游戏会拒绝同一张原理图、同一份存档、同一条模组河。

## 问题

家长买了手机上那个叫 Minecraft 的东西，以为电脑上的模组世界也能进去。Java 玩家把红石机器截图发给主机上的朋友，灯不亮——[《两条产品线：Java 与 Bedrock》](/history/java-bedrock)写过：收银台捆上了，世界没有捆。

要回答：语义差异为何比性能差异更致命？可被证伪的说法是：这只是移植损耗，C++ 跑得快一些，功能会对齐；Bedrock 就是优化版。只要还存在准连接只活在一边、只要还存在存档打不开、只要 Marketplace 的附加包进不了 Forge，这句话就不成立。损耗可以补。语义分叉补完会变成另一种玩法。另一种玩法可以很好。它不是同一台虚拟机上的同一份口令。

上一章（[《Java 版运行时》](/impl/java-runtime)）把 Java 写成偶然。偶然已经被换过一次。换完发生了什么，是本章的证据。禁止的读法写在方法里：不得把这边说成那边的皮肤。

## 另一次实现不是移植

移植假定同一份规格，换一套编译器。Bedrock 从 Pocket Edition 起就不是这份规格的缩小版。它要进触控、进商店、进主机认证、进跨设备联机。要进的房间，对「谁可以改程序」的答案相反：商店要审核，主机要分级，手机要省电。房间反过来塑造引擎——不是先有一份 Java 规格再翻译成 C++。是另写一份能进房间的程序，再用品牌把它叫做同一个词。

所以「另一次实现」是产品决策，不是工程偷懒。决策证明语言可换。决策同时证明：换语言时若没有同一份语义测试集，测试集会在墙上分家。飞行器停的那一侧，会说另一侧坏了。另一侧会说这边根本没这个功能。两边都对。对的不是性能。对的是：没有共同的未定义行为宪法。Java 把一份怪癖标成 WAI。Bedrock 从未签署。未签署，就不是同一台隐式 VM。

「Parity」作为官方口语，听起来像工期表。工期表假定有一份共同规格在两边逐项打勾。红石那一章（[《红石的实现》](/impl/redstone)）已经说明：规格在 Java 这边有一半写在墙上。墙上的东西无法打勾到「没有准连接」的那一侧而不立法。立法会停飞行器，或逼另一侧长出准连接。两边都不想付这笔。于是 parity 变成内容清单对齐：同一只生物、同一张新木头。内容对齐，因果不必对齐。内容对齐能上新闻。因果不对齐，灯不亮。灯不亮更致命，因为它发生在已经以为「同一款游戏」的房间里。

性能差是真的，尤其在能效和低端设备上。真，仍是次要句。次要句当主句，才会长出「Bedrock = 优化版」。优化版假定同一份玩法，只是帧更高。帧更高却少了准连接，不是优化。是另一种红石。另一种红石可以更干净、更好教。干净会让十年教科书作废。作废是语义事件。语义事件比跑分贵。

贵，还因为玩家已经用口令住进某一侧。口令不能靠补丁包一夜翻译。翻译要改手、改农场、改「这台机器该不该亮」。改完，品牌仍叫同一个词，房间里已经是两套物理课。物理课分班，比帧数分档更早结束「优化版」这个称呼。

## 技术栈与扩展模型

C++、自研渲染栈（后来的 RenderDragon）、跨平台后端，服务的是进房间，不是服务 Mixin（渲染栈对照见[《客户端与渲染》](/impl/client-render)）。Java 的民间官方渲染改的是那一套 OpenGL 提交。Bedrock 的提交在另一栋楼里。楼可以更快。楼不允许你用加载器切开主循环。切开主循环会进不了商店。

扩展模型因此另写。资源包改看见。行为包改实体与规则的 JSON。脚本 API 在沙盒里跑 JavaScript，权限分层，before 事件里不能随便改世界。[^script] 这是官方承认的扩展面，比 Java 数据包更像「能写一点逻辑」，仍不是任意 jar。任意 jar 是 Java 模组河的活法。活法进不了这张桌子，不是因为 C++ 做不到注入。是因为注入过不了审核。审核是扩展面的墙。墙比语言硬。

脚本看起来像「终于能写程序了」。写的是沙盒里的调度：监听事件，改组件，生成实体，在允许的时机碰世界。调度能做出小游戏和互动地图。调度加不出 Mixin 那种「切进活塞检查」。切不进，墙上的怪癖就不会作为民间 opcode 繁殖。不繁殖，Java 红石教科书就没有译本。没有译本，不是脚本作者不够努力。是权限模型故意不给切口。故意，才能过主机认证。过认证，才能进房间。进房间，是这条产品线的第一约束。第一约束排在「和 Java 共用一台隐式 VM」之前。排完，扩展面再宽，也宽不到加载器河。

世界存在 LevelDB 里，不是 Anvil 的 region 文件（两边的格式见[《存储与序列化》](/impl/storage)）。柜子不同，翻译器不是改个后缀。存档分叉是产品线分叉的硬证据：同一座家，搬不过去。搬不过去，比「这边帧数高」更早结束「同一游戏」这句话。

触控把「使用」收成长按或按钮，战斗没有同一根冷却条，红石没有同一套班次。输入不同，可以仍是同一动词（[《最小动词集与手感》](/design/verbs-feel)权衡的就是这条线）。班次不同，就不是同一动词的时间形状。时间形状一换，误用换口令。口令换了，社区教科书不能当译本。译本失败，是语义。语义失败，性能再好也接不进 Java 那条第二作者河：河水认的是切口和怪癖，不是跑分。

<Impl title="脚本有权限，没有切口">
before 事件里不能随便改世界，是为了稳定。稳定是审核友好。审核友好换不来 Mixin 那种「切进活塞检查函数」。切不进，准连接不会作为民间 opcode 长出来。长不出来，就没有同一份墙上的 VM 可翻译。
</Impl>

删掉句中的「Bedrock」或「Java」，附加包、准连接、LevelDB 的句子会断。合写只剩：两边都挖、都放、都有刻。分写从扩展面开始，一直写到灯。

## 语义分叉表

至少五行。行是玩家能核对的因果，不是跑分。[^qc] [^combat] [^be-te] [^fmt]

| 玩家能核对的事 | Java | Bedrock |
| --- | --- | --- |
| 活塞看不看上方那格空气 | 准连接存在，MC-108 为 WAI | 无准连接 |
| 红石何时认输入 | 与主循环同队；社区红石刻 = 2 游戏刻 | 产出 / 消费两段，活塞启动更死 |
| 近战连点 | 1.9 后有冷却 | 没有同一根冷却条 |
| 活塞能不能推带方块实体的方块 | 通常不能 | 能 |
| 作物、树叶、铜氧化这类随机刻事务的快慢 | `randomTickSpeed` 默认 3 | 同名规则默认 1，只宜当相对速度看 |
| 世界怎么躺在磁盘上 | Anvil 分区文件 | LevelDB |
| 第二作者怎么进门 | 加载器 + 注入；数据包为温和层 | 附加包 + 脚本；Marketplace 审核 |

表可以再长。长不是为了骂哪一边缺功能。长是为了证伪「对齐中」。对齐中假定差在工期。工期补得上冷却条，补不上十年 WAI，也补不上已经按 LevelDB 写下的手机存档。补冷却条，PVP 口令会换。换口令是立法。立法按已经记住的手计费。手感那一章（[《音频、粒子与手感谎言》](/impl/feel-client)）写过钉子。钉子分叉，比 GC 分叉更像两个游戏。

红石章把同一张原理图写成护照问题（[《红石的实现》](/impl/redstone)）。护照在这里变成表。表上任何一行单独看都可以说「偏好」。几行叠在一起，偏好变成产品：你无法同时把 Java 墙上的 VM 和 Bedrock 的审核扩展面说成同一份物理。无法同时，就是致命。致命不是崩溃。致命是品牌说「都叫 Minecraft」时，玩家的灯不亮。

## Marketplace 的反向约束

货架看起来是分发。分发会反过来改能做什么。能上架的，要过审核、要可定价、要能在主机上关停、最好不要任意本地代码。于是扩展面被训练成：JSON 加沙盒脚本，资源可热发，逻辑可抽查。训练成功，手机上的孩子能装到皮肤和地图。训练成功，也把 Forge 那种共同立法关在门外。门外不是审美失败。是房间的门卫。

Marketplace 包常常锁在账号和购买状态上，外部专用服务器不一定带得走。带不走，UGC 就不是 Java 那种「把文件夹扔进 mods」。UGC 是租。租能规模化。租让第二作者变成供货商。供货商可以过得很好。供货商立法的方式，和加载器矩阵立法的方式，不是同一种政治。把 Marketplace 听成「Bedrock 的模组」，会把审核听成 API。审核是过滤。API 是承诺。过滤可以明天加严。承诺变严要走弃用。两边都叫扩展。扩展的利息由不同的人付。

反向约束还会漏进正作功能：官方更愿意加能进货架叙事的内容，更不愿意加只能靠注入才稳的边角。边角在 Java 是社区 API。在 Bedrock 可能从未存在。从未存在，就没有革命可革——因为没有那台墙上的 VM。没有，可以是设计。设计会让跨产品线的教科书失败。失败是语义税。税单开给品牌：为什么买一份仍不是全部。

账号锁还有一层工程后果：世界目录不再是完整产品。Java 整合包可以把 mods 文件夹和世界一起打包带走。Bedrock 的货架包若绑在购买状态上，带走的家会缺一块脸、缺一张图、缺一段脚本。缺，不是文件损坏。是产品假定「人跟着账号走，世界跟着人走」。假定对家庭账号友好。假定对「把存档拷到另一台没登录的电脑」不友好。不友好会反过来训练作者：别把关键玩法做成必须买的附加包，或者反过来，把关键玩法做成必须买的附加包。两种训练都在改能做什么。改完，扩展面就不是中性管道。管道有收费闸。闸是反向约束的金属部分。

货架还会训练作者写什么。能定价的皮肤、能过分级的小游戏图、能热更新的资源，会挤掉「给活塞开一个民间 opcode」这种活。活不是没有人想做。是做了上不了架，上不了架就没有房间。Java 的加载器河不靠架。不靠架，才能养工业包这种无法审核成商品的系统。系统进不了 Marketplace，不是工业包不够好。是商品合同不收系统当 SKU——系统会把默认世界变成另一款游戏，而主机上的默认必须仍叫 Minecraft。默认一肥，空循环的问题在卷二写过。这边用货架把肥挡住。挡住，是反向约束的完成态。

<Callout type="warning" title="禁止优化版读法">
跑得顺、能上手机，不能写成「同一游戏的正确实现」。正确实现要先有同一份因果。因果已经分叉。分叉之后，快是快。快的是另一款 Minecraft。
</Callout>

## 两个游戏的工程现实

工程上你面对的是：两份世界表示、两份协议、两份扩展面、两份测试集。Geyser 一类桥证明翻译能续命——桥的工作层就是协议，翻译的边界见[《网络协议》](/impl/protocol)。续命会丢语义——准连接过不了桥，就不是翻译损失了一点画质。丢失的是语言。语言丢了，机器停。机器停，两边的作者会互相指责实现。指责找错了科室。科室是产品线，不是优化开关。

Realms 和好友列表让 Bedrock 的多人更像默认。默认是产品逻辑。默认改变不了 LevelDB 里的家搬不进 Anvil。搬不进，家庭房间里已经是两个存档两种灯。工程现实因此不是「再做一个转换器」。转换器能搬方块，搬不走未签署的因果，也搬不走账号锁住的货架包。三件叠在一起，两个游戏的说法才不是修辞。修辞是「都叫 Minecraft」。非修辞是：启动器可以进两扇门，门后不是同一份物理。

对开发者，抄「C++ 跨平台」能抄到进房间。抄不走 Java 的切口河，也抄不走 Bedrock 已经长出来的审核河。你若从 Java 重写到原生，并假设社区 API 会跟着走，墙上的测试集会投票反对。你若从第一天就按商店写扩展面，模组文化不会自动发生。不会自动，不是玩家不够爱。是门卫不同。门卫不同，完整产品的形状不同：一边是内核加加载器，一边是客户端加货架。两边都挖。两边都不是对方的皮肤。

卷四会考偶然能否进兼容层。本章不代答该扔掉哪一行表。本章钉的是：换语言重写之后，若不去对齐语义测试集，分叉会变成两个游戏。两个游戏可以共存。共存已经发生。发生了还说优化版，是把品牌偷换成规格。

<Constraint name="语义分叉比跑分贵" verdict="地基" chain="另写实现 → 测试集分家 → 同名不再是同一物理">
性能能解释为什么手机能玩。解释不了灯为什么不亮。抄走 C++ 和附加包，丢掉准连接、存档格式和审核墙，你会得到能进商店的客户端，失去「一份原理图走遍 Minecraft」的幻觉。幻觉可以破。破了要改口令。口令在玩家手里。
</Constraint>

<Memoir title="截图里的灯">
同一套台阶，同一卷粉。那边不亮。不是网不好。是那一行表从来没签过。口令「Bedrock 不行」能当情绪。情绪底下是护照。护照上写着产品线，不是帧数。
</Memoir>

<Alternative title="若从第一天强制同一份红石规格">
跨平台会更慢，或其中一边要革掉墙上的 VM。你得到更可翻译的品牌。你失去的是：某一侧已经靠未签署的怪癖建成的城市，以及另一侧已经靠审核进店的货架。统一规格是立法。立法两边都要死人。
</Alternative>

下一章看同一内核如何既给单人档用、又给万人网络用。原版没有把兴趣管理当成一等公民。第三方核心是证据，不是安装推荐。

## 这一章留下什么

- **爱好者**：手机上的 Minecraft 能更顺，仍可能点不亮你截图里的灯。存档搬不过去。模组进不了货架。这不是「还没优化完」。这是两款游戏共用一个名字。
- **开发者**：能抄走的是为进商店而另写实现、把扩展面收成数据包式的附加包加沙盒脚本、用跨平台后端换房间。能一起抄走的还有：语义表必须先于跑分——准连接、红石班次、战斗冷却、方块实体推移、世界格式、作者怎么进门。抄不走的是 Java 模组河、Marketplace 审核、两份已经写下的存档。你不得把 Bedrock 写成优化版 Java。换语言已经发生。发生之后，分叉比帧数更贵。贵在测试集。测试集在玩家手上，不在基准测试里。
