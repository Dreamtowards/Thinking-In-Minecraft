> **本章命题**：协议是未承认的公共 API。单人档也在跑一台服务器。版本一换，模组常常不是跟不上玩法，是跟不上这套从未承诺稳定的字节。

## 问题

你按 Esc，单人世界会停。开了「对局域网开放」，Esc 就不停了。熔炉还在烧。不是菜单坏了。是宇宙里出现了第二双可能的眼睛，暂停这种礼貌被收回。[《多人是默认状态》](/design/multiplayer)

要回答：协议为何成为模组兼容瓶颈？可被证伪的说法是：模组难更新，是因为玩法每年都变；协议只是联机用的电线，单人用不上。只要还存在 1.3 之后单人内部跑服务端、只要还存在 ViaVersion 靠翻译包才能进旧服、只要还存在同一模组要为每一个协议号出包，这句话就不成立。

上一章把格子收成网格。[《客户端与渲染》](/impl/client-render) 网格可以本地编。编完仍要问：这一格在不在、别人看不看得见、口袋里那一剑还在不在。[《物品、库存与合成》](/impl/items) 问的那条线，就是协议。协议没有官方「模组稳定面」。没有稳定面的东西，用久了就会变成稳定面。变成之后，改它就是改所有第二作者的接头。

## 单人游戏为什么要有「服务器」

2012 年夏天，Java 把单人改成内置服务端。[^sp] 表面上是为了局域网。工程上是承认：世界的运行时本来就该只有一份。挖、烧、刷怪、红石，不该在「一个人玩」和「两个人玩」里写成两套因果。两套因果会裂：单人模组和多人模组、单人杜普和多人杜普、单人暂停和多人不停。收成一套，模组少写一半，漏洞少开一扇门。

所以「单人即本地服务器」不是比喻。进程里有一个客户端在画、在听键，有一个服务端在走拍、在管存档。它们用协议说话。延迟可以是内存里的几毫秒，格式仍是那套包。你没有联网，你已经在联机——联的是本机那台权威。对局域网开放，只是把这根线从 loopback 拉到房间里。拉出去之后，暂停消失，是因为权威不再只为你的 Esc 服务。

1.7 把这根线换成 Netty。[^netty] 换的是工程，不是合同。合同仍是：握手时先报协议号，对不上就进不了世界。协议号是这张未承认 API 的版本字段。模组加载器、代理、翻译器，全部先读这个数。数一变，后面的形状才允许变。变形状的自由，官方留给自己。读形状的人，没有投票权。没有投票权还要跟，就是瓶颈。瓶颈从进服的第一包就开始。第一包对不上，后面的家、炉子和红石都还没机会说话。说话权在接头上，不在菜单里。

Bedrock 从一开始就更不像「单机程序」。手机上的世界也按主机权威走，好友列表比「发布到局域网」更像默认入口。合写的是：模拟有一份权威。分写的是：Java 用一次 1.3 把两套代码收成一套；Bedrock 的包格式、RakNet、blob 缓存，不是 wiki.vg 那张表的译本。[^be] 删掉句中的产品线，「单人即本地服务器」仍常常成立。成立的是合同。合同让协议变成所有人的接头——包括从不进服的人。

画面可以先演。熔炉认的是本机服务端那一拍。F3 上的 ms ticks 在单人里诚实，正因为集成服务端就在旁边。连到别人的服，诚实搬走。
</Callout>

## 权威模型

客户端可以撒谎。它能说「我到了那边」「我挖下了这格」「我的剑还在」。服务器若信，世界就变成各人各话。Minecraft 的选择是：方块、库存、生命、进度，以服务端为准。客户端负责输入和呈现。呈现可以预测。预测错了，橡皮筋拉回来——你瞬移回权威认为你在的地方。

这不是联机功能。这是同一套权威在单人里也跑。创造模式取消稀缺，不取消「这一格改没改要登记」。登记发生在服务端。客户端画一个洞，服务端若拒绝，洞会补回去。补回去很难看。很难看是诚实：你看见的流畅，有一部分是猜测。

权威要付同步税。每一个别人需要看见的变化，都要变成包。包太多，带宽和主线程一起疼。包太少，别人看见幽灵。设计若把「所有装饰」做成实体，税会从实体章打到这一章。[《实体与碰撞》](/impl/entities) 展示实体几乎不撞，仍要广播给每个能看见的人。看见是协议问题，不是网格问题。网格可以不画墙后的鸡。协议仍可能把鸡的坐标送出去——直到距离和规则把它裁掉。

在线模式把账号焊进握手。焊的是「你是谁」，不是「世界怎么走」。世界怎么走仍是这套包。模组若在握手之后才塞私货，私货享受不到账号那一层的稳定——账号协议很少像玩法包那样每个快照翻脸。翻脸集中在玩法包，所以瓶颈也集中在玩法包。反作弊读的是玩法包。翻译器翻的是玩法包。第二作者死在玩法包上。

```java
void onClick(SlotClick pkt) {
  if (!server.validate(pkt)) {
    sendSlotState(pkt.window(), pkt.slot()); // 拉回权威
    return;
  }
  apply(pkt);
  broadcast(pkt.window());
}
```

示意。窗口那一章写过：点一下是立法请求。本章补的是：请求走协议。协议一变，请求的形状变。模组若把私货塞进旧形状，新版本会把私货读成空气。

## 同步什么：区块、实体、库存

三样东西，三种账单。

**区块**是空间的切片。你走近，服务端把柱子的状态、光照、生物群系打成包；你走远，客户端丢掉网格，服务端可以卸载模拟。[《存储与序列化》](/impl/storage) 柜子和协议不是同一份，但切法同源：无限世界付不起「一次送全图」。视距拧大，包变多。模拟距离拧小，你仍可能看见一座不怎么动的城——看见是区块到了，动是拍还在不在。两者都走协议，职责不同。

**实体**按只同步。位置、速度、装备、乘客，常常还要插值：客户端在两包之间把鸡滑过去，免得一顿一顿。滑是谎言。谎言服务手感。权威仍是服务端那只鸡在哪一格附近。掉落物、经验球、箭，短命却能在同一拍里炸出一堆包。上一章的脉冲税，这里变成带宽税。

**库存**是窗口。打开箱子，服务器发桌布；点击，客户端发模式；对不上，槽位被拉回。[《物品、库存与合成》](/impl/items) 组件化之后，槽位甚至可以只带哈希再对账。对账是反杜普。反杜普必须在协议里，不能只在 GUI 里。GUI 是皮肤。

三种同步都没有「模组稳定字段」。模组要加一种新实体、新窗口、新区块数据，就要在包上找缝：插件通道、自定义载荷、混进 NBT。缝用久了变成生态。正作一改包结构，缝要重挖。这就是瓶颈的预演——还没到版本号，形状已经是 API。

自定义通道看起来像官方留的门。门上没有锁，也没有门牌规则。两个模组抢同一条名字，就会在玩家背包里打起来——不是玩法冲突，是接头冲突。Forge、Fabric、插件分别给这条门加过自己的规矩。规矩是第二作者立法。立法没有写进协议号。协议号一跳，规矩要重写一遍。重写一遍，就是「每个大版本都是末日」在联网层的那一半。

光照和高度一改，区块包跟着改。1.18 把柱子拉长，送的不再是同一截。客户端网格上一章已经付重建税；协议这里付的是：旧模组若按 256 高去读包，会把新世界读碎。读碎不是渲染 bug。读碎是接头还认旧宪法。

<Impl title="没送到的区块不是没生成">
生成可以在服务端悄悄做完。没进视距、没打成包，客户端就还是雾。雾不是世界的边。雾是协议还没把这一刀切给你。
</Impl>

## 延迟、预测、反作弊为什么难

延迟是墙钟。拍是模拟。两根钟对不上，人会感到钝：开门晚一拍，打人不中，挖的裂痕闪一下又回来。客户端于是先演：先挥镐，先走一步，先把方块打出裂纹。演完，等权威盖章。盖章慢，演变成撒谎。撒谎被揭穿，橡皮筋。

预测不是作弊。预测是让 50 毫秒的拍和 80 毫秒的 RTT 看起来像同一只手。难在：同一套预测通道，作弊也走。客户端说「我打到了」。近战有距离，弓有轨迹，移动有速度。服务器能设上限：走太快就拉回，打太远就不认。上限一松，外挂活。上限一紧，高延迟的老实人被当外挂——橡皮筋、打不中、被踢。反作弊先天困难，不是因为没有人写检测。是因为检测的输入来自不可信的客户端，而合法玩家的网和机器本来就把输入弄脏。脏的合法和干净的作弊，叠在同一根线上。

不要配置步骤。只要成因：权威在服务器，感官在客户端，中间是协议。协议若把每一次挥手都做成「先问再演」，手感会死。协议若把每一次挥手都信，口袋会死。Minecraft 走中间：先演，再对账，对账失败就粗暴拉回。粗暴是产品。模组加传送、加飞行、加新武器，会把中间那条缝撕得更宽。撕宽之后，反作弊和兼容性抢同一处：都要读包、都要猜意图。

读包的人没有官方字段表。字段表每个版本一份，写在民间 wiki 上。反作弊核心于是变成「某一版的解释器」。解释器跟不上快照，不是运营懒，是 API 未承认。未承认的东西无法写回归测试。无法写回归，就只能冻结版本。冻结版本，是服务器河用协议号当宪法。宪法一多，多版本代理才成为刚需。刚需不是功能。刚需是瓶颈的症状。

Bedrock 的预测和 Java 不是同一套补偿。合写的是：延迟下必须先演。分写的是：哪一种先演会被官方当合法。跨产品线抄反作弊，会抄成误伤。

<Memoir title="我明明挖下来了">
裂痕走完。洞闪了一下。方块又回来。不是镐坏了。是客户端先演完，服务端说那一格还在——也许延迟，也许别人先放，也许你根本没对准权威那一份。口令「橡皮筋」能当诊断，因为被拉回的是你的身体，不是画面设置。
</Memoir>

## 协议版本与多版本服务器

Java 几乎每个大版本都换协议号。换的不是「多了一种猪」。换的是包的形状：字段、顺序、压缩、是否用组件代替整棵 NBT。模组加载器要挂钩子，钩子打在这些形状上。形状一变，钩子全断。看起来像「每个大版本都是模组末日」。末日的一半在字节码，一半在这张从未承诺稳定的表。后一半就是本章的答案：协议是公共 API，官方只当它是版本电线。电线每年换规格，插在上面的所有东西都要重做接头。

多人模组还要让客户端和服务端说同一种私货。私货走自定义通道。整合包把二十个模组焊在同一根线上，线的规格却写在某一版的 wiki 上。wiki 不是 Javadoc。快照可以让 wiki 连夜作废。作废之夜，翻译器会先出，模组会后到，服务器核心会卡在「先保旧包还是先跟正作」。保旧包，是 Paper 和代理的政治。跟正作，是玩家要进新世界。两边都在协议上立法。立法席不在 Mojang 的模块文档里。立法席在包的形状上。

ViaVersion 一类翻译器把这件事写成产品：让新客户端进旧服，或反过来。[^via] 能翻译，证明协议可以被当成语言。必须翻译，证明语言没有稳定方言。生存服不敢更新，有时是红石，有时是这一层：插件、反作弊、NPC、箱子插件，都把字段写进了某一版的包。Paper 核心、Bungee / Velocity 代理，全是协议上的第二作者。第二作者比引擎更难维护，因为引擎至少还有一个官方版本号。协议的「官方」是每个快照都可以作废上一份。

Bedrock 的协议号同样在涨，Geyser 一类桥把 Java 玩家送进 Bedrock 服，或反过来。桥是又一次翻译。翻译证明分叉。分叉让「一份模组走遍 Minecraft」不能写进合同。合同能写的是：你要跟哪一张表说话。表就是瓶颈。瓶颈不是带宽。瓶颈是：未承认的 API 被全世界的第二作者当成了承认的。

<Constraint name="协议是未承认的 API" verdict="地基" chain="单人即服务端 → 包形状被模组当接头 → 改协议即改生态">
稳定的玩法可以换皮。不稳定的包会让换皮失败。抄走权威服务器和预测，丢掉「协议每年可以换形状」，你会得到能联机的演示，失去十年插件和模组已经焊在某一版字节上的世界。ViaVersion 是证词。证词说：翻译可以续命。续命不是稳定面。
</Constraint>

<Alternative title="若协议像数据包一样有稳定字段">
模组少死几次。官方加字段要走版本协商，迭代变慢。你得到更像引擎中间件的联网层。你失去的是：正作能在快照里把槽位收成组件、把区块改切法，而不先开两年 RFC。快，是债。债的利息由第二作者付。
</Alternative>

下一章把协议盖章之前那几十毫秒请出来：声音、粒子、挖掘的停顿、受伤的红。手感有多少是模拟，有多少是客户端先演完的谎。

## 这一章留下什么

- **爱好者**：单人档里也有服务器。Esc 能暂停，是因为还没有第二双眼睛。开了局域网，炉子就不陪你停。挖的洞闪一下回来，是权威在拉你，不是显卡抽风。
- **开发者**：能抄走的是客户端–服务器权威、单人跑同一套服务端、区块 / 实体 / 窗口三种同步、预测加对账、协议版本必须当生态 ABI 来涨。能一起抄走的还有：反作弊难，因为合法延迟和撒谎共用预测通道。抄不走的是每年作废的包形状、ViaVersion 与代理河、Java 与 Bedrock 两张表；以及插件已经把字段焊进某一版。你若每年换协议还不提供翻译层，第二作者会比引擎先死。死的不是玩法。死的是接头。

[^sp]: Java Edition 1.3.1（2012-08-01）将单人改为内置服务端，并加入对局域网开放。见 [Java Edition 1.3.1](https://minecraft.wiki/w/Java_Edition_1.3.1)；设计对照见本书 [《多人是默认状态》](/design/multiplayer)。

[^be]: Bedrock 使用基于 RakNet 的 UDP 协议，与 Java 的 TCP 包格式不是同一张表。见 [Bedrock Edition protocol](https://minecraft.wiki/w/Bedrock_Edition_protocol)。

[^netty]: Java Edition 1.7 将网络栈换为 Netty。见 [Java Edition 1.7](https://minecraft.wiki/w/Java_Edition_1.7)、[Java Edition protocol](https://minecraft.wiki/w/Java_Edition_protocol)。

[^via]: ViaVersion 等翻译器让不同协议号的客户端与服务端互连，证明包形状可被当成语言、且没有官方稳定方言。见 [ViaVersion](https://github.com/ViaVersion/ViaVersion)。
