> **本章命题**：原版不把相邻的同材质面焊成一张大面，不是没听说过贪婪网格。1.8 之后，格子不再保证「每一格都是立方体贴图」；重建还要跟得上挖和放。优化模组改写的是这一层，它们是民间官方实现，不是外挂滤镜。

## 问题

装上 Sodium，帧数可以翻一截。聊天里的口令是「原版渲染太烂」。烂是观感。要回答的是：原版为何不用贪婪网格，模组如何改写这一层？可被证伪的说法是：Mojang 没听过合并相邻面，优化模组只是把显卡调亮一点。只要还存在 1.8 把方块收成 JSON 模型、只要还存在挖一格必须立刻重编网格、只要还存在资源包能换楼梯的形状，这句话就不成立。

上一章（[《红石的实现》](/impl/redstone)）把墙上的粉写成隐式虚拟机，权威落在服务端那一刻上。本章把镜头转到看见：格子如何变成三角形。看见可以晚到，可以骗人，但不能另结一份物理——刻是服务端的共享真实（[《游戏循环与刻》](/impl/tick)），画面是客户端的工作。工作是允许换实现的。换实现若改掉了「这一格看起来还是那一格」，后面的手感章会接着论证那是谎言。本章只问：谎言底下的网格，为什么长成现在这样。

本章不要渲染器教程，不要着色器清单，只要对比选择：即时模式、批处理、按格出面、贪婪合并、剔除、透明分层。选择一旦被模组改写，原版债就有了证人。

## 看得见的世界如何被拼出来

眼睛看见的不是调色板。调色板住在区块里（[《体素世界的数据模型》](/impl/data-model)），那是数据；客户端要做的事更粗鲁：把这一节里朝外的面收成可以交给 GPU 的三角形，也就是网格。第一批账单在这里就能省：看不见的面不画——两块石头贴在一起，中间相对的那两张面可以整个丢掉。这就是面剔除。剔除之后，剩下的工作量仍然可观：每一格、每一面、常常还是每一张独立的小四边形，都要在重建时生成一遍。

网格拼装的单位是区块，区块柱再切成节。你走远了，远处的节可以不建；你挖一格，这一节和露出新面的邻居节都要重建。重建不是重画一张风景照，而是：这一格的法律变了，网格作为法律的可见层必须重造。重造慢了，你会看见「挖穿了，后面还是黑的」——那一帧里，新面还没有生成出来。重造错了，你会看见接缝、闪烁、水在错误的次序里叠加。

所以渲染这一层的合同很短：**世界可变，网格必须跟得上变。** 跟得上变，比「把同材质的面焊到最大」更优先。焊到最大，三角形少，GPU 轻松；可焊完之后再挖一格，整张大面都可能作废，拆的账单落在 CPU 的重建线程上。Minecraft 的玩法是每一秒都在拆：挖、放、活塞、水流。网格算法若只为静止的山优化，会在家门口卡成另一种账单——炉子的 TPS 还好，帧率先垮。

实体另走一条路。鸡、掉落物、展示实体不进区块网格（[《实体与碰撞》](/impl/entities)）：它们按个体各自建模、各自提交，每一只都是自己的绘制开销，实体章已经算过这笔税。本章的山是方块。方块便宜，便宜在重复：一座山几十万格，翻来覆去常是几十种状态。重复要变成「少画几次」，才轮得到贪婪网格这个念头。

```java
void rebuildSection(Section s) {
  for (Cell c : s.cells()) {
    for (Face f : c.exposedFaces()) emitQuad(f); // 示意：按格出面
  }
}
```

示意不是源码。它钉死的是默认策略：先问哪些面露在外面，再一张一张交给 GPU。贪婪网格会在这一步之后再走一道工序，把能合并的四边形焊起来。原版长期停在「交出去」。停，不是没听说过算法；停的理由，是后两节要写的合同。

## 渲染简史

最早的 Java 客户端接近「当场喊 OpenGL」：每一帧看见什么，CPU 就把那些顶点现场报给显卡，这叫即时模式。即时模式好写，几百个方块无所谓；世界一变大，「好写」就变成每一帧把同一座山重新口述一遍，CPU 光报坐标就把帧预算吃光。后来的几步，都是在修这件事。

| 方案 | 做法 | 省下的是什么 |
|------|------|------------|
| 即时模式 | 每帧由 CPU 现场报出每个顶点 | 无（这是起点） |
| 显示列表 | 把报过的话录下来，逐帧重放 | CPU 的口述 |
| 顶点缓冲（VBO） | 顶点数据常驻显存，重建时才改写一次 | 每帧的上传 |
| 批处理 | 许多小网格并成少数几次大批提交 | 每次调用的固定开销 |

批处理不是审美升级，它回答的是可变世界的特殊问题：同一段网格要在两次挖掘之间反复播放，播得越便宜越好。顺带还有一件省力的事：所有方块贴图缝进一张图集，整片地形一两次绘制就能提交——「按格出面」之所以撑得住，图集是背后的合伙人。

1.8 是合同换代。方块不再只是六张面贴在立方体上：模型进了 JSON，资源包能改楼梯怎么缺角、栅栏怎么伸出手。[^model] 同一版本还把更认真的遮挡剔除写进主线：看不见的节可以整节不画。[^cull] 这不是贪婪合并。这是「先别把东西交出去」——先别交，比焊大面便宜，也跟得上模型已经不再是纯立方体的现实。

1.14 强制走顶点缓冲，旧的即时路径从此不是选项。1.17 把渲染收成 OpenGL 3.2 核心配置，固定管线换成着色器。[^gl] 看起来是现代化，现代化的代价写在玩家工单上：有人升完更卡，有人的高清包动画把帧率打穿。债没有消失，只是换了形态：从「不会批」，换成「批了，但仍按模型出面；管线换了，资源包的合同还在」。

Bedrock 另写一条河。移动端更早就要批、要切，后来的 RenderDragon 引擎把渲染拆成可替换的后端，同一份世界在不同平台上走不同的图形接口。合写的是：看得见的世界是网格，不是调色板的皮肤。分写的是：Java 的官方换皮面是资源包，Bedrock 的皮肤、光影和渲染管线不是同一套作者席——删掉句中的产品线，「装个优化模组」常常不成立，Sodium 改不了手机。

## 网格、剔除、透明

三件事叠在同一座山上：**出面、丢掉看不见的、让半透明别排错队。**

**网格。** 贪婪算法把相邻、同材质、同朝向、连逐顶点数据都一致的面焊成一张更大的四边形，三角形数量可以少一个数量级。[^greedy] 少，对静止的洞和墙极好。Minecraft 的墙不静止，而且墙常常不是墙：楼梯、栅栏、树叶、多层模型都是模型而非立方体；生物群系染色和平滑光照还把同一张贴图的四个顶点涂成四种颜色和亮度——要合并就得连这些逐顶点数据一起对齐，四个角涂得不一样，两张四边形就焊不成一张。1.8 之后，模型成了官方输入，「足够像、可以当一张」的范围进一步收窄，资源包还能随时把它再改掉。于是原版的选择是：按模型烘出四边形，做面剔除，不做经典意义上的贪婪合并。这是历史——早期那个纯立方体世界本可以焊。这也是复杂度——焊了就要维护第二套管线：立方体走贪婪快路，楼梯、活塞头走模型慢路，两套路径各要测试、各会腐烂。一套按模型出面，是承认作者席已经交给 JSON，不再假装世界只有立方体。

**剔除。** 三种剔除省的是三种账。面剔除在重建时省：贴住的面对不生成三角形，网格本身就变小。视锥剔除在提交时省：镜头背后的节整节不进渲染队列。遮挡剔除更进一步：被墙挡住的节，哪怕在视锥里，也可以不画——1.8 那一刀写的就是这个，洞穴深处你看不见的远方，可以整节静默。[^cull] 后两种不减少网格里的三角形，减少的是「有多少节被问到」；问得少，重建和绘制的线程才喘得过气。Sodium 后来把遮挡判定和批处理做得更狠，恰恰证明原版在这一层留了余地。留余地不是不知道有墙，而是官方重建必须正确、必须跟得上挖：正确优先于极致的少画。

**透明。** 水、染色玻璃、冰这类半透明面，必须按从远到近的次序叠加，否则远处的河会画到近处的玻璃前面。不透明面可以乱序画，靠深度测试就能排对；半透明要做混色，混法依赖次序，次序错了颜色就错。1.16 的 Fabulous 图形把半透明排序做成官方选项，等于承认：这一层一直是债，平时用分层凑合，讲究了才还。[^fabulous] 贪婪网格在半透明上更别扭——面焊得越大，排序的单位越粗，水线边缘越容易出错。所以原版把几何分成固体、镂空、半透明几层依次提交，用分层换正确。分层看起来土，换来的却是：隔着水你仍看得见后面的石头，而且石头不会被水抢了次序。

重建成本把三件事拴在一起。挖一格，这一节要重建；邻居若露出新面，邻居也要重建。算法越聪明，单次重建越慢——省下的 GPU 时间，要用 CPU 上的停顿去换。而玩家的动词是挖（[《最小动词集与手感》](/design/verbs-feel)）：挖必须在几十毫秒里看见新洞，否则手感先死。贪婪网格若让每一次挖掘多付一截重建时间，省下的三角形就会在手上还回来。原版不用贪婪，首先是因为重建是玩法账单，不是演示场景的账单。

<Impl title="贪婪网格省的是三角形，不是挖的那一下">
合并相邻面能让 GPU 少画。挖、放、活塞推格，会让合并结果作废。作废就要重算。模型、染色、平滑光、半透明排序，都会让「可合并」变少。可合并变少之后，还要维护一套只对实心立方体有效的快路径——这就是复杂度选择。
</Impl>

<Alternative title="若官方只渲染实心立方体并贪婪合并">
山会更轻。楼梯、栅栏、自定义模型、资源包换形状，都要另开管线或禁止。你得到更像 2012 年演示的体素引擎。你失去的是：格子上的法律已经变成模型，模型已经是官方模组面。
</Alternative>

## 资源包作为官方模组

贴图包先来。1.5 及更早叫材质包，能换的只有贴图。1.6.1 起收成资源包：不只换皮，还能换声音、字体、模型，和后来的核心着色器。[^rp] 这是官方承认的第二作者席，而且故意停在「新动词」之前。你能让石头长成另一副面孔，不能让石头变成一种新的挖。挖仍是那只手。面孔是皮肤。皮肤进 `assets/`，法律仍在 jar 与数据包里。

1.8 把模型放进资源包，官方模组面突然碰到网格算法。玩家换一个包，楼梯的缺角变了，网格必须按新的 JSON 烘。贪婪合并若假设「石头永远是 1×1 的四边形」，这个包会把它打穿。所以资源包不是装饰。资源包是渲染合同的一部分：出面必须以模型为准。以模型为准，优化就不能靠「全世界都是立方体」这条捷径。捷径留给自己做引擎、自己规定方块形状的人。Minecraft 把形状交给了作者。交给了，就要付按模型出面的税。

格式号随版本涨。涨一次，旧包可能要跟着翻译。翻译的成本按资源项计费——不像世界迁移按每一格财产计费，那是存储章的账——但生态一样会疼。高清包、光影包、程序员艺术，都是在官方模组面上立法。立法能被关闭：关掉资源包，世界仍在。关闭不了的是：这一层已经承诺可被换皮。承诺可被换皮的渲染器，很难再假装自己只认识立方体。1.14 官方重绘默认贴图时，把旧贴图收成「程序员艺术」资源包，等于官方自己当了一回资源包作者：默认脸换了，旧脸仍可装回来。[^rp] 换脸不是新引擎，换脸恰恰证明合同还在。

Bedrock 的资源包、材质与 Marketplace 皮肤不是 Java 这张网。合写的是：官方允许换掉看见的那一层。分写的是：Java 的 JSON 模型直接改网格输入；手机上的皮肤常常碰不到楼梯怎么缺角。跨产品线抄「资源包是官方模组」，要先问「模组」二字在那边指谁。

## 优化模组作为证据

OptiFine 曾经是这一层的民间官方。它从帧数补丁起步，十几年里长成一套大杂烩：连接材质、动态光影、视距与细节开关，很多玩家装上它才觉得「像现代游戏」。它证明两件事。第一，玩家愿意为「看见」付钱——付的是兼容性风险，是每个新版本出来后干等模组更新的那些天，是它和 Forge 长期互相较劲的兼容矩阵。第二，原版留下了空间：同一套格子，可以画得更省、更亮、更远。空间不是漏洞。空间是债。债被一个模组收成产品，这个模组就变成许多人的默认客户端。

Sodium 把证据写得更硬。这个名字取自化学元素「钠」，作者是 jellysquid3——上一章 Lithium 的同一位作者：那边还逻辑的债，这边还渲染的债。它不靠「把画质调糊换帧数」，而是重写区块渲染：更紧凑的顶点格式、更狠的批处理、更准的遮挡判定、多线程重建网格。[^sodium] 经典贪婪合并不是它的卖点；卖点是「行为仍像原版，算得更快」。上一章写过，Lithium 把更新顺序当 ABI（[《红石的实现》](/impl/redstone)）；Sodium 把「这一格看起来还是那一格」当 ABI。ABI 对上，飞行器还飞，楼梯还缺同一只角，只是帧率高了。ABI 对不上，优化模组就成了另一款游戏的显示器。民间官方实现的意思就在这里：它替正作还债，却不能改合同。

Iris 一类光影接在这套网格后面，证明分层：先有正确的节与面，才有电影。电影可以关。节与面不能关。关了，你看不见家。所以优化模组不是滤镜商店。它们是这一层缺席的官方实现。缺席可以。缺席时，生态会选举一个。选举的结果进启动器、进整合包、进「第一次装 MC 要不要装优化」。卷四会考要不要把选举收回 jar。本章不代答。本章钉的是：原版不用贪婪，不是因为愚昧；模组改写这一层，是因为可变模型世界的批处理，官方长期写得够用不够好。够用，家能看见。不够好，证人是帧数和那几个几乎人人要装的客户端模组。

<Memoir title="没装优化的第一晚">
视距拧到远。转身，山在远处一块一块地长出来。不是世界不存在，是网格还在排队。口令「原版卡」能当诊断，是因为炉子可能还好，帧已经先告状。告状的是这一层；权威那一层还没开口。
</Memoir>

<Constraint name="网格必须跟得上挖" verdict="地基" chain="格子可变 → 模型可换 → 重建优先于焊最大面">
贪婪网格省三角形。Minecraft 的动词在拆三角形。抄走面剔除和分层透明，丢掉「模型是官方输入」，你会得到更快的立方体演示，失去能被资源包改形状的家。优化模组证明债在。它们能抄的是批和剔除。抄不走的是：正作把形状交给了第二作者。
</Constraint>

下一章把看见背后的那根线请出来：协议。单人档里也有服务器。画面再流畅，槽位和方块仍要问权威。权威说话的格式，会变成模组的兼容瓶颈。

## 这一章留下什么

- **爱好者**：远处一块块长出来的山，是网格在排队，不是世界没生成。装优化模组能把排队变短，家还是那座家——若它答应看起来仍像原版。资源包能换楼梯的脸，换的是官方允许的那一层。
- **开发者**：能抄走的是区块网格加面剔除、视锥与遮挡、不透明与半透明分层、资源包作为官方换皮面。能一起抄走的还有：可变世界里重建延迟比静止场景的三角形数更先。抄不走的是二十年 JSON 模型与资源包格式号、Java 的 Sodium 选举和 Bedrock 的另一条管线；以及「看起来像原版」已经是 ABI。你若按纯立方体贪婪合并，会得到漂亮的基准测试，失去楼梯、栅栏和玩家已经写下的包。原版不用贪婪，是合同。模组改写这一层，是还债。债还完，合同还在。

[^model]: Java Edition 1.8（14w06a 起）加入可配置的 JSON 方块模型，后由资源包提供。见 [Model](https://minecraft.wiki/w/Model)、[Java Edition 1.8](https://minecraft.wiki/w/Java_Edition_1.8)。

[^cull]: Java 1.8 与当时的 Pocket Edition 0.9 加入更认真的区块遮挡剔除。见社区说明如 Tommaso Checchi 对 MCPE 0.9 / PC 1.8 剔除的公开解释；概述亦见版本说明 [Java Edition 1.8](https://minecraft.wiki/w/Java_Edition_1.8)。

[^gl]: Java Edition 1.17（21w10a）起渲染使用 OpenGL 3.2 核心配置，固定管线改为着色器。见 [Java Edition 1.17](https://minecraft.wiki/w/Java_Edition_1.17)。

[^greedy]: 贪婪网格把相邻同属性的体素面合并为更大的四边形。见 Mikola Lysenko，《Meshing in a Minecraft Game》，0 FPS，2012-06-30，<https://0fps.net/2012/06/30/meshing-in-a-minecraft-game/>。

[^fabulous]: Java 1.16 的 Fabulous! 图形选项改进半透明排序。见 [Graphics](https://minecraft.wiki/w/Graphics)、[Java Edition 1.16](https://minecraft.wiki/w/Java_Edition_1.16)。

[^rp]: Java 1.6.1（13w24a）用资源包取代材质包。见 [Resource pack](https://minecraft.wiki/w/Resource_pack)。

[^sodium]: Sodium 是 Java 版区块渲染优化模组，强调在接近原版外观的前提下降低绘制开销。见 [Sodium](https://modrinth.com/mod/sodium)。
