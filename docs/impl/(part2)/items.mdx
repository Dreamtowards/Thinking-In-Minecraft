> **本章命题**：物品是玩家时间最便携的那一份。技术一次次改口袋的法律——数字 ID、tag、组件、JSON 配方——不是因为好看，是模组已经把口袋当成立法席。改口袋，等于改所有已经写下的财产。

## 问题

人几乎透明。强写在物上。物能丢掉、能交给别人、能放回世界。[《合成、物品与库存》](/design/crafting-inventory) 设计合同在卷二。本章问实现：口袋的法律一改，为什么比改一座山更疼？

要回答：技术如何追随模组文化？可被证伪的说法是：物品格式跟着官方审美走，模组只是使用者。只要还存在矿辞被标签接替、只要还存在非结构化 `tag` 被组件挤走、只要数据包能加配方却仍加不了新动词，这句话就不成立。官方是在追：第二作者已经把物品当成可扩展对象，正作只好把对象收成可校验的模式。

上一章把实体写成税。[《实体与碰撞》](/impl/entities) 掉落物是税的一种。进了背包，税变成财产。财产必须比引擎活得久。[《存储与序列化》](/impl/storage) 柜子那一章把账单开在每一件物品上。本章把口袋打开：栈怎么叠，窗口怎么点，配方怎么从代码搬进 JSON。

## 物品为什么难迁

山可以留在未加载的柱子里，直到你走过去再翻译。口袋不行。玩家一进服，背包、末影箱、盔甲、手持，全部要立刻成为当前版本的法律。箱子里的剑、地上的掉落物、村民要价的那一格，同一份 schema。潜影盒和末影箱把口袋做成可携带的世界：格子里还有格子。格子套格子，迁移的作用域跟着乘。物品是财产的主要载体，所以迁移的作用域等于「所有还想被认作同一把剑的东西」。

难迁还有第二层：模组先于正作把物品当成结构体。附魔、属性、皮肤、自定义键，曾经一股脑塞进同一团 NBT。官方若只认 `id` 和 `Damage`，第二作者就在缝里立法。缝用久了，变成生态。正要收缝，生态会觉得被翻口袋。翻口袋不是换贴图。翻口袋是：这把剑还是不是昨天那把。

铁砧、附魔台、锻造台是口袋上的立法现场：两棵树合并成一棵。合并要规则。规则一变，所有已经合并过的树都要能被读回来。锻造模板把「升级」收成又一件物品——成长仍然在物上，只是多了一张门票。门票也要迁。迁的是财产，不是菜单皮肤。

Bedrock 的物品另有一套网络和附加包字段。Java 的组件化故事不能安到 Marketplace 头上。合写的是：物是可移交的状态。分写的是：状态住在 `components` 里还是复合标签里。

## 栈、NBT、组件化

物品在世界上的最小搬运单位是栈：一种东西、一个数量、一袋额外法律。数量有上限：64、16、1。上限是库存几何，不是物理。叠得住，潜影盒才是便携世界；叠不住，财产变成格子税。收纳袋把若干栈再装进一格，看起来像取消上限。实现上它仍是一件物品，里面另有一份口袋。口袋嵌套，迁移和窗口协议都要认这层套娃。套娃能抄。抄的时候记住：财产的单位还是栈，只是栈里开始住栈。

额外法律走过三代护照。数字 ID 加损伤值。名字加一团 `tag`。名字加一组有类型的组件。[^comp] 存储章写过护照。本章要写**为什么必须发生第三代**。

1.13 扁平化把「87 号方块、损伤值当种类」收成名字。物品跟着走：一种东西一个 id，损伤不再兼职种类。[^flat] 扁平化是给配方 JSON 铺路。没有名字，数据包无法说「这是橡木原木」而不踩到别人的 17 号。模组当时已经用矿辞在代码外认组。正作把认组收成标签，把认物收成名字。追随发生在扁平化这一刀上：第二作者逼官方把数字号变成可热更新的字符串。刀落下，全世界的箱子要翻译。翻译按件计费。这就是口袋比山疼的预演——山可以留在未加载的柱子里，剑不能。

`tag` 是任意树。任意，所以模组能活：谁都能塞键。任意，所以正作无法校验、无法按字段同步、无法让数据包声明「这把镐的挖掘规则」。命令把整棵树当参数，冲突在运行时才爆。数据驱动若要让食物、工具、饰纹、不消耗变成 JSON，必须先知道字段叫什么。组件把树收成注册表：`minecraft:damage`、`minecraft:enchantments`、逃到 `minecraft:custom_data` 的那些。[^custom] 校验发生在加载。网络后来甚至可以只传哈希再对账。[^slot] 这不是审美。这是：口袋已经是公共 API，API 必须有模式。必须发生第三代，是因为第二代已经证明：任意树能追随模组，却追不上「热更新还要能对账」。对账失败，财产裂开。财产裂开，居住合同先碎。碎的不是皮肤。碎的是这把剑还算不算昨天那把。

```java
record ItemStack(String id, int count, Map<String, Component> components) {}

ItemStack damagedSword() {
  return new ItemStack(
      "minecraft:diamond_sword",
      1,
      Map.of("minecraft:damage", new IntComponent(12)));
}
```

示意。1.20.5 之前，同一把剑的损伤写在 `tag` 里，和模组私货并排。并排能跟随时尚。并排不能跟随时尚而不变成兼容地狱——下一节的配方、再下一节的窗口，都要读同一份法律。法律若是任意树，客户端和服务器会对不上「点这一格到底改了什么」。

<Impl title="人几乎透明，口袋极重">
玩家文件不重。重的是每一格物品的树。组件化要扫所有玩家、所有箱子、所有掉落、所有展示框。作用域和扁平化扫方块一样：已经写下的全部对象。必须发生，因为非结构化 tag 已经扛不住数据驱动；发生了，十年生存服的升级墙时钟按对象数乘阶梯计。
</Impl>

## 配方数据驱动

合成曾经是代码里的表。模组用矿辞把「所有铜锭」收成一组，好让工业和魔法的金属能互相认。正作后来把配方搬进 JSON，把矿辞的职责收成物品标签。[^recipe] 追随的路径很清楚：第二作者先把「按组认材料」做成生态，官方再把组写成 `#minecraft:logs`。

数据包能加配方、能改结果上的组件，仍常常不能让材料按组件匹配——输入还是认 ID 和标签。极限在设计章写过：新动词要写系统。实现上的对应句是：JSON 能立法的是「什么形状产出什么栈」，不是「世界上多一种合成家具以外的动词」。工作台仍是格上的方块。检索菜单（配方书）是索引，形状仍能摆。Bedrock 的触控合成更常把形状收成按钮。两边都在追模组文化的同一半：内容要能热加。两边都没把合成收成角色技能。

从硬编码到 JSON，不是程序员嫌 Java 丑。是地图作者和模组作者已经证明：配方必须能在不改 jar 的情况下增加。正作把证明收进数据包。收进之后，物品结果也得能带组件——否则数据驱动会在口袋门口再次撞上任意 `tag`。扁平化已经把方块和物品的数字号收成名字；配方 JSON 才能用名字说话。名字冲突从「87 号是谁的」变成「这个命名空间是谁的」。冲突还在。冲突挪到了作者能热更新的那一层。这就是追随：把立法席从 jar 挪到数据包，但仍把新动词留在代码里。锻造、切石、烟熏，后来也走同一条路：形状不同，法律仍是 JSON。法律仍读栈。栈一改护照，所有形状的表都要能把旧结果认回来。认不回来，就是迁移地狱提前在配方里彩排。

进度系统解锁配方，看起来像 RPG。实现上它只是给窗口加了一份「你已知道的形状」列表。列表可以关。形状还在工作台上。检索雇走注意力，那只手仍可以记得九格。记得九格，合成才和房子用同一把尺。

## 窗口协议

打开箱子，不是「客户端自己改数组」。服务器发一个窗口号，客户端在那张桌上点。点击是一条消息：哪一格、哪个键、哪种模式（丢出、快速移动、数字键交换）。服务器校验，再把槽位同步回去。[^win] 权威在服务端。预测可以先在客户端演，对不上就橡皮筋——物品飞回原格。

窗口有类型。工作台九格、熔炉三格、漏斗五格、铁砧合成栏，看起来是家具，协议上是不同的桌布。桌布决定哪些点击合法。创造模式的检索栏是另一张桌布：看起来像浏览器，仍要经过权威。中间键复制、数字键映射热键栏，都是点击模式，不是客户端私自克隆。克隆若只发生在本地，多人里就会出现「我看见有、服务器没有」。所以窗口协议必须跟组件走：以前可以塞一整棵 NBT，现在槽位是类型化字段。点击包甚至可以只带组件哈希，让服务器用自己那份权威对账。这是反杜普，也是反「客户端说我有三十组」。不要步骤。只要：口袋是网络对象。点一下是立法请求，不是本地 UI。

漏斗是口袋伸进红石的那只手。它每一拍想物品，比较器再把想的结果收成 0–15。下一章的粉会读到这里。财产一旦能被信号读到，农场和钟就不必再问玩家开不开箱子。不问，是设计自由。不问，也是税：方块实体每一拍报名，窗口却只在打开时贵。两种贵不要混。混了，会以为关着的漏斗墙跟关着的箱子一样安静。

光标上那一格——你拖着走的半组——也是栈。窗口关闭时它必须有地方去：进背包，或掉成实体。掉成实体，税从口袋转到上一章的名单。同步失败，会出现「我看见有、服务器没有」或反过来。看见的流畅，是预测。真实是权威那一份槽位数组。多人里，裂开就是杜普和掉物。上一章的更新图会漏物品实体；这一章的窗口会漏栈。漏的都是财产。堵的都是权威。堵完，生态会把剩余的缝继续当 API——直到下一次组件化。

## 迁移地狱

物品难迁，是因为三件事叠在同一把剑上：格式阶梯、模组私货、窗口里正在飞的那一格。

阶梯在存储章：`DataVersion` 带着每一棵树走。物品从损伤值走到 `tag` 走到组件，中间不能跳。跳了，附魔会变成未知，名字会变成空气。模组不在官方梯子上。矿辞变成标签之后，没改包的模组会发现「铜」不再是那个字符串。窗口里正在点的栈，升级那一瞬间若还按旧包解释，对账会写成两次给予。给予两次，看起来像杜普。杜普在这里不是技巧。杜普是护照换发时，新旧窗口各签了一笔。权威若只认一笔，另一笔必须丢掉。丢掉的那一格，就是升级夜的空气。

所以兼容地狱不是运维事故。它是产品选择：成长写在物上，物就必须跨版本仍是物。清空背包的游戏没有这种地狱。有技能树的游戏把成长写在角色上，迁移角色表。Minecraft 把成长写成可移交的栈，迁移就变成扫全世界的口袋。[《作为文化遗产的 Minecraft》](/history/heritage) 伦理在遗产章。账单在这里：追随模组文化，就要收下模组已经塞进 tag 的那些键；收成组件，就要付一次翻译。不收，口袋会停在「任意 JSON，谁崩谁负责」。

数据包能改配方和结果上的组件，仍改不了「世界上多一种合成家具以外的动词」。模组能加动词，于是模组的私货继续住在 `custom_data` 或平行的注册表里。官方阶梯负责原版剑。第二作者的剑要自己准备梯子。生存服同时装着两种梯子，升级夜才会变成政治：一边是正作的组件化，一边是模组还在用旧键。两种立法席抢同一格。抢输的那一格变成空气。空气看起来像数据丢失。丢失的是：谁有权定义这把剑。

<Constraint name="口袋是公共 API" verdict="地基" chain="成长在物上 → 栈被模组立法 → 官方必须收成可校验模式">
任意 tag 更跟随时尚。有模式的组件才能数据驱动和同步。抄走 JSON 配方，丢掉翻译阶梯，你会得到能加合成的演示，失去十年箱子里还能被认作同一把剑的世界。
</Constraint>

<Memoir title="升级后的那一格空气">
生存服宣布换版本。有人的镐还在。有人的镐变成未知。不是他没备份。是那一格里的私货不在官方阶梯上。口令「物品迁不走」能当政治，因为丢掉的不是经验条，是能交给别人的那一份时间。
</Memoir>

下一章把墙上的粉收成隐式虚拟机。未定义行为如何变成社区 API，兼容性如何压过「正确信号」。口袋的法律会进漏斗，漏斗会进红石钟。财产和因果在同一拍里对账。

## 这一章留下什么

- **爱好者**：你的强在箱子里。升级若把箱子当成可以重开的背包，清掉的是能移交的时间。配方书能搜，工作台仍是家里那张九格。点箱子是在问服务器，不是在改自己屏幕上的画。漏斗关着也会想，箱子关着才安静。
- **开发者**：能抄走的是栈（id、数量、有模式的额外法律）、配方进数据包、窗口点击由服务端权威对账。能一起抄走的还有：组件化必须发生——非结构化 tag 跟不上数据驱动和同步。抄不走的是矿辞到标签、模组私货进 `custom_data`、两套产品线的口袋 schema；以及二十年财产已经按旧护照写下。你若每年清空背包，迁移会很便宜。便宜的是养成。贵的是居住。居住把时间写成可移交的栈，栈就必须有能对账的法律。对不上账的口袋，住不进下一版。下一版仍要认昨天那把剑。认得出，才叫财产。

[^comp]: Java Edition 1.20.5 用结构化组件替换物品上的非结构化 `tag`。见 Mojang，《Minecraft Java Edition 1.20.5》，<https://www.minecraft.net/en-us/article/minecraft-java-edition-1-20-5>；[Data component format](https://minecraft.wiki/w/Data_component_format)。

[^custom]: 无法归入官方组件的自定义数据进入 `minecraft:custom_data`。见 [Data component format](https://minecraft.wiki/w/Data_component_format)。

[^slot]: Java 槽位数据改为组件结构；容器点击包可用组件的 CRC32C 哈希对账。见 [Java Edition protocol/Slot data](https://minecraft.wiki/w/Java_Edition_protocol/Slot_data)。

[^recipe]: Java 1.12 起配方开始数据驱动，1.13 起由数据包的 JSON 提供；物品标签承担「一组材料」的职责。见 [Recipe](https://minecraft.wiki/w/Recipe)、[Tag](https://minecraft.wiki/w/Tag)。

[^win]: 打开容器由服务端分配窗口；客户端发送点击，服务端校验并同步槽位。见 [Java Edition protocol](https://minecraft.wiki/w/Java_Edition_protocol) 中容器与点击相关条目。

[^flat]: Java Edition 1.13 扁平化：方块与物品从数字号加损伤值改为命名标识符。见 [Java Edition 1.13](https://minecraft.wiki/w/Java_Edition_1.13)；本书 [《存储与序列化》](/impl/storage)。
