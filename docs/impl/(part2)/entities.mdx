> **本章命题**：方块是世界的地板，实体才是每一刻的税。格子靠重复几乎免费；会动、会想、会互相挤的东西，按只计费。农场把这笔税放大到能被看见——不是因为方块太多，而是因为活物太多。

## 问题

同一片区块，一万格石头可以很安静，一百只鸡不行。石头以「调色板」里的共享状态存在：一万格同一种石头只是一行重复数据，几乎不占刻。鸡每一刻都要问：脚下是什么、要不要走、旁边那只是谁、掉落的蛋算不算新的一只。问完，这一刻五十毫秒的预算已经被买走一块（上一章的付款日，见[《游戏循环与刻》](/impl/tick)）。

要回答：为什么实体才是真正的税？可被证伪的说法是：卡顿跟方块数量成正比，生物只是会动的方块。只要还存在「鸡场比城堡更打服务器」的现象、只要漏斗墙确实比实心墙更贵，这句话就不成立。卷二把怪物写成节奏装置而非内容主力（[《生物、战斗与威胁》](/design/mobs-combat)）；本章写成：节奏装置若用实体来敲，敲的就是主循环的预算。

本章不写刷怪塔步骤，只写税的因果：谁每一刻必须被点名，点名要做哪些几何计算和决策。

## 为什么生物多了比方块多了更卡

方块的贵，贵在加载、光照、存盘：柱子多，邻居图就大。而一旦进了内存，一格石头这一刻常常什么都不做，调色板让一万格同一种石头共享一行名字。[^palette]

实体的贵，贵在每一刻。只要它还在模拟距离里，就要被点名：移动、碰撞、是否该消失、要不要选一个目标。生物再加一层：寻路把周围格子收成节点，在节点上找路；路一堵，重算会把五十毫秒吃成「这一刻只走了鸡」。物品实体也贵——不是因为有 AI，而是因为数量可以爆炸：合并来不及做，漏斗每一刻还要在上方的空间里搜它们。[^hopper]

所以「生物多了更卡」不是「生物比石头复杂」这种审美判断，而是计费单位不同：方块按格存、按需更新；实体按只、按刻。城堡是密度，鸡场是频率——频率打主循环。

玩家自己也是实体。只要你在模拟距离里，每一刻都要碰撞、要被别人的 AI 看见，掉在手边的产出要变成物品实体。多人服的「人多了卡」，有时是区块账，有时就是实体名单上的实例数。经验球、箭、雪球都短命，却能在同一刻里炸出一大堆。短命不是免费，短命是脉冲税。

Bedrock 把会动的东西叫 actor，内部结构和 Java 的实体类不是同一份代码。合写的只有合同：会动的对象按实例计税。分写的是碰撞形状、船上的物理、活塞能不能推带方块实体的方块。[^be-te] 删掉句中的 Java 或 Bedrock，关于农场的经验之谈常常要推倒重写，但「税」这句话仍然成立。

## 三类对象

不要把「世界上会动的」收成一种。

**实体**是自由对象：有坐标、有速度、有碰撞箱，不必钉在某一格的中心。玩家、牛、掉落物、沙、TNT、矿车，都是。它们进实体名单，调试屏上的 `E` 在数它们。[^entity]

**方块实体**钉在格子上。箱子、熔炉、漏斗、刷怪笼，把方块状态装不下的内容写成格子上额外挂的一份数据，其中一些每一刻还要想一件事。漏斗的冷却计时和「上面有没有物品」，走的是方块实体刻，不是随机刻。[^be] 前文的数据模型章把这一层叫法律的第三层。本章补税：有的方块实体几乎只在你打开时才贵（箱子），有的只要区块还在模拟，就每一刻报到（漏斗）。Java 的活塞推不走大多数带方块实体的方块，Bedrock 可以推。这个分叉恰好证明：钉在格上，不等于这一刻免费。

**展示实体**是后来的第三种（Java 1.19.4）：方块展示、物品展示、文本展示，为地图和数据包作者准备，用来「看起来像方块或字」，却几乎没有碰撞、不受伤、不挡路。它们仍算进 `E`，仍要同步给客户端去画。[^display] 税从物理挪到了网络和渲染。地图作者用它们替换盔甲架墙，是在换税种，不是取消税。

```java
enum Kind { BLOCK, BLOCK_ENTITY, ENTITY, DISPLAY }

int taxPerTick(Kind k) {
  return switch (k) {
    case BLOCK -> 0;          // 安静时
    case BLOCK_ENTITY -> 1;   // 漏斗每一刻想一次
    case DISPLAY -> 1;        // 几乎不撞，仍要同步
    case ENTITY -> 10;        // 示意：碰撞 + 可能的 AI
  };
}
```

示意不是分数，它要钉死的是量级：安静的石头可以是 0，一只会寻路的生物不行。设计若把「装饰用的活物」做成实体，装饰就会变成服务器账单。展示实体的出现是官方的承认：有人需要看起来像实体的东西，但不想付碰撞和 AI 的钱。

<Impl title="掉落物也是实体">
挖出来的石头先变成物品实体，再被吸进漏斗或背包。合并机制能把附近若干份收成一堆；收不完，就是地上一层「会动的税」。农场的崩溃路径经常从这里开始：产出按只增长，合并按刻发生，漏斗按刻检索。坏的不是某一格方块，坏的是预算。
</Impl>

## 碰撞与特例物理

碰撞用的是轴对齐盒子（AABB）。玩家大约宽 0.6、高 1.8 格。盒子不随身体旋转，所以贴墙斜走时，挤你的仍是那只方盒子。[^aabb] 盒子便宜，所以算得起：每一刻问六个方向，问格子实心不实心，问别的盒子叠不叠。也正因为它便宜，船、矿车、末影珍珠必须当特例来写——方盒子加网格，塞不满所有「我以为能滑过去」的场面。

格子也不都是实心立方。栅栏、墙、台阶、地毯的碰撞盒，是更瘦或更矮的盒子。实体盒子去撞方块盒子，玩家行话里才会长出「卡在墙里」「迈不上那一格」。卡不是渲染错了，是两套便宜的几何对不上玩家的直觉。特例物理往往从这里长出来：与其让所有实体都学会栅栏的形状，不如给船另写一套物理。另写是税的另一种——代码分叉了，实例仍按只点名。

碰撞不只问格子，实体和实体之间也会叠盒子：挤、推，一条船把一排人焊成一份速度。Java 后来用挤爆规则给「同一空间叠多少只」封顶；封顶是节流阀，不是物理变真实了。盒子之间的推挤，仍是每一刻的几何。几何乘以只数，就是门口那一团动物比门口那堵墙贵的原因——墙在调色板里，动物在名单上。

**步进**是给玩家的那一截台阶：高差在半格上下（实现里约 0.6 格）就能自动迈上去，不用跳。台阶、地毯能不能被迈上去，是碰撞盒高度和步进阈值的算术；灵魂沙让人矮下去一小截，则是它的碰撞盒矮于整格的算术——都是几何账，不是脚感系统。手感章会说客户端的谎。这里的诚实是：先有盒子，才有「能迈上去」。迈得上去是几何，迈起来爽是客户端。几何错了，再多粒子特效也迈不上去。迈不上，是碰撞合同，不是手感谎言。合同先于手感。

**船和矿车**把盒子焊在另一种约束上。矿车认轨道，出轨是事件；船认水面，碰撞逻辑被改过多次，Java 与 Bedrock 的手感不是同一份。特例不是没做完的物理。特例是：网格世界里，交通工具若完全服从玩家那套 AABB，会卡在岸上、对不上轨。对不上，玩家口语会长出「船挤」「矿车卡」——失败仍指得着，只是指的是特例。

沙子掉下来，是方块先变成坠落实体、落地再变回方块；TNT 点燃，也是方块变成实体。转换本身要付税：实体名单短暂变长。重力方块只有少数几种，设计上可以当例外；实现上，掉落的那几秒得请实体系统来演。

<Alternative title="若一切会动的都用连续碰撞网格">
角色控制器、凸包、连续检测，预告片会赢，五十毫秒里能养的实例会变少；玩家行话会从「鸡太多」变成「网格太密」。你得到更像引擎中间件的物理。你失去的是：盒子简单到能被玩家口算，步进简单到能被念成「半格」。
</Alternative>

## AI：目标、寻路、村民日程

AI 不是灵魂。它是每一刻的两道题：我现在要做什么，我怎么走到那一格。

**目标选择**是一张按优先级排序的表：逃跑、攻击、盯着玩家看、闲逛、捡物品。每一刻，表里优先级最高且条件满足的那一项抢到答案，决定这一刻的速度向量。表可以很短。表短，怪物才是鼓点而不是同伴；做成同伴，表会变长，税会变成「每个村民都有一份日程」。

**寻路**把周围的格子收成可走节点、连成边，再在图上跑一条 A* 的变体找路。节点在门、台阶、两格高走廊这些地方会改形状。路被玩家临时堵住，下几刻会重算。重算次数乘以只数，就是鸡场这类装置能把 MSPT 打穿的原因。[^path] 这里不写寻路优化教程，只要一句：寻路是把体素再读成图。图的半径越大，越像上一章那张邻居图，只是这次问的是「谁能站上去」。

**村民**在 1.14 之后把职业、兴趣点和作息写进了「脑」。工作站点是格上的 POI（point of interest，兴趣点，服务端单独维护的一张表），日程是刻上的班次。[^villager] 设计上，这是把布景做成社会；实现上，这是每个村民都在模拟距离里付 AI 税，还要和方块实体（工作台、堆肥桶）对账。对不上，玩家口语叫「失业」。失业是寻路和 POI 的失败，不是剧情。

盔甲架、物品展示框、画，看起来像家具。家具若做成实体，家具就进名单。地图作者用盔甲架摆字、摆模型，等于把实体名单当渲染队列用：这种用法在创造模式里零成本，在实体计数 `E` 上很贵。展示实体后来把其中一部分税改成「几乎不撞、仍要画」。换税种可以，取消税不行——客户端仍要知道那几个字在哪。骑乘把税焊在一起：船上的人、矿车上的漏斗，共享一份速度。一份速度不是一份账单——船要算，人要算，漏斗还在想。

Bedrock 的 AI 定义和 Java 的目标表不是同一份代码。合写的是：AI 等于每刻的选择加寻路。分写的是：同一只铁傀儡，两边找到的路可以绕的不是同一道门。威胁的职位仍是鼓点；鼓点用实体来敲，就要付实体的税。

## 农场与崩溃路径

农场是税的显微镜。合规的意思是：用刷怪规则、漏斗和运输，把节奏装置收成材料来源。崩溃的意思是：实例数按刻增长，主循环按只点名，直到 TPS 先死。因果很短——不是「农场不道德」，是频率打赢了预算。刷怪本身就是在生产税：规则每允许一只生物出现，名单就长一条。运输若做成矿车，税种叠加；运输若做成水流，税从实体挪到流体那张邻居图上。挪不是免费，挪是换一张账单。本章不要塔，只要一句话：产出接口若返回实体，性能成本就已经被写进设计。

存储把已经完全生成的实体另存进单独的 `entities/` 目录，是为了让一只鸡不至于把整个区块的方块状态锁在一起（见[《存储与序列化》](/impl/storage)）。分柜不分税：税在刻上——区块被加载之后，名单上的每一只仍要报到。模拟距离是节流阀：看不见的城可以冻成原型，看得见且在模拟里的鸡必须付 AI 税。视距拧大、模拟距离拧小，你会看到一座会动的风景——风景里的村民可以是布景。布景一旦进模拟，布景就变税。

经典崩溃路径不需要图纸也能讲清楚：掉落物来不及合并；漏斗墙每一刻检索；动物挤进同一个格，挤爆规则开始造成伤害——Java 的 `maxEntityCramming` 默认 24，是「叠在同一空间里超过 24 只就掉血」的上限，不是给农场的许可证。[^cram] 展示实体不挤人，但能把 `E` 和网络带宽撑满。刷怪笼是方块实体，却在生产实体；生产成功，税就从方块实体转到实体名单。矿车漏斗把方块实体的「想」和实体的「动」焊在一起，税种叠加。叠加不是技巧清单，叠加的意思是：同一个位置既要每一刻想，又要每一刻撞。

官方一次次加规则：挤爆、模拟距离、实体渲染距离、掉落物合并。规则是节流阀，节流阀的存在承认税在。不承认税的写法是：再加一种会动的装饰，却按方块的价格卖给设计。设计可以加鸡，实现必须问：这只鸡在模拟距离里每一刻要走寻路吗？问完，预算才写得进合同。不问，城堡会先赢，鸡场会后到；后到的那一天，MSPT 已经没有讨价还价的余地。

能指着「实体按只、按刻计费」就够了。下一格怎么铺、漏斗怎么锁，留给别的网站。崩溃路径是机制。图纸是攻略。
</Callout>

<Constraint name="实体按只计税" verdict="地基" chain="每刻点名 → 碰撞与 AI → 实例数打穿 50 ms">
方块靠重复便宜。实体靠实例昂贵。把装饰做成实体，装饰会变成服务器。把计算做成方块更新，计算可以长在墙上。抄走 AABB 和目标表，丢掉「安静的格可以是 0」，你会得到更统一的对象模型，失去这座能盖满石头却栽在鸡上的世界。
</Constraint>

<Memoir title="城堡比鸡场安静">
生存服上最卡的往往不是最高的塔，是某个角落里掉落物和漏斗在同一刻里对账。石头不会报到，鸡会。老玩家那句「把动物处理掉」能当运维口令用，是因为税看得见：E 在涨，ms ticks 在涨，炉子又慢了。
</Memoir>

下一章把能被丢掉、交给别人、放回世界的那一份请出来：物品。玩家本人几乎透明；透明的口袋，迁移时却是最重的那袋。

## 这一章留下什么

- **爱好者**：一万格石头可以不卡，一百只鸡会卡，因为鸡每一刻都要被点名。漏斗比实心墙贵，因为漏斗会想。地上一层掉落物不是风景，是还没进背包的税。
- **开发者**：能抄走的是三类对象——安静方块、按需或按刻的方块实体、每刻碰撞（加可选 AI）的实体；展示实体是换税种。能一起抄走的还有：AABB 加步进、交通工具必须特例、寻路是体素上的图、挤爆和模拟距离是节流阀。抄不走的是二十年农场口语已经把「E 太高」当成这个游戏的性格；Java 推不走带方块实体的方块而 Bedrock 能推，两边的船和村民 AI 也不是同一份物理。你若把生物做成会动的方块、或让所有装饰付 AI，会得到统一的类层次，失去能盖满世界却必须给活物做预算的那台机器。税要写进合同：谁每刻报名。
