> **本章命题**：方块是世界的地板，实体才是这一拍的税。格子可以靠重复几乎免费；会动、会想、会互相挤的东西，按只计费。农场把税写到能看见，不是因为方块太多。

## 问题

同一片区块，一万格石头可以很安静。一百只鸡不行。石头住在调色板里，重复几乎不占拍。鸡每一拍都要问：脚下是什么、要不要走、旁边那只是谁、掉落的蛋算不算新的一只。问完，五十毫秒已经被买走一块。[《游戏循环与刻》](/impl/tick)

要回答：为什么实体才是真正的税？可被证伪的说法是：卡顿跟方块数量成正比，生物只是会动的方块。只要还存在「鸡场比城堡更打服务器」、只要还存在漏斗墙比实心墙更贵，这句话就不成立。卷二把怪物写成节奏装置，不写成内容主力。[《生物、战斗与威胁》](/design/mobs-combat) 本章写成：节奏装置若用实体来敲，敲的是主循环的预算。

不要刷怪塔步骤。要写税的因果：谁每拍必须被点名，点名要做哪些几何和选择。

## 为什么生物多了比方块多了更卡

方块的贵，贵在加载、光照、存盘：柱子多，邻居图大。一旦已经在内存里，一格石头这一拍常常什么都不做。调色板让一万格同一种石头共享一行名字。[^palette]

实体的贵，贵在每一拍。只要这块还在模拟距离里，它就要被点名：移动、碰撞、是否该消失、要不要选一个目标。生物再加一层：寻路把格子收成节点，在节点上找路。路一堵，寻路会把五十毫秒吃成「这一拍只走了鸡」。物品实体也贵——不是因为有 AI，是因为数量可以爆炸，合并规则来不及，漏斗每一拍还要在上面的空间里搜它们。[^hopper]

所以「生物多了更卡」不是生物比石头复杂这个审美判断。它是计费单位不同：方块按格存、按需更新；实体按只、按拍。城堡是密度。鸡场是频率。频率打主循环。

玩家自己也是实体。你在模拟距离里，每一拍要碰撞、要被别人的 AI 看见、手持的掉落要变成物品实体。多人服的「人多了卡」，有时是区块，有时就是名单上的实例。经验球、箭、雪球，短命，但能在同一拍里炸出一堆。短命不是免费。短命是脉冲税。

Bedrock 把会动的东西叫 actor，柜子和 Java 不是同一份。合写的是合同：会动的对象按实例计税。分写的是碰撞形状、船上的物理、活塞能不能推带方块实体的方块。[^be-te] 删掉句中的 Java 或 Bedrock，农场口令常常要改盖法，税的句子仍在。

## 三类对象

不要把「世界上会动的」收成一种。

**实体**是自由对象：有坐标、有速度、有碰撞箱，不必钉在某一格的中心。玩家、牛、掉落物、沙、TNT、矿车，都是。它们进实体名单，调试屏上的 `E` 在数它们。[^entity]

**方块实体**钉在格上。箱子、熔炉、漏斗、刷怪笼把状态装不下的内容写成额外一份数据；有的每一拍还要想一件事。漏斗的冷却和「上面有没有物品」，是方块实体刻，不是随机刻。[^be] 上一章的数据模型把这一层叫法律的第三层。本章补税：有的方块实体几乎只在你打开时才贵（箱子），有的只要区块在模拟，就每拍报名（漏斗）。活塞在 Java 推不走大多数方块实体；Bedrock 可以推。分叉证明：钉在格上，不等于这一拍免费。

**展示实体**是后来的第三种：方块展示、物品展示、文本展示。为地图和数据包准备，用来「看起来像方块或字」，却几乎没有碰撞、不受伤、不挡路。它们仍算进 `E`，仍要同步给客户端画。[^display] 税从物理挪到网络和渲染。地图作者用它们代替盔甲架墙，是在换税种，不是取消税。

```java
enum Kind { BLOCK, BLOCK_ENTITY, ENTITY, DISPLAY }

int taxPerTick(Kind k) {
  return switch (k) {
    case BLOCK -> 0;          // 安静时
    case BLOCK_ENTITY -> 1;   // 漏斗每一拍想一次
    case DISPLAY -> 1;        // 几乎不撞，仍要同步
    case ENTITY -> 10;        // 示意：碰撞 + 可能的 AI
  };
}
```

示意不是分数。它要钉死量级：安静的石头可以是 0；一只会寻路的生物不是。设计若把「装饰用的活物」做成实体，装饰会变成服务器账单。展示实体的出现，是官方承认：有人需要看起来像实体的东西，但不想付碰撞和 AI。

<Impl title="掉落物也是实体">
挖出来的石头先变成物品实体，再被吸进漏斗或背包。合并半径能把若干份收成一堆，收不完就是地上一层「会动的税」。农场的崩溃路径经常从这里开始：产出按只增长，合并按拍发生，漏斗按拍检索。不是某一格方块坏了。
</Impl>

## 碰撞与特例物理

碰撞用的是轴对齐盒子：AABB。玩家大约宽 0.6、高 1.8。盒子不旋转，所以对角走路仍按方盒子挤。[^aabb] 穷，所以能算：这一拍问六个方向，问格子实心不实心，问别的盒子叠不叠。穷，所以船、矿车、末影珍珠必须当特例——方盒子加网格，塞不满所有「我以为会滑过去」的场面。

格子也不都是实心立方。栅栏、墙、台阶、地毯，碰撞是更瘦或更矮的盒子。实体的盒子去撞方块的盒子，口令才会长出「卡在墙里」「迈不上那一格」。卡不是渲染错了。卡是两套穷几何对不上玩家的直觉。特例物理往往从这里长出来：与其让所有实体学会栅栏的形状，不如给船另写一套。另写是税的另一种：代码分叉，实例仍按只点名。

碰撞不只问格子。实体和实体也会叠盒子：挤、推、船把一排人焊成一份速度。Java 后来用挤爆规则给「同一格叠多少只」封顶。封顶是节流，不是物理变真实。盒子之间的推，仍是每一拍的几何。几何乘只数，就是门口那一团动物为什么比门口那堵墙贵。墙在调色板里。动物在名单上。

**步进**是给玩家的那一截台阶：高差大约半格，可以不用跳。台阶、地毯、灵魂沙的沉陷，是盒子高度和步进阈值的算术，不是脚感系统。脚感章会说谎。这里的诚实是：先有盒子，才有「能迈上去」。迈得上去，是几何。迈起来爽，是客户端。几何错了，再多粒子也迈不上去。迈不上，是碰撞合同，不是手感谎言。合同先于手感。

**船和矿车**把盒子焊在另一种约束上。矿车认轨道，出轨是事件。船认水面，碰撞曾被改过多次，Java 与 Bedrock 的手感不是同一份。特例不是没做完的物理。特例是：网格世界里，交通工具若完全服从玩家那套 AABB，会卡在岸上或对不上轨。对不上，口语会长出「船挤」和「矿车卡」——失败仍指得着，只是指的是特例。

沙子掉下来，是方块变成坠落实体，再变回方块。TNT 点燃，是方块变成实体。转换本身要付税：短暂的实体名单变长。重力例外在设计上是「少数掉」。实现上，掉的那些要请实体来演。

<Alternative title="若一切会动的都用连续碰撞网格">
角色控制器、凸包、连续检测，预告片会赢。五十毫秒里能养的实例会变少；口令从「鸡太多」变成「网格太密」。你得到更像引擎中间件的物理。你失去的是：盒子能被截图成整数，步进能被念成半格。
</Alternative>

## AI：目标、寻路、村民日程

AI 不是灵魂。它是每一拍的两道题：我现在要做什么，我怎么走到那一格。

**目标选择**是一张表：逃跑、攻击、看玩家、闲逛、捡物品。表按优先级抢答。抢到的那一项，决定这一拍的速度向量。表可以很短。短，怪物才是鼓点而不是同伴。做成同伴，表会变长，税会变成「每个村民都有一份日程」。

**寻路**把周围的格子收成可走节点，再找一条边。节点在门、台阶、两格高的走廊上会改形状。路被玩家临时堵住，下几拍会重算。重算乘以只数，就是鸡场和猪人门为什么能把 MSPT 打穿。[^path] 不要优化教程。只要：寻路是把体素再读成图。图的半径越大，越像上一章那张邻居图，只是问的是「谁能站上去」。

**村民**在 1.14 之后把职业、兴趣点和作息写进脑。工作站点是格上的 POI，日程是拍上的班次。[^villager] 设计上这是把布景做成社会。实现上这是：每个村民都在模拟距离里付 AI 税，而且还要和方块实体（工作台、堆肥桶）对账。对不上，口语叫「失业」。失业是寻路和 POI 的失败，不是剧情。

盔甲架、展示框、画，看起来像家具。家具若做成实体，家具就报名。地图作者用盔甲架摆字、摆模型，是在用实体当打印头。打印头便宜在创造栏，昂贵在 `E`。展示实体后来把一部分打印税改成「几乎不撞、仍要画」。换税种可以。取消税不行——客户端仍要知道那几个字在哪。骑乘把税焊在一起：船上的人、矿车上的漏斗，碰撞形状共享一份速度。一份速度不是一份账单。船要算，人要算，漏斗还在想。

Bedrock 的脑和 Java 的目标表不是同一份代码。合写的是：AI 是每拍的选择加寻路。分写的是：同一只铁傀儡，两边的路可以绕不开同一道门。威胁的职位仍是鼓点。鼓点用实体来敲，就要付实体的税。

## 农场与崩溃路径

农场是税的显微镜。合法的意思是：用刷怪规则、漏斗和运输，把节奏装置收成材料。崩溃的意思是：实例数按拍增长，主循环按只点名，直到 TPS 先死。因果很短——不是「农场不道德」，是频率打赢了预算。刷怪本身是在生产税：规则允许一只东西出现，名单就长一条。运输若做成矿车，税种叠加；运输若做成水流，税从实体挪到流体那张邻居图。挪不是免费。挪是换一张账单。不要塔。只要：产出接口若返回实体，性能接口就已经被写进设计。

存储把完全生成后的实体另放进 `entities/` 柜子，是为了让一只鸡别把整节方块状态锁上。[《存储与序列化》](/impl/storage) 分柜不分税。税在拍上：柜子打开之后，名单上的每一只仍要报名。模拟距离是节流阀：看不见的城可以冻成原型，看得见且在模拟里的鸡必须付 AI。视距拧大、模拟拧小，你会看到一座会动的风景——风景里的村民可以是布景。布景一旦进模拟，布景就变税。

经典路径不需要图纸也能说。掉落物来不及合并。漏斗墙每一拍检索。动物进一个格，挤爆规则开始杀人——Java 的 `maxEntityCramming` 默认 24，是给「叠在同一格」的上限，不是给农场的许可证。[^cram] 展示实体不挤人，但能把 `E` 和网络撑满。刷怪笼是方块实体，它在生产实体。生产成功，税从方块实体转到实体名单。矿车漏斗把方块实体的想事和实体的移动焊在一起，税种叠加。叠加不是技巧名单。叠加是：同一地址上既要每拍想，又要每拍撞。

官方一次次加规则：挤爆、模拟距离、实体渲染距离、合并。规则是节流阀。节流阀承认税在。不承认的写法是：再加一种会动的装饰，却按方块的价格卖给设计。设计可以加鸡。实现必须问：这只鸡在模拟距离里每拍要走寻路吗？问完，预算才写得进合同。不问，城堡会先赢，鸡场会后到，后到的那一天 MSPT 已经没有讨价还价。

<Callout type="warning" title="不写塔">
能指着「实体按只、按拍计费」就够了。下一格怎么铺、漏斗怎么锁，留给别的网站。崩溃路径是机制。图纸是攻略。
</Callout>

<Constraint name="实体按只计税" verdict="地基" chain="每拍点名 → 碰撞与 AI → 实例数打穿 50 ms">
方块靠重复便宜。实体靠实例昂贵。把装饰做成实体，装饰会变成服务器。把计算做成方块更新，计算可以长在墙上。抄走 AABB 和目标表，丢掉「安静的格可以是 0」，你会得到更统一的对象模型，失去这座能盖满石头却栽在鸡上的世界。
</Constraint>

<Memoir title="城堡比鸡场安静">
生存服上最卡的往往不是最高的塔。是某个角落里，掉落物和漏斗在同一拍里对账。石头不会报名。鸡会。口令「把动物处理掉」能当运维，是因为税看得见：E 在涨，ms ticks 在涨，炉子又慢了。
</Memoir>

下一章把能被丢掉、交给别人、放回世界的那一份请出来：物品。人几乎透明。透明的口袋，迁移时却是最重的那袋。

## 这一章留下什么

- **爱好者**：一万格石头可以不卡，一百只鸡会卡，因为鸡每一拍都要被点名。漏斗比实心墙贵，因为漏斗会想。地上一层掉落物不是风景，是还没进背包的税。
- **开发者**：能抄走的是三类对象——安静方块、按需或按拍的方块实体、每拍碰撞（加可选 AI）的实体；展示实体是换税种。能一起抄走的还有：AABB 加步进、交通工具必须特例、寻路是体素上的图、挤爆和模拟距离是节流阀。抄不走的是二十年农场口语已经把「E 太高」听成性格；Java 的方块实体推不走对 Bedrock 的可推、两边的船和村民脑，不是同一份物理。你若把生物做成会动的方块、或让所有装饰付 AI，会得到统一的类层次，失去能盖满世界却必须给活物做预算的那台机器。税要写进合同：谁每拍报名。

[^cram]: Java 游戏规则 `maxEntityCramming` 默认 24（1.11）。见 [Game rule](https://minecraft.wiki/w/Game_rule)。
