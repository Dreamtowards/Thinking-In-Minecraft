> **本章命题**：数据层改内容和一部分规则，系统层才加得出新动词。全脚本养不出墙上那台用红石搭出来的计算机，全原生养不出能热更新的地图工业。两层缺一，再开发会塌成审核货架，或塌成年年跟着版本重来的注入修补。作者体验不是文档站，是引擎产品。

## 问题

有了数据包，还是有人要写 Java；有了脚本 API，还是切不进活塞的检查逻辑。数据包这条官方温和路线停在动词前面：配方、战利品、进度都改得动，一种新的挖掘方式造不出来（[《数据包、资源包与数据驱动》](/impl/datapacks)）；Bedrock 的脚本同样停在引擎壁上（[《Bedrock 作为另一次实现》](/impl/bedrock)）。停不是疏忽，是政治：放开多少、审核多少、和 Marketplace 的货架怎么相处。政治进了考场，就变成一句硬话：**两端都会失败**——失败的方式不同，塌法不同。

要回答：为何两端都会失败？可被证伪的说法是：脚本足够快就能替代模组；或者给了稳定的原生 API，数据包就可以退休。只要函数还做不出第二种挖掘、只要 Mixin 还在版本夜——新版本发布、模组集体失灵的那一夜——集体失灵、只要 Marketplace 还装不下工业风格的系统包，这句话就不成立。

不变量第 6 条要的是席位，不是某一家加载器（[《必须保留的设计不变量》](/rewrite/invariants)）。卷三论证过：在官方签名 API 缺席的年代，注入点本身就是 API——民间用切口定义合同（[《模组与插件架构》](/impl/mod-architecture)）。本章提案：把这份民间合同收编成明码标价的两层权限，而不是许诺「以后做一个超级脚本语言」。加系统与加内容的边界，数据包那一章已经用二十年划出来了。

## 全脚本与全原生的失败模式

**全脚本。** 地图作者高兴：热重载、随世界分发、崩溃通常只炸这一张图。失败在系统：碰撞、刻、通知半径、新的「使用」对象——这些东西一旦进沙盒，就要么慢到不可用，要么被剪掉权限。而剪权限的理由永远成立：要过审核、要上主机平台、要「别把服务器打崩」。剪完之后，准连接这样的民间机制不会再繁殖出来——沙盒里没有可以误用的实现细节，只有被批准过的接口；工业管道也不会长成第二种物理。你得到的是货架友好的繁荣。繁荣是真的，但繁荣的不是墙上那台用红石搭出来的计算机。Bedrock 的脚本 API 已经把这条失败模式演示成了正式产品：能挂世界事件、能调度任务，却切不进活塞和碰撞那一层。

**全原生。** 引擎作者高兴：热路径在自己手里，新动词就是一个类。失败在内容：改一条掉落、改一个配方、改一条进度，都要编译、都要追版本夜、都要进兼容矩阵（版本 × 模组，一格一个坑）。地图工业活不成，教育包活不成。回想数据包的诞生：它是对模组文化的追随，让不会写系统语言的人也能改内容（[《命令、数据包与地图》](/design/commands-datapacks)）。追回来再取消，等于宣布第二作者只准是会写系统语言的人。门槛一抬，作者席变窄。窄掉的席看起来很像「正式 API」——正式，却空。空的证据是现成的：数据包出现之前，改掉落必须整套装模组；模组平台再繁荣，也长不出教育版课堂里那种「这节课每人交一个函数」的作业。

两端还有对称的崩溃：全脚本把世界锁在解释器里，一个死循环就能卡死共享真实；全原生把一次空指针变成整个进程的立法失败。失败域若不分开，小游戏里一个坏函数会带走十年的生存档。分开是下一节的权限问题，不是礼貌问题。

## 双层模型与崩溃域

两层叠在同一个实例上，认同一套格子和同一份权威。

| | 数据层（沙箱） | 系统层（原生 / 等价切口） |
| --- | --- | --- |
| 能做什么 | 配方、战利品、进度、函数、标签、部分世界规则 | 新方块行为、新碰撞、新调度、新窗口、新因果 |
| 不能做什么 | 加不出第二种挖掘、改不了通知半径的语义 | 不该成为改一行掉落的唯一途径 |
| 分发 | 随世界、可热更新 | 随进程、通常冷启动 |
| 崩溃域 | 包失败、函数超时：实例可隔离 | 进程失败：世界停 |
| 审核友好 | 高 | 低；这是优点不是缺陷 |
| 对应原版 | 数据包、资源包、命令函数 | 模组、一部分插件（改物理时） |

这张表就是两层的权限边界。数据层被允许做的一切——配方、战利品、进度、函数、标签、部分世界规则——都不触碰结算顺序；系统层被允许做的一切——新方块行为、新碰撞、新调度、新窗口、新因果——都以进程为崩溃域。插件这一脉常常两层都碰：权限与经济像数据，点名策略像系统。提案不取消插件。提案要求：法律若只是配置，走数据层；法律若改结算，走系统层，并在声明里写明兼容哪一种调度（兴趣、租约）。有了声明，Folia 那种「运行时崩溃当说明书」的死法就能前移到加载时。

崩溃域本身是产品。数据层必须能被单独杀死而不带走永续实例：一个函数超时，罚这个函数，不罚世界。原版已经演示过这两层爆炸半径的差别：一个写坏的数据包函数，通常只是运行时报错、日志记一行，服务器照常开着；一个写坏的注入，轻则启动失败，重则把整个服务端进程带走。差别不在作者水平，在两层站的位置——数据层站在世界旁边，系统层站在引擎里面。位置决定爆炸半径。系统层的崩溃等于引擎崩溃，必须稀少、必须可复现。稀少不靠禁止系统层——那只会把危险赶到脚本里，危险不会消失，只会在沙盒里变成「卡顿当玩法」；卡顿当玩法，共享真实先死。稀少靠的是系统层自身稳定、有弃用期、错误能定位到行。

Java 的 Mixin 与 Bedrock 的脚本，不要合成一层。合成一层，才会从「这里卡」一步跳到「那就全用脚本吧」。跳过去的人，还没付第 4 条不变量的账。

## 稳定 API 面

没有稳定 API 面的时候，协议和字节码会充当面：模组去抓包、去切混淆名。充当面的后果是版本夜等于末日（[《网络协议》](/impl/protocol)）。提案要三块**承诺稳定**的 API 面，并刻意不把网络协议当模组主入口。

**世界面。** 读改格子、实体、库存、实例寿命。保证的是地址和状态，不是某一版的数据包字段。活塞推的是状态，模组问的也是状态。稳定与否可以用一句话检验：引擎内部把方块的编码方式换一遍——调色板、压缩、序列化随便改——世界面的调用一行都不用改。检验不过，就不是面，是巧合。

**内容面。** 名字、标签、配方、组件 schema。数据层走这里。版本字段挂在内容上，热更新才知道自己在跟哪一代内容说话。

**扩展面。** 系统层在这里注册新动词、新方块行为、新的事件监听。监听是事件，不是「请切开这个混淆名」。事件要有弃用周期。周期会让正作迭代变慢——慢，是把兼容矩阵的税从第二作者的深夜搬回第一作者的日程表。搬，是「完整产品」这四个字应有的主语。

协议仍然要存在，但它服务客户端和多版本翻译器。模组若只靠抓包加功能，等于面又没了。抓包可以当兼容层里的客居者，不能当新引擎的宪法。宪法在世界面：世界面对不上，包形状对上了也只是能进服的幽灵。

## 热重载与 schema

数据层应当能热。热是地图作者的呼吸：改一条战利品表，不必重启一份十年档——Java 版的 `/reload` 已经证明这条路能走。热的边界要写明：能热的是内容和一部分规则；不能热的是新类、新碰撞、新的结算监听。系统层冷启动。冷，是立法；立法不该假装成按一次 F5。这条边界也是审核的分界线：能热的东西随世界分发，出了问题撤回这份世界就行；不能热的东西进了进程，撤回就是一次升级事故。

schema 必须有版本。没有版本，热重载等于在黑暗里换护照。物品组件化已经证明迁移可以按件计费；提案把计费从物品推广到数据层一切带法律的对象：进度、函数、世界规则包。计费可以贵，贵过清空——清空是第 5 条不变量的反面。

系统层的 schema 是事件与注册表的版本，不是 JSON 文件的版本。两个版本号不要合并成一个「游戏版本」：合成一个，数据包和模组就会再次连坐。原版已经用同一套版本号体系连坐过——一处升级，全体失灵。连坐是瓶颈；瓶颈可以不进内核。

<Impl title="热重载不是魔法">
函数改完立刻跑，听起来像理想。理想碰上正在走的活塞，会得到半旧半新的相位。热更新必须选在队列边界，或对正在跑的租约拒绝热替换。拒绝很烦。烦比悄悄错相位诚实。
</Impl>

## 作者体验是产品

映射词典、弃用警告、示例包、能在游戏里打开的检查器、一句「这一层你没有权限」的报错而不是一部崩溃日志小说——这些不是社区福利，是模组平台这一格产品的成功标准（这一格在四格里占哪一格，[《我们到底在重写什么》](/rewrite/what-to-rewrite)已经分好）。

原版长期把作者体验留在 Wiki 和 Discord。留在外面，民间官方实现就会再写一遍。再写一遍不是罪；把「再写一遍」当成产品策略，等于又一次先卖再修——卷三算过这笔账（[《技术债作为产品策略》](/impl/tech-debt)）：先卖再修的前提，是你确实有人替你写说明书。

作者体验还包括把两层的门分清：数据层的人不必会系统语言，系统层的人不必为改一行掉落打开 IDE。门分清了，教育包和工业包才不会抢同一把钥匙。抢同一把钥匙不是繁荣，是兼容矩阵。

<Alternative title="若只做审核友好的一层脚本">
货架会干净，主机能进。你会失去墙上的红石计算机和加系统的入口。干净是熟人小圈子产品的美德。熟人小圈子不是模组平台。请把商标写对。
</Alternative>

<Constraint name="两层缺一席位塌" verdict="地基" chain="数据热更新内容 → 系统冷启动动词 → 崩溃域分开">
抄走双层，丢掉崩溃隔离，你会得到要么改不了物理、要么改一行掉落都要重启的引擎。两种都能卖。两种都不是完整的再开发。再开发要求地图作者和系统作者能住在同一份世界上，而不互相绑票。
</Constraint>

## 这一章留下什么

- **爱好者**：数据包改的是这一张图怎么掉东西、怎么引导你。真正的新方块、新的挖法，仍要有人改引擎那一层。两层都在，整合包才不是要么纯原版要么纯破解。
- **开发者**：能抄走的是权限表：数据层热、沙箱、随世界走；系统层冷、能加动词、崩溃即进程。能一起抄走的还有：世界 / 内容 / 扩展三块承诺稳定的 API 面，协议不当主 API；schema 版本让热重载有护照。抄不走的是 Mixin 的兼容矩阵和 Marketplace 的审核范围。你不得从本章读出「全用某种脚本语言」。两端都会失败。失败过的现场就在眼前：数据包停在动词前，附加包进不了活塞那一层。两层都在，作者席才像产品，而不像夜间施工队。
