> **本章命题**：数据层改内容和一部分规则，系统层才加得出新动词。全脚本养不出墙上的虚拟机；全原生养不出能热更新的地图工业。两层缺一，再开发会塌成货架或塌成切口夜。作者体验不是文档站，是引擎产品。

## 问题

有了数据包，还是有人要写 Java。有了脚本 API，还是切不进活塞检查。[《数据包、资源包与数据驱动》](/impl/datapacks) [《Bedrock 作为另一次实现》](/impl/bedrock) 官方温和河停在动词前。停，是政治。政治在考试里变成一句硬的：两端都会失败——失败的方式不同，塌法不同。

要回答：为何两端都会失败？可被证伪的说法是：脚本足够快就能替代模组；或者给了稳定 native API，数据包就可以退休。只要还存在函数做不出第二种挖掘、只要还存在 Mixin 在版本夜死亡、只要还存在 Marketplace 上不了工业包，这句话就不成立。

不变量第 6 条要的是席位，不是某一家加载器。[《必须保留的设计不变量》](/rewrite/invariants) 卷三把注入即 API 写成利息。[《模组与插件架构》](/impl/mod-architecture) 本章提案：把利息收成两层权限，而不是收成「以后做一个超级脚本」。design/13 的收编原则尚未成稿。本章不抢：加系统与加内容分开，是已写的数据包章已经证明过的边界。

## 全脚本与全原生的失败模式

**全脚本。** 地图作者高兴：热重载、随世界分发、崩溃常常只炸这一张图。失败在系统：碰撞、刻、通知半径、新的「使用」宾语，一旦进沙盒，就要么慢，要么被剪权限。剪权限才能过审核、过主机、过「别把服打崩」。剪完，准连接不会作为民间 opcode 繁殖，工业管道不会长成第二种物理。你得到 Roblox 式的货架友好。货架友好可以繁荣。繁荣的不是墙上的粉。Bedrock 的脚本已经把这条失败演示成产品：调度很强，切开没有。

**全原生。** 引擎作者高兴：热路径在手里，新动词就是一个类。失败在内容：改掉落、改配方、改一条进度，都要编译、都要跟版本夜、都要进兼容矩阵。地图工业活不成。教育包活不成。数据包河是对模组文化的追随，不是装饰。[《命令、数据包与地图》](/design/commands-datapacks) 追回来再取消，等于宣布第二作者只准是会写系统语言的人。门槛一抬，作者席变窄。窄的席看起来像「正式 API」。正式，却空。

两端还有对称的崩溃：全脚本把世界锁在解释器里，一次死循环卡死共享真实；全原生把一次空指针变成整进程立法失败。失败域若不分开，小游戏的坏函数会带走十年生存档。分开，是下一节的权限，不是礼貌。

## 双层模型与崩溃域

两层叠在同一实例上，认同一套格子和同一份权威。

| | 数据层（沙箱） | 系统层（原生 / 等价切口） |
| --- | --- | --- |
| 能做什么 | 配方、战利品、进度、函数、标签、部分世界规则 | 新方块行为、新碰撞、新调度、新窗口、新因果 |
| 不能做什么 | 加不出第二种挖掘、改不了通知半径的语义 | 不该成为改一行掉落的唯一途径 |
| 分发 | 随世界、可热更新 | 随进程、通常冷启动 |
| 崩溃域 | 包失败、函数超时：实例可隔离 | 进程失败：世界停 |
| 审核友好 | 高 | 低；这是优点不是缺陷 |
| 对应原版 | 数据包、资源包、命令函数 | 模组、一部分插件（改物理时） |

插件河改法律，常常两层都碰：权限与经济像数据，点名策略像系统。提案不把插件取消。提案要求：法律若只是配置，走数据层；法律若改结算，走系统层并声明兼容哪一种调度（兴趣 / 租约）。声明，Folia 那种死法会前移到加载时。

崩溃域是产品。数据层必须能被杀死而不带走永续实例。系统层的崩溃等于引擎崩溃，必须稀少，必须可复现。稀少不是靠禁止系统层。稀少靠：系统层稳定、有弃用期。把一切危险都赶到脚本里，危险不会消失，只会在沙盒里变成「卡顿当玩法」。卡顿当玩法，共享真实先死。

Java 的 Mixin 与 Bedrock 的脚本，不要合成一层。合成一层，才会从「卡」跳到「全用脚本」。跳过去的人，还没付第 4 条的账。

## 稳定 API 面

没有稳定面时，协议和字节码会充当面。充当面，版本夜就是末日。[《网络协议》](/impl/protocol) 提案要三块签名过的面，刻意不把协议当模组主入口。

**世界面。** 读改格子、实体、库存、实例寿命。保证的是地址和状态，不是某一版包字段。活塞推的是状态。模组问的也是状态。

**内容面。** 名字、标签、配方、组件 schema。数据层走这里。版本字段挂在内容上，热更新才知道自己在跟哪一代说话。

**扩展面。** 系统层注册新动词、新方块行为、新班次监听。监听是事件，不是「请切开这个混淆名」。事件要有弃用周期。周期会让正作变慢。慢，是把矩阵税从第二作者夜里搬回第一作者。搬，是完整产品写全主语。

协议仍要存在。协议给客户端和多版本翻译器。模组若只靠抓包加功能，面又没了。抓包可以当兼容层的客居者，不能当新引擎的宪法。宪法在世界面。世界面对不上，包形状对上了也只是能进服的幽灵。

## 热重载与 schema

数据层应当能热。热是地图作者的呼吸：改一条战利品不必重启十年档。热的边界写明：能热的是内容和一部分规则；不能热的是新类、新碰撞、新的结算听众。系统层冷启动。冷，是立法。立法不该假装成 F5。

schema 必须有版本。没有版本，热重载是在黑暗里换护照。组件化已经证明迁移按件计费。提案把计费从物品推广到数据层一切有法律的对象：进度、函数、世界规则包。计费可以贵。贵过清空。清空是第 5 条的反面。

系统层的 schema 是事件与注册表的版本，不是 JSON 文件。两个版本号不要合成一个「游戏版本」。合成一个，数据包和模组会再次连坐。原版用协议号连坐过。连坐是瓶颈。瓶颈可以不当内核。

<Impl title="热重载不是魔法">
函数改完立刻跑，听起来像理想。理想碰上正在走的活塞班，会得到半旧半新的相位。热更新必须选在班次边界，或对正在跑的租约拒绝热替换。拒绝很烦。烦比悄悄错相位诚实。
</Impl>

## 作者体验是产品

映射词典、弃用警告、示例包、能在游戏里打开的检查器、一份「这一层你没有权限」的错误而不是崩溃日志小说——这些不是社区福利。这些是模组平台这一格产品的成功标准。[《我们到底在重写什么》](/rewrite/what-to-rewrite)

原版把作者体验长期留在 Wiki 和 Discord。留在外面，民间官方实现会再写一遍。再写一遍可以。当产品策略，等于又一次先卖再修。先卖再修没证明你可以没有人替你写说明书。[《技术债作为产品策略》](/impl/tech-debt)

作者体验还包括：数据层的人不必会系统语言；系统层的人不必为改掉落开 IDE。两层的门要分清。分清，教育包和工业包才不会抢同一把钥匙。抢同一把，不是繁荣，是矩阵。

<Alternative title="若只做审核友好的一层脚本">
货架会干净，主机能进。你会失去墙上的 VM 和加系统的河。干净是房间半径的产品。房间半径不是模组平台。请把商标写对。
</Alternative>

<Constraint name="两层缺一席位塌" verdict="地基" chain="数据热更新内容 → 系统冷启动动词 → 崩溃域分开">
抄走双层，丢掉崩溃隔离，你会得到要么改不了物理、要么改一行掉落都要重启的引擎。两种都能卖。两种都不是完整的再开发。再开发要求地图作者和系统作者能住在同一份世界上，而不互相绑票。
</Constraint>

## 这一章留下什么

- **爱好者**：数据包改的是这一张图怎么掉东西、怎么引导你。真正的新方块、新的挖法，仍要有人改引擎那一层。两层都在，整合包才不是要么纯原版要么纯破解。
- **开发者**：能抄走的是权限表：数据层热、沙箱、随世界走；系统层冷、能加动词、崩溃即进程。能一起抄走的还有：世界 / 内容 / 扩展三块签名面，协议不当主 API；schema 版本让热重载有护照。抄不走的是 Mixin 矩阵和 Marketplace 的审核范围。你不得从本章读出「全用某种脚本语言」。两端都会失败。失败过的现场叫数据包停在动词前，和附加包进不了活塞。两层都在，作者席才像产品，而不像夜间施工队。
