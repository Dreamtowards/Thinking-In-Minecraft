> **本章命题**：同一套可寻址的格子，必须同时服务「住十年的家」和「十二分钟一局的战场」。差的不是度量衡，是实例的寿命政策。把小游戏做成另一份物理，口令会裂；把生存做成不可重置的唯一实例，大厅会把家拖死。旧档是第一等公民，不是导入向导里的可选项。

## 问题

生存档里那座山，玩家打算走一辈子；起床战争的岛，一局结束就要清平重来。两边都在挖、都在放、都在认「门是两格高」。原版用同一种东西硬扛这两种寿命：一份按区块柱体组织的世界文件。家付无限的流式账单，大厅只好在服务端外面再开几个进程、每个进程装一份世界，用运维手艺假装它们还是同一个国家（这份账单怎么算，[《服务端与规模》](/impl/servers)已经算过）。硬扛会裂。裂的不是方块好不好看，是：**重置和居住在抢同一种表示法。**

要回答：怎样同时服务生存与小游戏？可被证伪的说法有两个：只要格子还在，一份世界文件就能当所有产品用；或者反过来，小游戏应当另做一套连续关卡，生存单独用体素。只要大厅和主世界还在抢同一份每秒二十刻的预算、只要换一张地图还等于换一套物理、只要还有十年前的存档打不开而赛季服满不在乎，这两个说法就都不成立。

上一章把表示法里可以抛弃的偶然松开了：语言运行时、全局二十刻，都是实现的选择而非世界的本质（[《可以抛弃的历史偶然》](/rewrite/accidents)）。本章提案只动柜子的组织方式，不换一米这把尺，并且逐条对齐七条不变量（[《必须保留的设计不变量》](/rewrite/invariants)）。本章交付的是一张「原版怎么装、提案怎么分装」的对照表，不是某门语言的伪代码大全。兼容的梯子怎么搭，留给后文的兼容章；本章只把一件事写成表示法自己的职责：**旧档必须能被指着说「还在」，而不是售后部门的一项可选服务。**

## 表示法要服务两种产品

两种产品都需要格子，但不需要同一种寿命。提案不把它们收成两种引擎，而是把「寿命」从产品属性收成实例属性。

**居住实例**要稀疏、要流式、要旧。人走远了，区块柱体可以卸到磁盘；人回来，墙还在原来的坐标上。空气必须便宜到近乎免费，否则「无限世界」就是一句自杀的修辞。库存和熔炉的账记在方块实体名下，不摊到每一格里。这份实例的成功标准只有一条：十年之后，仍能指着某一行坐标说「这是当年那扇门」。

**对局实例**要密、要短、要可丢。岛很小，实体很多，十二分钟后整份世界可以作废重来。成功标准是三条：重置便宜；因果在这一局之内可复述——这局怎么赢的、那台机器怎么炸的，都说得清；下一局不欠上一局的光照债。原版把对局塞进居住实例里，靠插件在半夜清场。清场是在虐待表示法：表示法若认识「实例」，重置就是生命周期的一次正常翻页，而不是一次偷偷摸摸的回档。

共用的是度量：一米、可破坏、可放置、可计数、空气也是合法状态。不共用的是三件事：**这一份格子活多久、卸盘策略是什么、要不要进旧档兼容的梯子。** 大厅进程和主世界进程，是原版用运维手段凑出来的多实例。提案把它收进内核：同一个模拟核心认同一套状态，世界 ID 不同，寿命政策不同。政策是数据——「永续」「赛季」「这一局」都是合法取值。政策不是另一套碰撞箱。

于是创造服的展览、小游戏的战场、家庭生存档，可以跑在同一个内核上，而不必假装共住在同一份 `region/` 里。用四产品矩阵的说法，这是原版体验和服务器平台共享骨头、分开实例（[《我们到底在重写什么》](/rewrite/what-to-rewrite)）。共享失败的样子很具体：起床战争的重置误删了隔壁玩家的家，或者家的无限柱体把大厅的毫秒预算一起拖烂。

Java 的 Anvil 与 Bedrock 的 LevelDB 是两套柜子，但那是两条实现史，不是两种产品需求（[《两条产品线：Java 与 Bedrock》](/history/java-bedrock)）。提案不要求把两套柜子合并成一套。提案要求的是：无论哪套柜子，都要能同时表达「永续实例」和「可丢实例」。表达不了，你就只服务了矩阵里的其中一格。

## 稀疏与调色板

「无限」是修辞，账单落在区块上（[《世界生成即内容生产》](/design/worldgen)）。原版其实已经做对了大半：Java 版把一个区块竖着切成十六格高的小节，每节各自维护一张短表——调色板。这一节里出现过的方块状态各记一行，每个格子只存「表里的第几行」；千篇一律的石头共享同一行，空气也是表里一个合法条目（[《体素世界的数据模型》](/impl/data-model)）。提案不打算改成八叉树以示现代。八叉树可以当某个实现的偶然选择。不变量要的是：地址仍是整数格，I/O 仍按区块柱体切，「空气也是状态」这条法律仍在。

稀疏的意思是：没人去过的柱体可以不在内存里，甚至可以还没有生成。生成是管道，不是表示法的对立面。表示法要允许「尚未存在」和「存在但是空气」是两种不同的法律——原版用「未加载」和「空气状态」大约做到了这个区分。提案把这两种法律升成第一等：未生成不是空指针漏洞，是生命周期的一站。对局实例可以整图预生成、整图丢弃；居住实例必须允许玩家走出去、再触发生成。两种生命周期共用调色板，不共用「必须先铺满」这条假设。

调色板的边界仍然是：一格的法律必须可数。不可数的属性——比如把任意 NBT 挂在每一格上——会把短表胀成每格一份行李，活塞也就推不动「这一格的法律」了：它连这一格有哪几种合法状态都枚举不出来。原版把库存从方块状态里赶进方块实体，这一步是对的。提案保持这道墙。墙这边：朝向、开合、水位、含水，进状态、进调色板。墙那边：箱子内容、熔炉进度、刷怪笼名单，进方块实体的账户。账户可以组件化；格子不能。格子一旦组件化到任意字段，稀疏会死在空气海里——每格都背一份组件表，压缩就不存在了。

流式 I/O 是居住实例的呼吸。对局实例可以不呼吸：整图驻留内存，对局结束即删。内核如果只有一种呼吸方式，万人大厅就得按十年生存档的节奏存盘——那不是内核性能不行，是政策装错了。政策写在实例上，算法可以共享。

## 状态 vs 组件

原版自己走过两次改革：扁平化把数字 ID 收成「名字加状态」；组件化把物品上任意堆积的 tag 收成有模式的字段（[《物品、库存与合成》](/impl/items)）。两次都对，但对象不同——一次改的是方块，一次改的是物品。提案把对象边界写死，免得第三次改革又混成「一切皆组件」。

**方块状态**服务活塞、命令、调色板和玩家的口令。它必须是有限键值：有限，才能被推、被数、被指。含水在 Java 是状态上的一位，在 Bedrock 是另起一层的独立方块——这是口音，可以分叉。不变量是：无论哪种口音，都必须可点名、可进调色板。

**物品组件**服务财产。一把剑要能对账、能移交、能跨版本迁移。模组的私货走显式的逃生口，不能污染官方字段——原版的 `custom_data` 组件就是这个方向。提案保持并加一条：组件带 schema 版本，迁移按件计费。计费是伦理（第 5 条不变量），不只是性能彩蛋。

**方块实体 / 实体**服务账户和开销。实体的计算成本远高于方块，卷三已经算过这笔账（[《实体与碰撞》](/impl/entities)）。提案不把展示用的装饰默认做成实体海：能进状态或短寿命对象的装饰，不要进万人广播名单。表示法在这里为协议省下真实的带宽。这不是优化指南——这是：玩家看见的流畅，不该强迫每一片落叶都有一份权威生命。

对照不是选型，是职责。职责一混，生存的山会像物品一样难迁移，小游戏的剑会像空气一样不可数。

## 多世界、确定性回放

多世界不是「再加几个维度」。下界和末地本质上是规则变体：换生成器、换床的合法性、换水的形态（[《维度、进度与终局》](/design/dimensions-endgame)）。提案里，变体就是实例上的一份规则包：重力、床、水、生成器各占一项。大厅、战场、剧场、测试用的红石平板，同样都是实例。实例可以共享同一个种子推导——那是「可能世界」的口令；也可以完全手摆——那是地图作者写的文本。

确定性回放服务两件事：调试与伦理。调试：这一刻谁改了哪一格、那台飞行器为什么停。伦理：回滚不是神话，是对玩家时间的手术。表示法要为此留下足够的因果钩子——哪一个实例、哪一节、哪一份状态版本——下一章的调度器才有钩子可挂，把因果收成可解释的队列。钩子不是全量录像，全量录像是另一种产品。钩子是：状态迁移带着版本号，事件可以按实例重放一小段。小游戏用它做「这一局的录像」，生存用它做「回档到被熊孩子拆毁之前」。两种用法认同一套版本字段。

Java 与 Bedrock 的种子本就不是同一把钥匙（[《世界生成管线》](/impl/worldgen-pipeline)），提案不假装一份噪声两边通用。确定性是**实例内部**的合同：同一版本、同一规则包、同一输入，应当得到可复述的同一批柱子。跨产品线的确定性，只能是兼容层的翻译——翻译要标明是翻译，不能谎称合同。

## 旧档

旧档不是「导入」。导入这个词假定过去是别人的格式；而 Minecraft 的过去是玩家投入的时间。表示法若把「新世界」当默认、把旧世界当转换器插件，第 5 条不变量——世界比引擎活得更久——在内核里就已经假了。

提案把旧档写成第一等公民：每一份实例都带 schema 版本；加载即自动走兼容梯子；走不动的格子变成**显式的未知状态**，而不是空气假装什么都没发生。未知状态能被指着、能被活塞当障碍物、能等以后的翻译器再认。空气假装是拆迁；未知是诚实。

对局实例可以声明「不进梯子、可丢」。声明必须是实例层面的政策，不能变成引擎默认——默认仍是居住：读得起昨天。读得起的代价有多贵，后文兼容章会写成伦理账单。本章只要求表示法不把账单赖掉。赖掉的形状很具体：新柜子里没有版本字段，于是梯子没有地方挂。

大厅会很快，家会很稳。你会失去同一口令、同一套模组、同一只手从工地走进战场。分家是两个游戏共用一个启动器。启动器很方便。方便不是四格共享的内核。

## 这一章留下什么

- **爱好者**：你家和大厅可以不再挤在同一份硬盘脾气里，但门仍应是两格。一局结束可以丢岛，不能把丢岛做成默认——默认仍是：墙比你的命长。
- **开发者**：能抄走的是「同一度量、多种实例寿命」：永续实例走稀疏调色板和流式 I/O，对局实例走可丢生命周期；状态可数，组件在栈和账户上，不在每一格空气里。能一起抄走的还有那张对照表：旧档是职责，未知状态比假空气诚实。抄不走的是二十年 Anvil / LevelDB 的兼容梯子，以及大厅已经用进程联邦补上的那一层。你不得从本章带走八叉树或某门语言。你若用两套物理服务两种产品，口令会先死。口令一死，四格产品只剩启动器还在一起。
