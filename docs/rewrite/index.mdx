前三卷主要在理解 Minecraft。到了这一卷，问题换了。

假如我们已经知道 Minecraft 的许多伟大之处并不等于“1 米方块 + Java + 红石 + 20 TPS”，那今天重新做一个沙盒世界时，究竟应该继承什么？又有哪些东西完全可以换掉？

这就是 **Reinvention** 和 Rewrite 的区别。Rewrite 容易把人带到语言、架构和兼容层；Reinvention 更关心的是：**当新的技术能力出现时，原来成立的设计关系还能不能成立？**

## 第一部 · 先弄清我们想继承什么

先区分四件事：兼容 Minecraft、复刻 Minecraft、继承 Minecraft 的思想、重新发明沙盒。然后把所谓“不变量”降级成待验证原则，再把具体表达与历史偶然分开。

入口是[《我们究竟想继承什么》](/rewrite/what-to-rewrite)。

## 第二部 · 把旧原则放进新世界

这一部开始真正做压力测试：

- 方块换成 Smooth Voxel，会得到什么，又失去什么？
- 世界拥有真实刚体、车辆、机械与破坏后，可预测性怎么办？
- Mod、脚本和运行时 UGC 应该怎样共存？
- Avatar、VR 与 Flatscreen 共处时，“同一个世界”的尺度和交互怎么定义？
- 更高的画面与角色表现力，会不会把创作门槛一起抬高？

这里不追求唯一架构，而是反复问一句：**这个新能力增加了玩家什么可能，又破坏了什么旧关系？**

## 第三部 · 新的变量与最后的反问

AI NPC 是一个很好的例子：接入大模型并不自动让世界更有生命。真正要看的是它有没有创造新的关系、行动与意外。

经过这些压力测试后，才有资格回头讨论下一代沙盒值得稳定哪些语义边界，以及全书最初提出的问题该怎样回答。
