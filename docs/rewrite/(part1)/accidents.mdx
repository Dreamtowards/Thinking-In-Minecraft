> **本章命题**：语言运行时、全局恰好二十刻、两条产品线并存、某几个具体怪癖，都不是骨头。抛弃它们的前提，是上一章的七条不变量仍能活。保不住，你就不是在抛偶然，而是在拆规则。偶然可以很贵；再贵也进兼容层，不进内核。

## 问题

有人把卡写成「因为 Java」，于是重写的第一天就要换语言。有人把万人服写成「因为 20 TPS」，于是第一天就要拆掉主循环。有人把灯不亮写成「因为有两个 Minecraft」，于是第一天就要合并产品线。三句都指向真实的痛。三句都还没问：痛的下面，哪一块是规则，哪一块只是 2009 年到今天的走法。

要回答：哪些不是本质？可被证伪的说法是：现在仓库里难养的东西都是本质，抛掉就会不像；或者反过来，凡是让你疼的都是偶然，清掉就会更像。只要还存在换掉 Java 却连带丢掉整条模组河、只要还存在拆掉全局刻却让飞行器无法复述、只要还存在合并双端却拿不出共同测试集，这个说法就不成立。

上一章把骨头钉成七条（[《必须保留的设计不变量》](/rewrite/invariants)）；卷三已经把语言标成偶然候选、并禁止那一章提前判毕业（[《Java 版运行时》](/impl/java-runtime)）。判毕业是本章的事。判法不是一句「可以扔」，而是回答：扔下去之后，不变量从哪条路继续活。那条路通常叫兼容层或仿真层。层可以很厚，厚不是把偶然偷渡回内核的许可。

不得从本章读出开工用的语言选择。抛弃 Java 不等于指定 C++；Bedrock 已经指定过一次，指定完，因果分了叉。

## 语言运行时

Java 是 2009 年的正确答案：一份字节码跑遍多家操作系统，一个人就能迭代，后来字节码还能被切开，模组河才有了河床。正确会过期，过期的是「必须用这门语言」；不过期的是不变量第 6 条：扩展面必须真能加动词。切开字节是一种实现，稳定 API、脚本加原生的双层、经过认证的沙盒，是别的实现。实现可以换，席位不能换。

抛弃语言运行时，要保住的是：

- 第二作者仍能在系统层立法，而不只是换皮、改掉落表；
- 数据层仍能跟着世界走；
- 旧切口河若要继续活，兼容层必须把 class 文件和 Mixin 认成客居者。不肯养这层，你走的就是继承路，而继承要写在封面上（[《我们到底在重写什么》](/rewrite/what-to-rewrite)）。

Bedrock 用 C++ 抛弃过一次 Java。它保住了格子、大部分动词和一份权威；没保住同一条模组河，也没保住同一台墙上的虚拟机。这不是「C++ 失败」，这是抛弃运行时的同时，把第 6 条和第 4 条的形状一起换掉了，又用品牌假装没换（[《Bedrock 作为另一次实现》](/impl/bedrock)）。考试的判词是：语言可抛；抛完若只剩下审核友好的货架，你抛掉的就不只是语言。

虚拟机税——垃圾回收、即时编译、启动时间——是这门语言的账单，不是格子的账单。账单可以换；换账单时，别把「启动更快」写成「所以更本质」。更快是性能曲线上的一次移动，本质在能不能指、能不能改、能不能再开发。

<Constraint name="运行时可抛席位不可抛" verdict="待定" chain="换语言 → 必须另写系统层扩展面 → 旧切口进兼容层或宣布继承">
抄走「不必用 Java」，丢掉「必须有人能加新动词」，你会得到一个原生客户端和一张空着的第二作者席。客户端可以很光，光不是完整产品；完整产品含再开发。再开发的形状允许换，再开发的缺席不能用性能来辩。
</Constraint>

## 全局 tick 与兴趣管理

不变量要的只是共享真实：有一份结算，熔炉、活塞、白天都认它；客户端可以先演，不能另结一份账（机制见[《游戏循环与刻》](/impl/tick)）。「全世界所有实体抢同一条五十毫秒」，是把共享真实落成规模的一种具体写法。这种写法在十人生存里很诚实；到了万人网络，诚实的代价是所有人的炉子一起慢（[《服务端与规模》](/impl/servers)）。

所以 **20 这个整数**可以抛。抛的不是「不要刻」，抛的是「全世界必须同一条刻」。兴趣管理、分片、区域循环，是已经发生的局部抛弃：Folia 把证词写进了加载器——假设自己在主线程上的插件，若不显式声明兼容，加载时就被直接拒绝。拒绝，说明这个偶然已经焊进了插件 API；焊进 API 的偶然，抛弃时要付兼容税——旧插件成批作废。税可以付。付完，不变量第 4 条必须仍能复述：红石玩家还要能指着某一格说清，这一刻谁先说话。说不清，飞行器不是变快了，是语言散了；语言散了，可误用系统就只剩脚本，脚本是另一条河。

抛弃全局 20 的活法：

- 内核承认「兴趣」是调度单位：单人档的兴趣可以是整份世界，万人服的兴趣可以是许多个圈。
- 红石与流体若需要比实体更严的因果，就给它们专用的、可解释的刻内顺序——沿用卷三「班次」的说法：同一刻里谁先谁后必须固定、可查、能教，不能黑盒到只有引擎作者懂。
- 兼容层可以假装世界仍是全局 20 刻，给旧机器一条仿真刻。仿真会慢，慢是读旧程序的价格；价格记进兼容层，不写进「新内核必须永远 20」。

无论怎么拆，共享真实这条底线不动：任何一个兴趣区域内部，仍要有一份所有认刻系统共同承认的结算；变的只是这份结算不必覆盖全世界。

一天仍可以是两万四千刻。这个数作为修辞能教——教的是节奏，不是主线程的拓扑。拓扑不是骨头。

<Callout type="warning" title="抛刻不是抛因果">
TPS 掉了，玩家失去的是结算，不是画面。重写若用更高的帧率掩盖更乱的刻内顺序，你会得到好看的演示和没法写进教科书的红石。演示通不过不变量第 4 条。
</Callout>

## Java / Bedrock 双端

双端是产品史：一条产品线要进模组河和 PC，另一条要进客厅、进商店、进主机认证（两边的史实与动机见[《两条产品线：Java 与 Bedrock》](/history/java-bedrock)）。这段历史完全能理解，但理解不等于「Minecraft 的本质就是两个引擎」。本质若真的需要两个引擎，总命题就得写成两句；它没有，一句已经够难。

抛弃双端，不是命令官方明天合并——合并眼下没有共同测试集。可抛弃的是「必须永远维持两份因果」这条隐含的设计要求。继承之路上，你可以只做一份内核；兼容之路上，你可以在一份内核外面挂两套仿真：一套认 Java 的词，一套认 Bedrock 的词（另一次实现的细节见[《Bedrock 作为另一次实现》](/impl/bedrock)）。挂仿真，等于承认口音贵；再贵，也还是口音，不是骨头。

这样抛弃之后，不变量的活法是明确的：第 4 条由两套仿真各自保住——Java 墙上的飞行器在 Java 仿真里继续飞，Bedrock 的两段红石刻在 Bedrock 仿真里继续走；第 5 条由存档转换梯子保住，转换器是兼容层的正式部件，不是可选项（[《兼容性策略》](/rewrite/compat)专写这件事）；第 6 条要求新内核的扩展面同时容得下两种形状，而不是只认一边。少任何一条，合并就只是用一边的口音吃掉另一边。

不得从「双端可抛」读出「Bedrock 是错误」或「Java 是错误」。两边都是完整到某一格、残缺到另一格的产品：Java 进不了客厅的房间，Bedrock 切不开自己的程序。残缺是产品选择，选择可以改；改的时候不要宣布「我们终于做出了真正的那一个」。真正的那一个是七条规则，不是任何一条产品线的仓库。

账号、Marketplace、EULA，是双端之外更外一圈的偶然。它们塑造「能做什么」，但不是格子。格子不认识收银台；收银台只关心格子上的东西能不能被审核——这种反向约束卷三写过，它属于产品伦理的讨论范围。本章只判一句：双端分裂不是骨头。骨头是扩展面还在不在；在的形状，允许只剩一条河。

## 特例与未定义行为如何安置

特例方块和怪癖，是最容易被错判的一层。它们看起来像灵魂，其实常常只是口音长在规则上。

**安置原则。** 内核留下的是可误用性：建造度量上的离散因果，稳定、可观察，官方不必教完。某一条具体的指令——准连接、某一端的更新顺序、红石火把的过载熄灭、船的某一次碰撞——进仿真层或兼容层（成因见[《红石的实现》](/impl/redstone)对准连接与 BUD 的拆解）。新内核可以没有准连接，只要它仍允许墙上长出新词，并且每次修词都承认自己在立法。若新内核又干净、又不许长新词，不变量第 4 条死了；若新内核把 Java 的旧词焊死、不许仿真之外的因果存在，继承之路死了。

**仿真层。** 给旧机器一条「按某一版 Java 红石说话」的运行模式。模式可以慢、可以做成可选，但必须可复述：可复述，Wiki 才能继续当它的说明书。若这一层的规格只存在于已经停更的旧代码里，谁也验收不了它，兼容就是一张空头支票。

**新语义。** 观察者、合成器那种加法：把民间需求收编成方块，但不注销旧词。旧词走仿真，新词走内核。这两条路 Java 在 1.11 和 1.16 已经彩排过：1.11 收编侦测需求给出观察者，1.16 把粉的连线对齐、又加回圆点当减压阀。彩排证明偶然能挪；挪是搬走，不是擦掉。

**特例物理。** 床在下界爆炸、水在下界蒸发、船的碰撞、一格能不能同时含水——逐条问同一个问题：它增加的是可误用的动词，还是一份必须背下来的菜单？增加动词的，可以留在内核附近；必须背下来的，进数据或进仿真。停手原则卷二已经写全；本章只要安置权：特例不是自动的不变量，自动升格会让内核变成方块图鉴。图鉴不是规则。

Java 与 Bedrock 在这一层最不能合写。「准连接」这个词删掉「Java」就不成立。所以抛弃的句子必须带护照：抛的是「某一边的词必须进内核」，不是「两边的红石本来就是同一门语言」。同一门语言从来没有存在过；没有存在过，所以双端不是本质，也所以兼容层不能只做一份。

<Impl title="兼容层不是内核的垃圾桶">
把所有不想养的东西都丢进「仿真」，会得到一层无限厚的假官方。层要有边界：只救测试集里已经稳定、可复述、被当材料的行为。某个人存档里的奇迹不成 API；不成 API 的东西，不配进层，也不配进内核。
</Impl>

<Alternative title="若把怪癖全部焊进内核">
飞行器永不会停，你得到一份考古级的兼容。你失去的是继承：任何新调度、任何新表示，都得先过 2012 年某次通知顺序的海关。海关会把四格产品全部停在同一夜。停在同一夜不是尊重玩家时间，是让时间没法继续被住下去。
</Alternative>

<Memoir title="修了，所以革命">
快照说明写着「修复」。墙上那一层机器停了。聊天里没有人说谢谢；他们说，语言被删了。下一章若开始画新调度，请把这句话放进验收单：你抛的若是偶然，旧教科书应当能翻译成新说明；翻译不过去，说明你抛到的是骨头。
</Memoir>

## 这一章留下什么

- **爱好者**：Java、整二十刻、两个版本、某一次「红石 bug」，都可以不是命。命是：格子还能指，世界还能改，目标还空着，墙上还能长出语言，存档还能打开，别人还能接着改。命还在，换引擎叫继承；命还在、又要让旧飞行器继续飞，才需要一层翻译。翻译可以很烦，烦不构成「所以什么都不能动」。
- **开发者**：能抄走的是四条「可抛」——运行时、全局 20、双端必然、具体怪癖与特例清单——以及与之对称的纪律：每一抛都要写清七条不变量的活法；活法通常是兼容层或仿真层，不是「删掉就干净了」。抄不走的是测试集本身，以及 Bedrock 已经交过的卷：换语言不等于换本质，本质也不会自动跟过来。你不得从本章带走任何指定语言。现在只配做一件事：把偶然和骨头分成两叠。分完，本卷后面才许画世界表示和调度。画的时候若把准连接写进内核当骄傲，或把扩展面送进商城当进步，请回到上一章重考。
