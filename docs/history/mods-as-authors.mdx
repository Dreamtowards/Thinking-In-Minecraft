> **本章命题**：模组不是正作做完之后的周边。它与客户端同步生长，是因为正作卖出的是带结构空洞的规则，又把程序本身留在可改写的状态。Forge 与 Bukkit 把再开发收成第二条作者席；产品边界从此不再等于 Mojang 发布的那个程序。

## 问题

2011 年 11 月，拉斯维加斯把 Minecraft 1.0 做成一场发布会。对外的句子是：游戏完成了。同一年的时间表却对不上这份语法。7 月，SpaceToad、Eloraam 等人已经在提交后来被称为 Minecraft Forge 的代码；更早一年的 12 月，Dinnerbone 在 Bukkit 仓库里写下第一行。正式版典礼举行时，第二条生产线已经开工，而且不是刚开工。

玩家侧的经验更直白。买过正版的人，启动器里跑着的经常不是盒子上的那个客户端。2012、2013 年，许多人实际点开的是 Technic 或 Feed The Beast，或者一个已经插满插件的多人服。商标还是 Minecraft，磁盘里的游戏已经换了作者。有人坚持「我玩原版」，却换过材质、用过让画面能看的补丁、进过改了规则的服务器。

上一章把工作室化写成设计权从个人直觉交给组织。本章把镜头转开：组织并没有独占作者席。模组几乎与正作成长同步，并且改写了产品边界——这句话如果要成立，必须同时解释两件事。第一，为什么不等游戏「做完」再出现模组。第二，模组做的不是皮肤市场或附加下载，而是把「Minecraft 是什么」从官方版本说明里抢出来。

产品边界被改写，指的不是论坛上多了几份 zip。它指的是：一个没玩过模组的外人，已经无法从截图、视频和口碑里还原「官方发布了什么」。管道、量产矿机、任务 NPC、插件服大厅，都被叫做 Minecraft。商标覆盖的对象大于版本说明。这是卷一要证明的媒介形成史里，最早、也最容易被写成附录的一块。它不是附录。没有这一块，后面的服务器、影像和灰色经济都会变成「社区很热情」的空话。

## 「原版 Minecraft」从来不是完整产品

完整产品有两种意思。一种是货架上的 SKU：一个 jar、一份版本号、一次买断。另一种是人们实际拿来玩、拿来录、拿来开服的那套规则。Minecraft 很早就让这两种意思分开。货架上的程序是真的；它从来不够覆盖第二种意思。

分开的原因不在社区热情，而在正作自己的结构。

Cave Game 卸掉了比赛、过重模拟和作者关卡，留下可破坏空间。空规则是产品，不是工期。空着的东西总会被填：官方可以填饥饿、村庄、龙，玩家也可以填工厂、法术、任务、领地、小游戏。Alpha 已经训练过一圈人——说话可能有用，更新是公开施工。那圈人在 1.0 之后并没有解散。他们只是发现，等下一周的官方补丁太慢，而 Java 客户端的 jar 本周就能改。

同步发生在这里，不是发生在「游戏火了以后大家开始做 DLC」。火是结果。同步的机制有三层，叠在同一段 2010–2012 年里。文化层：共同作者已经习惯把自己当成施工队员，模组只是把建议从论坛搬进字节码。设计层：正作卖出的规则带整块结构空洞，空洞本身就是可填写的接口。技术层：Java 发布、字节码可拆、社区迅速做出映射和重打包流程，把混淆过的程序变回能写的对象。三层缺一层，模组都会晚很多才出现，或者根本长不成作者席——只会剩下换皮和关卡编辑器。工程细节留给[模组与插件架构](../impl/mod-architecture)；本章只取产品后果：正作在卖出的那一刻，就把自己写成了一份可被他人继续编写的文档。没有官方 API，并不等于没有接口。没有官方接口时，注入就是接口。每个大版本都会把这种接口砸一遍，那是后来的维护税。2010 到 2013 年，税还没高到让第二条作者席无法成立。

最早进入日常的，往往还不是工业树，是工具型补丁。TooManyItems 一类的物品面板、Single Player Commands 一类的指令，让单人档提前获得创造模式和运营者才会有的手。许多人以为「这就是游戏」，后来才知道那是别人塞进 jar 的。OptiFine 更接近隐形基础设施：画面能看、能跑、能远望，被大量自认为在玩原版的人装进客户端。工具型模组证明了一件不好意思写进版本说明的事——官方客户端作为游玩工具并不自足。内容型模组只是把同一判断推到系统和世界上去。

「原版」作为一个干净范畴，是后来才被发明出来的对立面。有人要把它从整合包里抢救出来，有人用它给速通划界，有人用它骂某一版更新「不像以前」。这些用法都依赖一个前提：存在一份未被第二作者碰过的核心。前提可以成立，作为审美，作为规则。它不能倒过来证明 2011 年的产品已经完整。完整与否看的是当时人们拿什么当 Minecraft 来玩、来教、来卖服务器名额。启动器、整合包、插件服列表和影像，指向的都是一个大于 jar 的对象。

所以「原版不完整」不是骂官方偷懒。它是一个更硬的判断：官方发布的是引擎加一份偏薄的规则集，完整玩法从一开始就被分配给了多个作者。材质决定世界长什么样，插件决定这台服务器上什么合法，模组决定世界上有没有管道、研究台和另一套成长。把这三样全部剥掉，剩下的确实还能玩，而且很多人爱玩。爱玩不等于那就是产品的全部。若 2011 到 2014 年绝大多数人接触到的 Minecraft 都是未打补丁、未换包、未进插件服的原版 jar，这一节就应当改写。

Pocket Edition 在 2011 年已经出现。它从一开始就没有这条 jar 补丁的河。手机上的 Minecraft 更接近货架 SKU：能玩，难改程序。Java 版的第二作者席因此不是「Minecraft 的普遍属性」，是这一条产品线的历史。后来 Bedrock 用附加包和市场重新发明了一种被官方管理的扩展，那是另一张合同，不能回写到 Forge 头上。两个 Minecraft 在模组这件事上，从来不是同一个产品。

## 三条河：ModLoader / Forge、Bukkit、资源包

再开发不是一种行为，是三条几乎同时涨水的河。混在一起，会把插件当成模组的小号，把材质包当成模组的皮。三条河改的对象不同，玩家要不要换客户端不同，官方后来采取的态度也不同。

**第一条河改程序。** 早期做法是直接改 jar 里的 class 文件。两个模组改同一处，后装的覆盖先装的，冲突是物理事件。Risugami 的 ModLoader 把「多个模组如何共用一个客户端」收成加载器。2011 年夏天出现的 Forge 最初不是又一个加载器，而是一层叠在 ModLoader 上的共享补丁：SpaceToad 的 BuildCraft 和 Eloraam 的 RedPower 都要改同一批基类，与其各改各的，不如把公共切口抽出来。LexManos、cpw 等人随后把这条路走成 Forge Mod Loader，加载器与 API 收成一套。

这条河的作者席是：可以往世界上加新的方块、物品、维度、能源和机器，也可以改掉原版的合成与生成。玩家必须换一套被注入过的客户端，以及通常配套的服务端。它看起来像下载站，本质是一条没有官方许可的并行工具链。模组作者不是在货架上上架皮肤，是在编译另一种 Minecraft。Forge 若只是插件市场，它不会关心基类补丁如何被多个模组共享，也不会在每个大版本之后把半个生态拖去重写。市场卖的是商品槽位；Forge 卖的是编译权——尽管它并不收费。

**第二条河改服务器上的法律。** 2010 年，hey0 的 hMod 已经在给服务端加命令和权限。年底 hMod 停滞后，Dinnerbone、Grum、EvilSeph、Tahg 等人在 12 月 21 日另起 Bukkit。Bukkit 是 API，CraftBukkit 是把原版服务端接进这套 API 的实现。插件跑在服务端，原版客户端可以照进。它通常不加新方块——新方块会逼所有人换客户端，第二条河就会塌进第一条。它加的是领地、经济、聊天、登录、小游戏、反破坏、传送点：一台服务器上的宪法和玩法循环。

WorldEdit、WorldGuard 这类插件把立法写得很具体。前者让管理员以建筑师的权限改地形，不必每人装一套 Forge；后者让「这块地归谁、能不能拆」成为可执行的句子，而不再只是口头约定。进服的人可以继续用原版客户端。于是出现一种极其重要的不对称：玩家以为自己在玩官方游戏，实际服从的是服主写的法。第一河改写时，你看得见——物品栏里多了机器。第二河改写时，你不一定看得见，直到你拆了别人的墙，或者发现这个世界其实是大厅加传送。

这一席必须单独写。许多人把 Bukkit 理解成「服务端模组」。名字差一个字，作者权差一层。模组改的是每个人磁盘里的游戏是否还是原版；插件改的是你进了这扇门之后，这套规则对在场的人是否有效。买的是客户端，玩的经常是服务器——下一章会把服务器写成新游戏。本章先钉死：服务器能成为新游戏，是因为 Bukkit 这一席先把立法权从 jar 里拆了出来。没有稳定的服务端 API 时，服主只能改二进制；有了 Bukkit，服主开始写法律，不必每个都去补丁官方服务端。Spout 曾经试图给插件河接上客户端钩子，让第二条河也能加新方块。它没有取代 Forge，也没有取代 Bukkit。失败本身有用：想把法律席和物理席并成一张椅子的人，最后还是坐回了两张。

2012 年 2 月，Mojang 宣布招入 Bukkit 的四名核心开发者，公开目标是做官方 API，先服务端、再考虑客户端。Jeb 当时解释过为什么选 Bukkit 而不是 Forge 或 Spout：他们要的不只是模组，是心里装着服主的那套东西。官方承认了第二条河的存在，并且试图把它内化。那份官方 API 没有作为公共产品交出来。被招进去的人后来成为正作的重要作者——命令、方块状态、无数版本里的技术决定——但 Java 版没有因此得到一个与 Bukkit 同级的、官方承诺稳定的插件面。真空继续由社区填。这条河的脆弱会在 2014 年变成危机；那是基础设施的故事，不是本章的清单。

**第三条河改外观。** 材质包几乎从 Alpha 就存在，2013 年 1.6 收成资源包，把纹理、模型、声音、语言文件放进官方支持的目录。它是三条河里唯一被正作当成功能来维护的。玩家换包，不必反编译，也不必请求服主。它能把世界换成写实、卡通、16× 或 64×，不能加一套工业，不能立法禁止拆家。官方愿意承认这一席，正因为他改不了规则。规则仍归 jar，法律仍归插件，系统仍归模组。被承认的扩展面，是那个最不像作者席的扩展面：它改观看，不改因果。

三条河还需要一条街。Minecraft Forum、后来的 Curse 与 Bukkit 的插件中心，把 zip 和作者名变成可发现的公共物。没有发行层，第二作者席只存在于熟人之间的压缩包。有了发行层，它开始像产业——仍然无偿，但已经能被陌生人安装。启动器随后把安装从「打开 jar」变成「选一个包」。Technic、FTB 做的不是美化下载，是把第一河的编译权包装成普通玩家按得下去的按钮。

| 河 | 作者改什么 | 进门要不要换客户端 | 官方后来怎么对待 |
|---|---|---|---|
| ModLoader / Forge | 程序：方块、物品、维度、系统 | 要 | 默许，不提供稳定 API |
| Bukkit | 服务端法律与循环，尽量兼容原版客户端 | 通常不要 | 招人，承诺官方 API，未作为产品交付 |
| 资源包 | 外观与音频 | 要装包，不必改程序 | 唯一被写成功能的扩展面 |

三条河并排，产品边界就被拉开了。同一个商标下面，至少有三种「做 Minecraft」的方式：改物理、改法律、改皮肤。后来客户端加载器还会再分叉，Forge 与 Fabric 代表不同的加载哲学，那是[模组与插件架构](../impl/mod-architecture)的事。对卷一来说，分叉是后话。2011 到 2014 年已经足够得出结论：第二作者不是一种人，是三种权限。

Bedrock 侧没有这三条河的对应物。后来的行为包、资源包和脚本 API 更接近被沙箱化的第三河，外加一点被允许的数据层；Marketplace 再把扩展收成商品。Java 的第一、第二条河长期无法被那样收编。分述不是口味，是合同不同。

## 工业、魔法、RPG 在补哪些结构空洞

模组清单帮不了这一节。一年一个神作，读完仍不知道它们在干什么。要看的是正作留下的洞，以及洞被填上之后，产品变成了什么。

**工业补的是生产。** 原版有熔炉、漏斗、活塞，有一点能被误用的机械。它没有作为系统存在的工厂：没有被设计出来的能源层级，没有矿物处理链，没有把「从山上搬到箱子里」做成物流问题。挖、烧、合成，停在作坊尺度。BuildCraft 一类的模组把管子、引擎、泵和自动化做成第一等玩法；IndustrialCraft 一类的模组把电压、机器和量产做成成长。玩家在正作里是工匠，在这些模组里是厂长。空洞不是「方块不够多」，是规则集拒绝把生产当成中轴。拒绝有好处：原版不会变成模拟经营。空洞也因此稳定存在，社区用整棵科技树把它填上。填完之后，一群人的 Minecraft 不再以钻石和末地为后期，而以线缆、矿井和物流吞吐为后期。

**魔法补的是另一套因果。** 原版的附魔是随机、消耗和一点运气，不是宇宙观。没有研究，没有副作用，没有「懂这套规则的人住在另一种物理里」。魔法模组通常不满足于多几种武器。它们加的是发现过程：扫描、研究、仪式、与世界交换代价。这和红石不同。红石把失败的电力隐喻留给玩家去误用；魔法模组常常直接写出一套可学习的伪物理，让成长发生在知识上，而不只发生在镐的材料上。空洞是：正作把深度放在空间和物品上，几乎不放在认知体系上。谁需要一套内在的神话和进度，谁就会离开附魔台。工业模组把世界收成车间，魔法模组把世界收成可以对话的对象——矿石不只是材料，也可能是媒介。两种填法都在回答同一句原版不肯回答的话：后期凭什么继续变强。原版的答案是更好的镐和更大的家；第二作者的答案可以是电压，也可以是知识。

**RPG 补的是角色与他人。** 正作几乎没有职业、任务、对话型 NPC、作为内容的社会。村民后来补了一点交易，补的是经济接口，不是戏剧。经验条主要服务于附魔和修理。人在原版里变强，是因为地形被改过、物品更好、基础设施更密，不是因为角色卡片涨了级。于是另一批模组去加职业、任务、副本、对战、收集型生物。冒险地图和自定义 NPC 走的是同一空洞的另一面：用命令和实体，在原版物理上寄生出一局别人写好的故事。空洞是目标外包的代价。游戏不给你「你是谁、你该去哪」；有人就喜欢被给定这些。RPG 模组不是原版失败的证据，是原版把角色层留白之后，必然出现的另一种游戏。它也提醒一条容易被工业叙事盖住的事实：第二作者席不只属于写机器的人。写任务、写职业、写一张能玩一晚的地图，同样是在决定 Minecraft 还是不是「那个没有目标的沙盒」。目标一旦被写回去，起源处的减法就只对原版生存有效。

对照要写清楚。往游戏里加一座新森林、一种新矿、一套新装饰，改的是地图厚度，不一定改循环。系统空洞被填上，循环才会换。Twilight Forest 一类的维度模组可以极受欢迎，玩家仍可能把它理解成「原版探索的加长」。IndustrialCraft 不能被那样理解：电压和量产会重新定义什么叫后期。产品边界的改写，主要发生在后一种。前一种是内容；后一种是第二作者开始写游戏。

三类空洞有一个共同点：它们要的不是更多装饰性方块，是另一套循环。正作若自己把三套都做全，Cave Game 卸掉的目标会从三扇门回来。工作室在 Beta 1.8 已经试过往空循环里加饥饿和结构，社区为此分裂过一次。官方的答案是让生存更像冒险；社区的答案是让生存长出工厂、魔法和角色。两套答案并行了很久。工业、魔法、RPG 比饥饿更重，官方更没有理由整棵搬进来。社区搬进来了。搬进来的结果，是 Minecraft 这个词开始同时指作坊、工厂、法师塔和任务大厅。

漏斗和活塞没有堵住工业的洞，反而把洞的形状量清楚了。1.5 的红石更新给了原版一条很短的物流：物品可以移动，仍然没有能源层级，没有处理链，没有厂长视角。它证明官方愿意把自动化做成物理，不愿意把生产做成进度。洞的边缘因此更硬。硬边缘最适合第二作者施工——施工图纸已经画在正作不肯越过的那条线上。

整合包把这件事收成了可分发的产品。Technic 的 Tekkit、Feed The Beast 的包，不是「多装几个模组」的便利。它们是策展：哪些系统可以共存，科技树怎么咬，默认规则是什么，崩溃了谁来背。第二作者在这里升级为发行方。玩家购买 Mojang 的客户端，启动的是别人编好的游戏。产品边界的改写到这一步已经无法用「社区补充内容」来轻描淡写。补充内容不会换启动器；换启动器说明人们认为自己在玩的那个 Minecraft，作者栏里有一串官方名单以外的名字。影像更把这个边界对外固定：看的人学到的「Minecraft」，经常是整合包里的管道和插件服里的大厅。正作还在卖规则；第二作者已经在教下一批人规则是什么。

收编原则——正作该吸收系统还是内容、整合包作为设计方法——在[模组作为设计方法](../design/mods-as-method)里写。本章的史实只负责到这一句：空洞是设计选择留下的，填空洞的人成为了第二作者，策展的人把第二作者席做成了货架上能看到的另一种 SKU。

## 选择性收编：活塞能进，大型工业不能

官方不是对模组视而不见。它看见了，并且挑着收。

活塞是最干净的样品。Hippoplatimus 先做成模组，Jeb 把它折进 Beta 1.7，作者进了致谢名单里的 Additional Programming。收进来的是一个方块、一个动词：推。推下去长出的门、电梯、飞行器和各种怪癖，仍然靠玩家误用，不靠官方发布「活塞玩法包」。致谢名单后来还会写下马的作者、区域文件的作者。官方承认劳动的方式，是把人写进字幕，把物写进原版。

命令方块走的是另一条路。2012 年 1.4 加入时，它不是某个著名模组的移植，是把已经存在的社区实践——地图作者和服主用命令改规则——做成方块。谁拿得到这个方块，谁就在原版里得到一截关卡设计师的权限。它收编的不是工业树，是运营者。数据包更晚，1.13 之后才成为正作承认的数据驱动扩展。进度、战利品、函数、一部分世界生成，可以从 jar 外改。它把第三河的「官方允许」往规则层推进了一寸，仍停在新动词之前：可以改表，很难加出与原版镐同级的新动作。活塞、命令方块、数据包排成一条时间线，原则已经能被看见——虽然原则本身要到卷二才展开：能进正作的，多半是单一动词、单一生物、单一权限或一张可热更新的数据表；整棵工业、整套魔法研究、整座 RPG 角色系统不能进。

马的取舍同样清楚。1.6 以 DrZhark 的 Mo' Creatures 为基线，开发者进了致谢。官方要的是一种可骑的生物、一种新的移动尺度，不是那座动物园。模组可以靠物种数量成为内容包；正作收编时把数量卸掉，只留一个能进原版生态的动词。McRegion 更不像玩法：Scaevolus 的区域文件方案被收进存储层，改的是世界怎么活过下一次启动。谁解决了正作自己的基础设施痛，谁的劳动更容易变成默认格式。内容要长得像原版工具才进得去；基础设施可以不长得像工具，只要它让世界比引擎活得更久。

不能进，不是因为这些模组不够流行。IndustrialCraft、BuildCraft 在整合包年代的安装量，足够证明需求。不能进，是因为把它们搬进原版等于换游戏。原版一旦有电压和矿机，挖、放、看的循环会被生产进度重新目标化，空规则会变成科技树。工作室可以加活塞，因为活塞扩大了可误用物理。工作室不能加大型工业，因为大型工业会把误用收成正确用法。历史给出的过滤标准很简单：看起来仍像原版里的一件工具，就能谈收编；看起来像另一个游戏的主循环，就留在第二作者席。

漏斗是这条标准的边界样品。它进了正作，物流仍然停在作坊。它足够像工具，不够成为工厂。红石更新因此不能被读成「官方其实做了工业」——做了物理，没做生产树。谁把漏斗理解成 BuildCraft 的官方版，谁就会对后来所有没被收编的机器感到困惑。困惑来自把工具和循环当成了同一个东西。

人比接口容易收编。Bukkit 团队进了 Mojang，Forge 没有变成官方 API。客户端模组河始终在法外：默许存在，版本一变就断裂，责任在模组作者。服务端河得到过一次招安承诺，没有得到交付物。那次承诺若兑现，收编的将是席位本身：插件不再寄生于社区维护的 CraftBukkit，而寄生于官方服务端。未兑现意味着官方愿意把第二作者变成同事，不愿意把第二作者的工作台变成产品。第三条河得到目录和格式，恰恰因为它最不像工作台。选择性收编因此不只是「哪些方块进游戏」，也是「哪一种作者席可以被公司内部化」。内部化了人，不等于内部化了那条河。

若有一天正作把 Mekanism 尺度的工厂或 Thaumcraft 尺度的研究做成默认生存，这一节的过滤标准就失效了。那不是更新说明变长，是产品换成了另一种。到目前为止，失效没有发生。发生的是另一面：原版变厚了，第二作者席没有因此消失。洞被官方填掉一些，社区继续在新的边缘挖。

## 署名与治理：官方该不该管模组

第二作者席一旦成立，就会冒出治理问题：官方该不该管模组？管署名、管兼容、管分成、管内容，都叫管。Minecraft 实际做的是一种很窄的组合——管得很少，承认得很少，抽成几乎没有——而完整产品靠这种组合才长成后来的样子。

署名。活塞和马证明官方可以点名。点名发生在致谢名单，发生在个别合作，不发生在模组生态的日常里。绝大多数模组没有字幕、没有分成、没有版本兼容的官方责任。劳动是真的：写代码、跟版本、做材质、看崩溃日志、在论坛上被骂。报酬长期是捐赠、流量、名誉，以及「我改了这个游戏」本身。这不是社区美德故事，是产业事实。正作的销量、影像、服务器人口，有一部分建立在这批无偿更新上。钱怎么转、灰区怎么形成，是[模组、服务器与灰色经济](./grey-economy)的题目。本章只需写明：第二作者席被默认为不必出现在价目表上。

无偿能维持，是因为作者席本身被当成报酬。改 Minecraft 在那几年里有一种难得的可见性：你的机器会出现在别人的世界里，你的插件会决定一个服的法律，你的包会被启动器放到按钮上。可见性不是工资。它足以让一批人把业余时间写成基础设施，也足以让后来的人在抽成问题上爆发——一旦可见性还在、钱开始从旁边流过，无偿就会从「大家一起盖」变成「谁在用我的劳动赚钱」。2011 到 2014 年，这个问题已经存在，还没有被 Marketplace 那样的官方货架写死。治理缺席，经济也缺席；两条缺席互相撑着。

治理的另一面是接口。管模组最强的手段不是审核下载站，是提供一份稳定 API，并在大版本之间承担兼容。Mojang 2012 年公开说过要做这件事，至少针对服务端。Java 版没有把这件事做成产品。结果是双重的。好处：没有商店审核，没有抽成，没有「只许改这些函数」。三条河可以长到官方想象之外，工业和魔法不必先通过品牌安全审查。坏处：每个大版本都是模组的末日预告，映射一换，河就要重挖。官方既没有把第二作者收成第一方功能，也没有把他们收成平台上的商户。中间地带是默许的法外之地。法外之地能长出 Tekkit，也能长出断裂、分叉和后来 Marketplace 对照之下的怨气。

「该不该管」如果翻译成道德题，只会得到两句空话：不管就是放任破解，管了就是扼杀社区。历史给出的是产品选择。Java 版选择了不管接口、少量署名、不抽成。于是模组成为产品的一部分，却不是合同的一部分。定义权因此是分散的。官方控制版本号和商标；第二作者控制很大一部分截图、教程和服务器里的实际规则。外人学到的 Minecraft，经常是后一种。官方若全面接管定义权，就要么提供能加新动词的稳定接口，把第二作者收编进第一方，要么禁止改程序，把定义权收回启动器。它两头都没做。

Bedrock 后来选择了管：附加包进格式，商品进 Marketplace，扩展面停在沙箱里。管了之后，第二作者变成供货商，品牌安全好做，工业树那种改程序的作者席不再是默认。两种治理对应两种 Minecraft，不是同一政策的松紧旋钮。Java 的不管，让产品边界被社区改写；Bedrock 的管，让产品边界停在货架上。哪一种「该」，取决于你认为 Minecraft 是可再开发的规则，还是可分发的客户端。本书的总命题站在前一种。站在前一种，并不等于要求官方永远不要提供 API——稳定接口其实更像把第二作者席写进合同。Java 版真正奇怪的地方是：席位存在，合同不存在。

还有一种更隐蔽的管法：把第二作者变成第一作者。招进 Bukkit 核心成员，就是这种。它改变了正作的代码质量、命令系统和一部分技术方向，没有把插件河收成官方交付物。人进了公司，席位还在外面。治理因此显得像态度友好，结构上仍是：完整产品依赖外部作者，外部作者不享有产品承诺。

若官方从 Alpha 起就提供稳定、无抽成、能加新动词的 API，模组仍会出现，但不会以「每个版本重写一次」的形态出现，产品边界的撕扯会轻一些。若官方从一开始就禁止改 jar、只开皮肤商城，Java 版那种工业——魔法——RPG 的第二作者席很可能长不出来，Minecraft 会更接近后来的 Bedrock 加商店，卷一后面的灰色经济也会换一张图。两种反事实都没有发生。发生的是中间这条：默许、无偿、不稳定、偶尔致谢、偶尔招人、把活塞收进去而把工厂留在门外。

产品边界就是在这条中间带上被改写的。人们说「Minecraft」时，所指的对象包括：未改装的生存、Forge 整合包、Bukkit 小游戏服、换皮的视觉作品。官方版本号只能覆盖其中一块。其余块的作者不在 Mojang 的工位上，却在决定这个词还能否被继续使用。下一章把第二条河推到底：一旦立法权在服务器上，很大一部分游戏就不在客户端里了。

## 这一章留下什么

- **爱好者**：你玩过的那个 Minecraft，作者栏很可能比启动器显示的更长。原版是一种玩法，不是产品的全称。整合包和插件服不是「玩法变体」这么轻的东西，它们是正作把空洞留下来之后，别人写完的另一半。
- **开发者**：能看见的是：把规则卖空、把程序留在可改写状态、不抽成，社区会补出第二条作者席，产品边界会被他们改写。抄不走的是这份合同的年代条件——Java 可注入、官方 API 长期缺席、买断伦理不允许把模组收成内购、以及工业/魔法/RPG 那种整系统空洞恰好还能被民间填上。开一个创意工坊不等于拥有第二作者；没有空洞、没有法外工具链、还想按次抽成，货架上只会剩下皮肤。
