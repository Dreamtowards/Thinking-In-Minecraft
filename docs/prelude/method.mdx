> **本章命题**：方法先于观点。没有口径，后面的章会写成维基；没有证伪条件，判断会退化成情怀。

## 问题

读者凭什么相信后面的判断？

游戏书写有一条很滑的路：把熟悉的场面排成清单，读起来都对，合上书什么都没留下。另一条更滑：把作者的品味写成必然，用「这就是 Minecraft 精神」挡掉一切反例。两条路都不必造假，也都不构成论证。

本章把地板钉死。后文凡是听起来像观点的句子，都应该能回到这里的口径上受检验。

## 三种失败

**百科。** 方块有哪些、版本哪年加了什么、命令怎么写。这些东西 Wiki 已经写得更好。百科的失败不是事实错误，是把「有什么」当成了「为什么是这样而不是别的」。一本按物品 ID 展开的书，无法解释创造模式为什么必须寄生在生存规则上。

**攻略。** 第一晚怎么过、刷铁机怎么造、速通怎么打床。攻略假定目标给定，把系统收成步骤。Minecraft 的设计恰恰把目标外包给玩家。教步骤会把误用写成正确用法，把发明写成标准答案。后文会分析刷怪塔为什么能存在，不会教你怎么建。

**情怀。** 「那是我们的童年」「方块就是爱」。怀旧是真实现象，值得被解释，不能拿来当结论。任何一句只有在 2012 年听过 C418 的人才会点头的判断，对开发者没有用，对没赶上那一波的爱好者也没有用。情怀还有一个更隐蔽的变体：控诉。把微软、Marketplace、聊天举报写成道德剧，读起来痛快，等于放弃理解一连串各自可辩护的决定如何累积成一个奇怪的结果。

后文允许怀旧作为材料，不允许怀旧作为推理规则。

## 现象开篇

每章从玩家已经见过的场面进入，再收成机制。

「三高五宽、左边留门」先于「离散空间的信息论」。「TPS 掉了，熔炉像是慢了」先于「20 刻契约」。「修了一个红石 bug，机器全炸」先于「未定义行为成为社区 API」。

这个顺序不是为了好读。它是证伪装置。如果开篇的场面你没见过、或者你见过但完全不是那么回事，这一章的命题当场可驳，不必读完抽象句。写作者没有资格从原则推出现象之后，再让现象给原则站台。

卷二、卷三会把硬核细节往下压一截：爱好者走主路径，仍应能抓住「这意味着什么」；公式、包结构、加载器差异不挡在命题前面。

## 什么叫可被资深玩家证伪

一句判断如果无论发生什么都能自圆其说，它就不是判断。后文的命题必须带上「怎样算我错了」。

例子：

- 「死亡掉落但不摧毁世界，是克制。」若有一个版本把背包、末影箱、地皮和区块一并行刑，而社区认为这才是「真正的生存」，这句话要改。
- 「创造模式不是关卡编辑器。」若创造一旦去掉生存的方块、尺度和物理，玩家仍然觉得自己在玩 Minecraft，这句话要改。
- 「红石是可误用系统。」若官方按文档里的「正确信号」把准连接和更新顺序清干净，社区觉得游戏更诚实了、而不是被阉了，这句话要改。

证伪者必须是玩过的人，不是没碰过游戏的理论读者。Minecraft 的机制密度很高，外行很容易把「我没见过」当成「不存在」。本书面向资深爱好者与开发者，正是为了把反驳权留在对的人手里。

「可被证伪」不等于「已经用实验证实」。很多章是机制解释加历史对照，不是实验室报告。它要求的是：句子有牙，咬得动反例，而不是圆得什么都能吞。

## 两个 Minecraft

后文默认在说 **Java 版** 时会标明。Bedrock 不是同一句话的另一个皮肤。

需要分述的，至少包括：红石语义、战斗手感、世界格式、模组 / 附加包能力、Marketplace 对能做什么的反向约束、跨平台与账号体系。这些差异不是移植损耗，是产品分叉。分叉会决定设计空间——卷一第 8 章、卷三第 15 章、附录对照表从三个密度处理它。

禁止的写法：「Bedrock 就是 C++ 版 Java」「两边除了优化都一样」「手机版可以忽略」。也禁止把 Java 的模组文化直接安到 Bedrock 头上，或把 Marketplace 的商品逻辑直接安到 Forge 头上。

一条经验规则：如果你删掉句中的「Java」或「Bedrock」，句子对另一边仍然成立，才可以合写。否则拆开。

## 材料从哪来

按可信度大致这样排，不是按敬畏排：

1. **可复现的机制。** 方块更新、刻、合成、权限、死亡掉落。读者能进游戏里核对。这是地板。
2. **版本说明、官方博客、公开访谈、MineCon 讲话。** 用来还原当时的意图和约束，不用来证明意图等于结果。设计经常在意图之外生效。
3. **社区的稳定实践。** 被广泛使用、被Wiki记录、被版本升级反复踩到的红石装置、服务器插件惯例、模组加载哲学。一个人的生草机器不算，一种活了十年的惯例算。
4. **反编译、映射、实现细节。** 只作机制旁证：用来说明「它为什么会这样」，不拿来当目录，不贴映射名录，不写成源码导读。能用玩家可观察的行为说清的，就不下到这一层。

数字——销量、月活、分成、服务器人数——能给出处就给；只能给到量级，就标明是量级。不编精确数字撑场面。

## 不写什么

- 方块图鉴、合成表、附魔列表、更新日志汇编
- 红石搭建教程、生存第一晚、速通路线
- 模组安装、启动器评测、开服手册、反作弊配置
- Yarn / MCP / 混淆映射清单，大段反编译
- YouTuber 排行、服务器广告、模组「神作」榜
- 把社区创造写成附录趣闻，再把正作写成唯一正文

不是这些东西不重要。是它们已经有更好的载体。本书占用的是另一块：为什么是这样而不是别的，以及开发者到底能拿走什么、抄不走什么。

## 几个最容易混的词

其余见附录术语表。这五个必须在进正文前对齐，因为后文会把它们当普通名词用。

**区块（chunk）。** 世界在空间和 I/O 上的裁切单位，通常是 16×16 的柱体。玩家说「我卡在区块边界」和程序说「区块已卸载」，说的是同一个裁切，职责不同：一个是体验，一个是存储与模拟的账单。

**刻（tick）。** 模拟的时间步。Java 版约定每秒 20 次游戏刻。红石刻、计划刻、随机刻、客户端渲染帧不是同一个钟。后文说「时间」而不加定语时，默认指游戏刻；涉及红石时会分开写。

**数据包（datapack）。** 官方提供的数据驱动扩展：进度、战利品、函数、世界生成标签这一层。它能改内容与部分规则，不能任意加出新动词。和模组不是同义词。

**模组（mod）。** 改客户端和/或服务端程序本身的扩展，通常依赖加载器。它能加系统，也能加内容。和「资源包只换皮」不是一层。

**插件（plugin）。** 主要改服务端、对原版客户端保持兼容的扩展。Bukkit / Paper 这一河。玩家进服往往不用装它；它改的是这台服务器上的法律，不是每个人磁盘里的游戏。

模组、插件、数据包都是再开发，但作者席、崩溃域、兼容政治完全不同。混用这三个词，卷三和卷一都会写乱。

## 这一章留下什么

- **爱好者**：后面每章的「命题」都可以拿你自己的存档去砸。砸得动，就是我们错了。
- **开发者**：不要把本书的原则当成到处可抄的模板。原则附带口径——双版本、证伪条件、不可迁移条件。缺这三项，抄走的只是语气。
