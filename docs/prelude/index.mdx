> **本章命题**：这不是百科，两条读者线共用总命题、随后分叉。原语是公共地基；其余按你的问题跳。

## 这本书不是什么

不是攻略。这里不教你过第一晚，会解释饥饿和黑夜到底在「逼」什么。

不是维基。能查到的事实会用，事实本身不是章节。章节问的是：为什么是这样，而不是别的。

不是怀旧散文。2011 年的口哨声、2013 年的服务器、某个世界存档——这些可以当材料。它们不能当结论。

不是控诉。Marketplace、双版本、聊天举报、收购，都会写。写成坏人故事最容易，也最没有用。真正值得写的是：一连串各自合理的决定，如何把一套可再开发的规则，推向另一种产品形态。

如果你要配方、命令、版本对照表，请去 Wiki 和附录。正文是论证。

## 两类读者

**资深爱好者**要的是「原来如此」。你已经知道活塞能推、苦力怕会炸、创造模式能飞。你未必能说出：创造为什么不是关卡编辑器，服务器为什么才是很多人真正在玩的游戏，TPS 掉了的时候世界失去的为什么是因果而不是帧率。后文按这个标准写：把习以为常的东西变成可检验的机制。

**游戏开发者**要的是「可以拿走」。拿走的不是方块美术，是十二条原则，以及——同等重要——**抄不走的条件**。没有不可迁移条件的原则是鸡汤。Minecraft 有过公开开发、付费 Alpha、二十年模组工具链、一整代人的影像入口。这些不是设计手法，是历史窗口。卷二第 16 章把两份清单分开写；在此之前，请把「我要做下一个 Minecraft」先搁下。

两类人读的不是同一本书的缩写。共用的是[全书的命题](./thesis)，分叉的是深度和顺序。

## 路径

不必按卷号通读。

| 你更像 | 顺序 | 可跳过 |
|--------|------|--------|
| 设计师、玩法程序 | 序 → [卷二](../design) 全部 → 卷一第 4–6、12 章 → 卷三第 17–18 章 | 卷三实现细节 |
| 引擎、技术程序 | 序 → 卷二第 1–2、7 章 → [卷三](../impl) 全部 → [卷四](../rewrite) | 卷一影像章可略 |
| 制作人、商业 | [卷一](../history) 全部 → 卷二第 11–16 章 → 卷三第 15–17 章 | 红石实现、渲染 |
| 资深玩家通读 | 按卷顺序；每章先读命题，再决定是否下沉到节 | 标了开发者侧重的章，可读命题与结尾 |

卷四是可选的重写思想实验。它不是续作预告。没读过卷二原语和卷三结语就进卷四，会把尚未论证的「本质」当成前提。

作者侧的开工顺序——也是为什么你会看到设计原语写在许多史实前面——是：原语 → 历史证据 → 实现约束 → 重写考试。不要从卷四起笔。阅读可以不照这个顺序；论证必须照。

## 为什么正文先写设计原语

「Minecraft 味」如果含糊着，后面每一句都会打滑。Beta 1.8 算不算「向游戏收敛」，取决于你认为生存是难度还是意义机器。红石的 bug 该不该修，取决于你认为可误用是设计还是事故。Bedrock 算不算「同一个游戏」，取决于度量衡是网格与动词，还是账号与跨平台。

这些判断的地板在卷二第 1–4 章：体素、最小动词与手感、生存、四种模式。它们是不变量。后面所有「像不像 Minecraft」的句子，都要能指回这四章。所以即使你走商业路径或引擎路径，也建议先读这四章，再分叉。

方法在[《体例与方法》](./method)：现象开篇、证伪、双版本、不写什么。读完命题和方法，你应当知道这本书会怎样骗人、怎样被你拆穿。然后再把时间交给正编。

## 从这里往下读

1. [全书的命题](./thesis) —— 只留十分钟就读这一篇。
2. [体例与方法](./method) —— 口径。后文默认你读过。
3. 按上表进卷：[卷一 · 历史与商业](../history)、[卷二 · 游戏设计](../design)、[卷三 · 技术实现](../impl)。卷四在不变量冻结之后。

附录是查阅：年表、人物、双版本对照、术语、文献、实验题。不承担论证。

## 这一章留下什么

- **爱好者**：你可以跳。跳之前先读命题；读命题之前，知道这书不是来陪你怀旧的。
- **开发者**：你可以拿走原则。拿走之前先读不可迁移条件——它们往往比原则本身更值钱。
