> **本章命题**：红石不是电。官方留下一份会传信号、会推方块、会按格衰减的物理，社区把它用成逻辑电路，再误用成计算机。成功的不是隐喻，是可误用。把未说明的行为清成「正确信号」，灯会更老实，机器会变少。

## 问题

Wiki 上的红石和游戏里的「红石」不是一回事。

Wiki 画的是门、锁存器、加法器、零刻、准连接。游戏里给你的是粉、火把、中继器、比较器、活塞，以及「红石会亮」。没有一张官方图告诉你这是在编程。可有人用这些砖搭出能算的东西，还能把搭法写成教科书，传十年。[^wiki]

本章要问：失败的电力隐喻，如何成为成功的逻辑电路？不要步骤，不要原理图。要立起的是方法章里已经等着的那句话：红石是可误用系统——官方交付的玩法清单只有「机关积木」，但物理本身稳定、可观察、可复述；于是所有未被说明书担保的行为，只要稳定，就能被社区当成语言去依赖，再依赖成机器。这个词后文当普通名词用。可被证伪的说法是：社区发明的那些机器，是官方故意藏在关卡里的「高级玩法」，Wiki 只是攻略。只要还存在一次「修复」让半个社区觉得被阉、而不是觉得游戏更诚实，这句话就不成立。

卷二开卷那章把一米格压进四种玩法（[《体素作为设计原语》](/design/voxel-primitive)），红石没有自己的舞台：它寄生在建造用的格上。寄生正是它能从门上的灯长成一台虚拟机的原因。

## Wiki 上的红石和游戏里的「红石」不是一回事

游戏里的红石是材料：亮或不亮，强或弱，推或不推。玩家看见的是灯和门。Wiki 里的红石是语言：信号、刻、更新顺序、BUD（利用「某些方块不响应方块更新」的角落做成的探测器）、准连接。语言是社区从物理里读出来的，不是说明书发下来的。

阅读的起点人人都有，而且开局就被发到手上：木门用手能开，铁门用手开不动。铁门不认手，只认信号。这一格不认手，就是整个红石世界的第一块基石——从这里往后，门听信号的，不听你的。Wiki 的全部条目，都是这条观察的下游。

命名是把物理读成语言的第一步。把「火把贴着的方块一被点亮，火把就熄灭」叫成反相器，游戏行为没有任何变化，但从此它可组合、可教学、可检索：你可以在一页 Wiki 里查它，而不是在几千根火把里重新发明它。在别的游戏里，绕过设计好的触发器叫漏洞利用；在这里，给行为起名字不改动游戏一步，它只是阅读。这种落差不是文档没写完，而是一种设计站位：官方把红石当机关积木，玩家把积木当物理定律。定律一旦被读出来，就有人按定律盖超出机关的东西。超出不是作弊，是阅读。

词表也是进口的。门、锁存器、半加器、多路开关，这些名字从数字电路课借来，借得理直气壮——因为这套物理读起来的确是布尔逻辑。社区 Wiki 还发展出一层自己的标注：哪些设计稳定，哪些依赖时序、版本一改就可能变。这份维护不是官方文档，却在干官方文档的活，连弃用通告都有。社区甚至自己分了科：一边是拿红石盖门、盖农场的生存派，一边是自称「技术 Minecraft」的研究派——后者连刷新机制、碰撞箱都读，红石只是其中一章。

服务器和影像把阅读公开。红石教学视频不教「如何过关」，教「这套物理还能怎样念」（见[《影像、教育与一代人的媒介》](/history/media-education)）。教材能便宜，因为失败也落在格上：灯没亮，人人能指出是哪一格出了问题。指得出位置，才有共同排错；有共同排错，才有第二作者。

## 它不是电：隐喻失败

名字叫红石，样子像导线，强度从 15 走到 0，很像电压。它不是电压。没有电流、没有功率、没有短路烧掉你家。中继器不像电阻，比较器不像运放。拿着电路课的直觉来玩，只会学出一套错物理。[^dust]

把这层物理按玩家可观察的账列出来，其实没几条。红石粉把信号沿格传递，强度从十五档起、每走一格减一——衰减同时是刻度：从光源走到这里还剩几档，就是走了几格。红石火把是反相器，顺手还带着「贴着供自己的方块」的怪脾气。中继器单向放行，还能按刻加延迟。比较器读的是另一本账：它能把箱子装了几成、物品展示框转了几格，读成信号强度——世界里的存量，被读成了数。这几条行为，一盏灯一块粉就能当场核对。条目少是关键：语言必须小而稳，才传得开。

隐喻失败，对设计是福。真电太贵：要算连续量，要处理安全，要让小孩的灯和工程师的电网分开。红石把传输收成整数格、把强度收成十五档、把时间收成刻。离散的传输刚好能被当成逻辑来读：有信号、无信号、延迟几刻。逻辑电路不需要电真实，它需要稳定的、可数的因果。

时间也有自己的账。游戏刻每秒二十次，是世界的节拍；红石元件的动作有的在刻里排队，有的按自己的周期翻面——「红石刻」和「游戏刻」不是同一个钟。中继器的延迟按刻计，时钟的频率也是拿刻数凑出来的。把时间切成可数的格子，是时钟可造、机器可排程的前提。

还有一层隐喻失败是故意的残留：电路不画在另一张图纸上，它就住在你走廊的墙里。水能冲掉红石粉，你能从电线上走过去，一扇门后面就藏着一台机器。逻辑与生活共用一格——这是「脏」，也是礼物：机器永远在你的居住尺度里，而不是在一块独立的电路板关卡里。

活塞把逻辑接回机械。信号不只点灯，还推格。能推格，计算就有了手：能开门、能推动整排方块、能把方块阵列当成存储用的磁带。机械与电路焊在同一套格子上，这是红石不像单独「编程小游戏」的原因。编程小游戏有自己的舞台。红石的舞台是你家的墙。

官方后来投放的观察者，几乎是把社区当年偷读的物理收编成了正式方块：它做的正是 BUD 做的事——盯着邻居的更新。发射器和投掷器这一对也按格计较：长得几乎一样，发射器把东西「用」出去——射箭、放水、点火；投掷器只把东西「丢」出来。连输出都在认格。

Java 与 Bedrock 从这里开始说两种因果。准连接让活塞被「上方那一格若有机构就会亮」的鬼信号激活，哪怕那一格是空气；Wiki 标成 Java 独有，Mojira 把相关工单标成「按预期工作」。Bedrock 没有这套。时序、活塞、更新顺序也不共用一份。[^qc] 两条线的分叉，[《两条产品线：Java 与 Bedrock》](/history/java-bedrock)里记过账：同一张示意图，两边的灯可以不一样亮。债的形状在这里再次暴露——两边争的是还叫不叫红石，不是要不要格子。

<Note>
删掉句中的「Java」或「Bedrock」，红石句子常常不成立。本章合写的是合同：信号占格、强度可数、能推方块。分写的是因果。因果分叉，误用就无法完整跨产品线传播。
</Note>

## 官方不教意味着什么

官方教你做门上的灯，最多教到中继器怎么延时。不教飞行器，不教存储器，不教计算机。不教，不是因为这些不存在，是因为它们不是产品承诺。承诺停在物理层；物理之外的用法，是玩家自己阅读出来的。

不教有两面。一面是留白：玩家作者席被写进正作，不必等 DLC 关卡。另一面是冷酷：新手会站在红石粉前面感到被抛弃，直到点开别人的视频。这种抛弃是真的，是社区生态用视频把它补上的。补上之后，教科书不在游戏里，在社区里。游戏仍然只负责物理别塌。

官方偶尔投放新元件——观察者、标靶、幽匿感测体——照样不附带教材。投放本身成了一次次实验：社区在很短的时间内把新元件读进已有的语言。幽匿感测体上线不久，就被读成「用声音传信号的元件」，接进时钟、电报和自动农场——它本来不是为红石设计的，它被红石收编了。每一次收编都在证明同一件事：语言长在社区，官方只负责投放新物理。

把教程写进官方，红石会变成一门课。课有标准答案，标准答案会把误用标成错误；误用一旦被标成错误，修复它就有了道德正当性。可误用系统怕的正是这种正当性。

教科书于是长成三层：Wiki 的教程页是字典，视频的系列课是学校，服务器里老手带新手是师徒。三层都在游戏外；游戏内唯一的反馈是灯亮了没有。这留下一个长期的分层：「会用」和「懂了」分开——许多人会复制一台刷石机，说不出它为什么亮。复制粘贴的知识在这里也算稳定，因为它复制的不是步骤，是格子：格子不会抄错，只会抄旧。

<Callout type="warning" title="零教程">
本章不教搭。任何「先放中继器再……」都是攻略。要看的是：为什么没人教，仍然长得出计算机。
</Callout>

## 发明的计算：门、时钟、飞行器、计算机

四件事，只说明误用的方向，不给步骤。

**门**几乎像本意：信号到，门开。本意已经在拿格子当机关——铁门不认手，就是原版自带的种子。社区把本意读厚：活塞把整面墙收进地板，是隐藏门；物品展示框转几格能被比较器读成信号，转对了角度才放行，展示框成了密码盘；和时钟焊在一起的门，只在世界自己的节拍里开。读到这个厚度，门就不再是家具说明书里的那种门。「2×2 的隐藏门」是社区的入门仪式，视频里数以千计的隐藏门教学都是它的成年礼。对照很清楚：别的游戏把隐藏门做成脚本事件，这里的隐藏门是物理本身，你能看着它一格一格打开，也能一格一格拆掉。

**时钟**把时间变成可造的对象。会翻转的火把、首尾相接的中继器，都能让信号自己按节拍亮灭。循环一稳，世界上就有了节拍器：灯塔按秒闪，农场按节奏收放水，音符盒被时钟排成整首整首的曲子——有人把整首歌敲进方块，按键次序就是乐谱。时钟也撞上物理的边界——切换太快的火把会烧毁——于是连节拍的下限都是物理规定的。节拍器不是菜单里的计时器：它占格，能被挖掉，能把服务器拖卡。时间从此和库存沾亲带故。

**飞行器**把活塞的推读成位移。粘液块会粘住相邻的方块，活塞推自己粘着的整排，观察者在到位的瞬间再发一个信号，于是一组方块自己往前走。走路仍认格，仍能被一堵两格宽的墙挡住，仍能把家拆了。玩家拿它运货，也拿它攻城：无政府服务器上，装了炸药的飞行器一路拆到别人家门口。这是机械层的误用：机关积木变成交通。飞行器也是最吃时序的一族：版本一改活塞的规矩，有些设计就趴在原地，于是「这个设计在哪个版本还能飞」成了标题里要写的参数。真正的载具系统会给你一辆车；飞行器给你的更像一列会散架的路。

**计算机**把稳定的因果读成比特。灯是位，火把是反相器，中继器是延迟线，一排排方块阵列是内存。常见的入门机是 4 位、8 位——字长既是行话，也是预算：每加一位，机器就大一圈，大到占地抵得上一片农场。社区真有人用它搭出能做算术、能跑程序的处理机；字长、指令集、主频，是社区自己的行话。这些机器慢得惊人，一次加法可能要用掉以秒计的时间——慢不是缺陷，慢证明每一比特都是真实的物理。没有人在 Alpha 时代承诺过会有人用红石粉搭出算术单元（ALU）。承诺过的只有：信号会走，强度会减，方块会被推。这就够了——物理足够稳定，稳定到能当一份没有文档的指令集。

<Memoir title="修了一个 bug">
机器全炸。炸的不是你的审美，是一份被社区当成 API 的更新顺序。官方以为自己在修漏洞。玩家以为自己的语言被删了一个动词。两种诚实撞在一起。撞完，才知道红石的作者席有多大一部分不在 Mojang。
</Memoir>

这四件事共用一个形状：玩家把物理的边角读成功能。边角一旦稳定，就有人依赖。依赖一旦成群，边角就升级成宪法。其中最深的一份宪法是更新顺序：同一格线上哪个方块先听到更新，决定几千台机器的生死。它从没进过任何设计文档，却写在 Wiki 里、写在梗里、写在「求你们别修这个」——版本说明区的固定节目。

<Constraint name="可误用系统" verdict="地基" chain="稳定物理 → 未说明行为可依赖 → 修复即删语言">
系统给出的是可观察的因果，不是白名单玩法。未被文档、甚至被官方当成瑕疵的行为，只要稳定、可复述、被广泛当材料，就是社区 API。把 API 清成「正确信号」，游戏会更像说明书，作者席会变窄。可误用不等于必须永不修。它等于：修的时候你在立法，不是在擦灰。
</Constraint>

## 三种可编程：机械 / 电路 / 脚本；Minecraft 选了哪条

可编程不止一种。

**机械**：齿轮、连杆、活塞阵列。因果在力和碰撞上。Minecraft 有矿车、有活塞，机械是红石的一只手。矿车是老一辈的机械：轨道运货，矿车撞上探测器也能发信号，老机器里有整座矿车时钟。机械这只手比红石粉还老，至今没被解雇。

**电路**：离散信号在网络上走。红石粉走的是这条。失败的电隐喻，成功的是电路。

**脚本**：命令、函数、模组代码。因果在字符串和事件上。命令方块以后，官方把这条河越挖越宽。下一章（[《命令、数据包与地图》](/design/commands-datapacks)）写它。

Minecraft 没有只选一条。它把电路焊在机械上，再把脚本叠在上面。真正稀有的是中间那层：电路不是单独的编程小游戏，是墙上的粉。墙上的粉能被挖、能被水冲、能和门住在一起。别的沙盒发过更干净的电路：GMod 的 Wiremod 把接线做成一个扩展，图纸上漂亮得多。干净有干净的代价——它和墙不住在一起，拆得走，也拆得出。Minecraft 没把电路做成一个模式，做成了矿石。脚本更强、更干净、也更容易变成另一款游戏——地图作者的游戏，而不是居住者的游戏。机械更闹、更物理、更难做成通用计算。电路刚好在中间：足够稳定，能当逻辑用；足够「脏」，和墙长在一起，拆不出一张干净的图纸；足够占格，和房子共用一把尺。

所以开发者不能只抄「能接线的方块」。接线若画在另一张图上，门和机器会分家。要抄的是：把一份离散、可误用的因果嵌进建造用的度量里，然后故意不教完。不教完才有教科书长在外面。教完，你得到的是关卡里的解谜电线。解谜电线很好。它不是这台虚拟机。

可被证伪的说法是：把准连接和更新顺序按文档清干净，红石会更公平、更好学，社区会感谢诚实。方法章写过：若清完之后社区觉得更诚实而不是被阉，命题要改。至今，每一次「红石坏了」，争论的都是语言被删了多少，不是灯该不该更符合电学。

## 这一章留下什么

- **爱好者**：你早就在编程，只是把它叫成接线。Wiki 不是攻略，是从物理里读出来的语言。语言能被一次修复删掉，所以那次爆炸才像政治。
- **开发者**：能抄走的是「可误用物理当编程」——离散信号、占格、能推动世界，官方停在物理，教科书长在社区。抄不走的是：二十年误用已经把未说明行为写成 API；你换一套更干净的电路，等于让他们重新学说话。Java 与 Bedrock 已经证明：因果一分叉，同一张图就不再是同一门语言。干净好做，可误用难留；动手术的时候，记住你是在立法，不是在擦灰。

[^wiki]: 社区把红石电路、准连接、更新顺序写成可检索的条目与教程，长期充当非正式说明书。概述见 [Redstone circuits](https://minecraft.wiki/w/Redstone_circuits)、[Redstone mechanics](https://minecraft.wiki/w/Redstone_mechanics)。

[^dust]: 红石粉沿格传递，信号强度 0–15，每格衰减；中继器、比较器、火把改的是这份离散信号，不是电压与电流。见 [Redstone Dust](https://minecraft.wiki/w/Redstone_Dust)。

[^qc]: 准连接为 Java 独有：活塞、发射器、投掷器可被「上方那一格若存在机构方块时会被激活」的信号激活，即使该格为空气。Java 工单 MC-108 标为 Works as Intended。Bedrock 无此机制。见 [Tutorial:Quasi-connectivity](https://minecraft.wiki/w/Tutorial:Quasi-connectivity)；Bedrock 工单如 [MCPE-14664](https://bugs.mojang.com/browse/MCPE/issues/MCPE-14664)。
