> **本章命题**：红石不是电。官方留下一份会传信号、会推方块、会按格衰减的物理，社区把它用成逻辑电路，再误用成计算机。成功的不是隐喻，是可误用。把未说明的行为清成「正确信号」，灯会更老实，机器会变少。

## 问题

Wiki 上的红石和游戏里的「红石」不是一回事。

Wiki 画的是门、锁存器、加法器、零刻、准连接。游戏里给你的是粉、火把、中继器、比较器、活塞，以及「红石会亮」。没有一张官方图告诉你这是在编程。可有人用这些砖搭出能算的东西，还能把搭法写成教科书，传十年。[^wiki]

本章要问：失败的电力隐喻，如何成为成功的逻辑电路？不要步骤。不要原理图。要定义那句已经在方法章里等着的话：红石是可误用系统。可被证伪的说法是：社区发明的那些机器，是官方故意藏在关卡里的「高级玩法」，Wiki 只是攻略。只要还存在一次「修复」让半个社区觉得被阉、而不是觉得游戏更诚实，这句话就不成立。

上一章把一米格压进四种玩法。[《体素作为设计原语》](/design/voxel-primitive) 红石没有自己的舞台。它寄生在建造用的格上。寄生是它能从门上的灯长成虚拟机的原因。

## Wiki 上的红石和游戏里的「红石」不是一回事

游戏里的红石是材料：亮或不亮，强或弱，推或不推。玩家看见的是灯和门。Wiki 里的红石是语言：信号、刻、更新顺序、BUD、准连接。语言是社区从物理里读出来的，不是说明书发下来的。

这种落差不是文档没写完。它是设计位置：官方把红石当机关积木，玩家把积木当物理定律。定律一旦被读出来，就有人按定律盖超出机关的东西。超出不是作弊。超出是阅读。

服务器和影像把阅读公开。红石教学视频不教「如何过关」，教「这套物理还能怎样念」。[《影像、教育与一代人的媒介》](/history/media-education) 教材能便宜，因为失败也在格上：灯没亮，人人能指那一格。指得了，才有共同排错。共同排错，才有第二作者。

## 它不是电：隐喻失败

名字叫红石，样子像导线，强度从 15 走到 0，很像电压。它不是电压。没有电流、没有功率、没有短路烧掉你家。中继器不像电阻，比较器不像运放。把电路课搬进来，会学错。[^dust]

隐喻失败，对设计是福。真电太贵：要算连续量，要处理安全，要让小孩的灯和工程师的电网分开。红石把传输收成整数格、把强度收成十五档、把时间收成刻。离散的传输刚好能被当成逻辑：有信号、无信号、延迟几拍。逻辑电路不需要电真实。它需要稳定的、可数的因果。

活塞把逻辑接回机械。信号不只点灯，还推格。推格，计算就有了手：能开门、能飞、能把方块当成磁带。机械与电路焊在同一套格子上，这是红石不像单独「编程小游戏」的原因。编程小游戏有自己的舞台。红石的舞台是你家的墙。

Java 与 Bedrock 从这里开始说两种因果。准连接让活塞被「上方那一格若有机构就会亮」的鬼信号激活，哪怕那一格是空气；Wiki 标成 Java 独有，Mojira 标成就是这样。Bedrock 没有这套。时序、活塞、更新顺序也不共用一份。[^qc] [《两条产品线：Java 与 Bedrock》](/history/java-bedrock) 同一张示意图，两边的灯可以不一样亮。债的形状暴露了：两边争的是还叫不叫红石，不是要不要格子。

<Note>
删掉句中的「Java」或「Bedrock」，红石句子常常不成立。本章合写的是合同：信号占格、强度可数、能推方块。分写的是因果。因果分叉，误用就无法完整跨产品线传播。
</Note>

## 官方不教意味着什么

官方教你做门上的灯，最多教到中继器怎么延时。不教飞行器，不教存储器，不教计算机。不教，不是因为这些不存在，是因为它们不是产品承诺。承诺停在物理。物理之外，是阅读。

不教有两面。一面是留白：玩家作者席被写进正作，不必等 DLC 关卡。一面是冷酷：新手会在粉前面感到被抛弃，直到点开别人的视频。抛弃是真的。视频是生态把它补上。补上之后，教科书不在游戏里，在社区里。游戏仍然只负责物理别塌。

把教程写进官方，红石会变成一门课。课有标准答案。标准答案会把误用标成错误。错误一被标出来，修复就有了道德。可误用系统怕的就是这种道德。

<Callout type="warning" title="零教程">
本章不教搭。任何「先放中继器再……」都是攻略。要看的是：为什么没人教，仍然长得出计算机。
</Callout>

## 发明的计算：门、时钟、飞行器、计算机

四件事，只说明误用的方向，不给步骤。

**门**几乎像本意：信号变成通过。本意已经在用格子当机关。社区把本意读厚：隐藏的门、只有物品能开的门、和时钟焊在一起的门。厚起来的时候，门不再是家具说明书里的那种门。

**时钟**把时间变成可造的对象。红石自己会亮会灭，循环一稳，世界上就有了节拍器。节拍器不是菜单里的计时器。它占格，能被挖掉，能卡服。时间变成库存的亲戚。

**飞行器**把活塞的推读成移动。方块开始自己走路。走路仍认格，仍能被堵住，仍能把家拆了。这是机械层的误用：机关积木变成交通。

**计算机**把稳定的因果读成比特。灯是位，活塞是手，世界是磁带。没有人在 Alpha 的红石粉里承诺过 ALU。承诺过的只有：信号会走，强度会减，方块会被推。够了。够了，是因为物理足够稳定，稳定到能当未文档的指令集。

<Memoir title="修了一个 bug">
机器全炸。炸的不是你的审美，是一份被社区当成 API 的更新顺序。官方以为自己在修漏洞。玩家以为自己的语言被删了一个动词。两种诚实撞在一起。撞完，才知道红石的作者席有多大一部分不在 Mojang。
</Memoir>

这四件事共用一个形状：玩家把物理的边角读成功能。边角一旦稳定，就有人依赖。依赖一旦成群，边角就升级成宪法。宪法不写在版本说明里。写在 Wiki，写在梗里，写在「求你们别修这个」。

<Constraint name="可误用系统" verdict="地基" chain="稳定物理 → 未说明行为可依赖 → 修复即删语言">
系统给出的是可观察的因果，不是白名单玩法。未被文档、甚至被官方当成瑕疵的行为，只要稳定、可复述、被广泛当材料，就是社区 API。把 API 清成「正确信号」，游戏会更像说明书，作者席会变窄。可误用不等于必须永不修。它等于：修的时候你在立法，不是在擦灰。
</Constraint>

## 三种可编程：机械 / 电路 / 脚本；Minecraft 选了哪条

可编程不止一种。

**机械**：齿轮、连杆、活塞阵列。因果在力和碰撞上。Minecraft 有矿车、有活塞，机械是红石的一只手。

**电路**：离散信号在网络上走。红石粉走的是这条。失败的电隐喻，成功的是电路。

**脚本**：命令、函数、模组代码。因果在字符串和事件上。命令方块以后，官方把这条河越挖越宽。下一章写它。[《命令、数据包与地图》](/design/commands-datapacks)

Minecraft 没有只选一条。它把电路焊在机械上，再把脚本叠在上面。真正稀有的是中间那层：电路不是单独的编程小游戏，是墙上的粉。墙上的粉能被挖、能被水冲、能和门住在一起。脚本更强、更干净、也更容易变成另一款游戏——地图作者的游戏，而不是居住者的游戏。机械更闹、更物理、更难做成通用计算。电路刚好在中间：够稳，够脏，够占格。

所以开发者不能只抄「能接线的方块」。接线若画在另一张图上，门和机器会分家。要抄的是：把一份离散、可误用的因果嵌进建造用的度量里，然后故意不教完。不教完才有教科书长在外面。教完，你得到的是关卡里的解谜电线。解谜电线很好。它不是这台虚拟机。

可被证伪的说法是：把准连接和更新顺序按文档清干净，红石会更公平、更好学，社区会感谢诚实。方法章写过：若清完之后社区觉得更诚实而不是被阉，命题要改。至今，每一次「红石坏了」，争论的都是语言被删了多少，不是灯该不该更符合电学。

## 这一章留下什么

- **爱好者**：你早就在编程，只是把它叫成接线。Wiki 不是攻略，是从物理里读出来的语言。语言能被一次修复删掉，所以那次爆炸才像政治。
- **开发者**：能抄走的是「可误用物理当编程」——离散信号、占格、能推动世界，官方停在物理，教科书长在社区。抄不走的是：二十年误用已经把未说明行为写成 API；你换一套更干净的电路，等于让他们重新学说话。Java 与 Bedrock 已经证明：因果一分叉，同一张图就不再是同一门语言。干净好做。可误用难留。难留的时候，记住你在立法。

[^wiki]: 社区把红石电路、准连接、更新顺序写成可检索的条目与教程，长期充当非正式说明书。概述见 [Redstone circuits](https://minecraft.wiki/w/Redstone_circuits)、[Redstone mechanics](https://minecraft.wiki/w/Redstone_mechanics)。

[^dust]: 红石粉沿格传递，信号强度 0–15，每格衰减；中继器、比较器、火把改的是这份离散信号，不是电压与电流。见 [Redstone Dust](https://minecraft.wiki/w/Redstone_Dust)。

[^qc]: 准连接为 Java 独有：活塞、发射器、投掷器可被「上方那一格若存在机构方块时会被激活」的信号激活，即使该格为空气。Java 工单 MC-108 标为 Works as Intended。Bedrock 无此机制。见 [Tutorial:Quasi-connectivity](https://minecraft.wiki/w/Tutorial:Quasi-connectivity)；Bedrock 工单如 [MCPE-14664](https://bugs.mojang.com/browse/MCPE/issues/MCPE-14664)。
