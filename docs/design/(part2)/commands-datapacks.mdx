> **本章命题**：原版与模组的边界被故意模糊：命令和数据包让你在不改程序的前提下当关卡设计师，却到新动词为止。模糊是收编。收编给了地图工业一条官方河，也把真正加系统的作者席留在加载器那一侧。

## 问题

有人用原版做出 RPG：职业、任务、副本、倒计时。进门不用装模组。出门发现：职业是计分板，任务是命令方块，副本是一张冒险模式的图。它看起来像另一款游戏。它骑在同一套格子、同一套物理、同一只手上。

本章要问：原版与模组的边界为何被故意模糊？可被证伪的说法是：官方迟早会提供和 Forge 一样的模组 API，命令只是过渡。只要还看见数据包能改进度不能加新挖法、Bedrock 用附加包走另一条审核河，这句话就不成立。过渡会结束。模糊可以成为产品。

不要命令大全。要写的是作者席被收到哪一层，以及哪一层仍然必须写出新系统；作者席的历史账，[《模组作为第二作者》](/history/mods-as-authors)里已经记过。

## 原版能做 RPG 吗

能。能到一个令人不安的程度。计分板当属性：杀敌数、金币、阵营好感，一人一本账，随时可查可加减。函数当任务脚本，能排成每刻执行的主循环。战利品表当掉落，进度当引导，做完一步弹一条提示。Boss 栏当演出血条，标题和字幕栏当台词。结构方块当关卡块，把预制的房间原样抄进世界；盔甲架当 NPC 站桩，写好词条的物品当任务道具，村民的柜台当商店。玩家可以感觉自己在玩职业。底层仍是看、走、挖、放、使用——冒险模式把挖和放锁上，只留下作者亲手许可的那几个口子：哪些方块准动，写在物品自己身上，玩家拿到的每把「钥匙」都是作者提前签过字的。[^cmd]

不安来自成功。成功说明正作的物理够当别的游戏的地板。地板一当，边界就糊：这还是 Minecraft 吗，还是 Minecraft 做的引擎？答案是寄生。地图类型骑在同一物理上，才仍然能被没装模组的人打开。打开的那一刻，品牌还在。玩法已经是第二作者的。

不能的部分更硬。新的方块行为、新的机制动词，数据包都使不上劲；1.16 之后连新维度都能用 JSON 摆出来，但摆出来的维度，货架上仍是原版那套生成词汇——噪声的形状、结构的种类，都是现成的，你开得了新店，进不了新货。使不上劲的部分，不是因为文档缺了一条命令，而是命令改的是数据，不是程序。数据能给 RPG 穿上衣服；程序才能长出新的骨头。

## 命令方块：运营者变成关卡设计师

命令本是管理员的口。命令方块把口焊在世界上：某一格在某一刻说话。运营者不再只在聊天栏立法，他在地形里立法。门可以是命令，出生点可以是命令，死可以是命令。关卡设计师这个职业，从插件和模组里被请回原版。[^cblock] 这颗方块后来长出连锁与重复两种型号，一格接一格能排出一串话——但「每刻都说」的那一种，始终在提醒作者预算有限。

这块方块有三种口吻：一种踩一下说一句，一种每刻都说，一种接在前一句后面排队说。地图里的倒计时、检查点、过场演出，多半是这三种口吻的编排。说得最勤的那种，代价按刻付——地图作者学到的第一课往往不是语法，是预算：每刻能说的话有限，说多了全场跟着卡。权限是第二道门槛。能放命令方块的人，已经不是普通居民；原版服务端默认不开命令方块，要在配置里显式打开，世界才容许这一格立法——默认关，说明官方清楚这一格不是给居民用的。创造、作弊、操作员，这串钥匙和[《创造模式不是关卡编辑器》](/design/creative-mode)那张模式表咬合。地图工业需要这把钥匙：生产在创造，交付在冒险，演出用命令。居住者不需要每天拿这把钥匙。拿了，家会变成脚本。

Java 的命令和 Bedrock 的命令不是同一份方言。选择器、组件、执行子命令、函数怎么写，分叉到不能复制粘贴。[^cmd] 分叉再次证明：模糊边界是两条产品线各自的收编，不是一份 API 的两个皮肤。

<Callout type="warning" title="不写命令大全">
命令是工具。本章只问工具把谁变成了作者。语法留给 Wiki。
</Callout>

## 数据包：官方温和模组

Java 1.13 把数据包做成存档里的一个文件夹：进度、配方、战利品、函数、标签都在里面，后来一路长到维度和附魔都能被数据碰到。[^datapack] 原版自己也是一份内置包。实验性功能常常是再塞一份包。官方在说：改内容，走这条河，不必碰 jar。

温和在「不必碰 jar」。也温和在「碰不了 jar 里的那一层」。数据包住在存档目录里，随存档走：你把存档拷给朋友，功能跟着过去，他不必装任何启动器——模组住在每个玩家的磁盘里，数据包住在家里。函数可以排成每刻执行的主循环，数据包因此有了自己的「心跳」，这是它最接近程序的一步，但心跳里跑的仍然只是原版动词的排列组合。温和也有账单：数据包带版本号，游戏每次大版本升级都可能让它先报错，旧包要人手改一行配置才肯继续跑——收编作者的河，也会改道。

生态顺着河长出来。社区把单功能的小包当轻量分享品——换一套战利品、加几个配方、把原版拧困难一档——像插件时代的轻量替身，却不占每个玩家的磁盘。官方自己也在这条河里试水：实验性功能往往以一份包的形式预览，你开一个开关，等于提前住进下一版的原版。

数据包是承认的数据驱动模组，不是加载器。它把作者席部分收回：以前要 Forge 才能改的掉落和配方，现在原版能改。收回不是消灭模组。收回是把一部分第二作者变成第一作者的房客——住在世界目录里，随世界走，不随启动器走。

Bedrock 对应的河叫附加包：行为包、资源包、可选的市场审核（[《两条产品线：Java 与 Bedrock》](/history/java-bedrock)）。不要把数据包的故事安到 Marketplace 头上。一边是文件夹里的温和模组，一边是货架上的商品。都能改内容。作者席、崩溃域、分成完全不同。

| 河流 | 住在哪 | 能改到哪 | 谁审它 |
|------|--------|----------|--------|
| 数据包（Java） | 存档目录 | 内容与部分规则，不加动词 | 没人审，随世界走 |
| 附加包（Bedrock） | 存档或市场 | 内容，可加脚本 | 可选市场审核 |
| 模组 | 每个玩家的磁盘 | 程序本身，新动词 | 加载器与兼容性 |
| 插件 | 服务器 | 这台服的法律 | 服主 |

<Note>
Java 进度绑世界、可被数据包改写；Bedrock 成就是账号和平台的。数据驱动在两边不是同一个开关。
</Note>

## 类型寄生：地图类型如何骑在同一物理上

冒险地图、CTM（Complete the Monument，收集指定物品补全纪念碑的地图流派）、解谜、RPG、跑酷图、起床战争的大厅，形态差很远，地板同一张：格、碰撞、红石或命令、冒险或生存的钥匙。解谜图把「不准挖」当主规则，钥匙是物品，机关是藏在墙后的红石；RPG 图用带词条的物品和命令脚本扮演职业；跑酷图把移动系统的每一格潜规则练成题型。寄生是恭维。恭维说物理够用。够用，地图才不用自带引擎。

资源包补另一半：换皮不换骨。那把「魔剑」的剑穗是新贴图，挥出去的仍是剑的弧线。看破这层皮不破坏乐趣——它正是寄生的证明：所有奇观都还在原版动词上跑。

寄生也是约束。解谜不能靠「新的挖」，只能靠「不准挖」加机关。RPG 不能靠新职业骨骼，只能靠物品和脚本扮演职业。CTM 把探索收成收集，仍要走生成或手摆的地形。每一种类型都在原语上借力，也被原语卡住。卡住之处，就是下一节的极限。

服务器把寄生做成产业：一张图，一个大厅，一次重置（[《服务器即新游戏》](/history/servers)）。重置需要脚本。脚本需要命令或插件。插件是另一条立法河。命令方块让小一点的作者不必先当插件作者。分工也跟着细：建筑、脚本、测试、运营——「地图作者」早就是一个工种，不是一个人的爱好。这是模糊的社会功能：降低关卡设计师的入门，不降低系统设计师的入门。

## 极限：何时必须写出新系统

当你需要新动词。想要一种抓钩、一条真正的自动化流水线——这些都是新动词。当你需要新的方块行为——一块新方块该怎么被激活、怎么老化。想要一块「磁铁」吸附近的掉落物，数据包也能凑：每刻扫描、再搬运——跑得动，但那是用字符串假扮力场，加载器一行代码的事，这里要写成一套扫描账本。当你需要给所有存档装上同一套程序，而不是给每一张图塞命令方块。

极限不是道德。极限是分层。数据层改内容与部分规则。程序层加系统。官方把数据层收成数据包 / 附加包，把程序层留给模组加载器和长期缺席的「真正模组 API」。对 Java，缺席是历史事实：模组 API 早就长在社区的加载器里。对 Bedrock，缺席是产品选择：能上架的走审核，能加系统的走脚本那条窄门。

命令本身也在给这条边界作证。函数、命名空间、按刻执行——命令系统一年年长出程序的样子，像在数据河里偷偷挖程序的航道，但航道挖到动词为止。

所以边界模糊是故意的。故意让地图作者留下。故意不让每一个内容创作者都变成引擎程序员。故意把加系统的人继续放在第二作者席上，好让收编可以选择——活塞能进，工业模组不能，原则留给第 13 章。本章只要说清：模糊不是还没想好。模糊是分层本身。

可被证伪的说法是：数据包再长几年，就能替代模组。替代若发生，加载器会失业，新动词会从 JSON 里长出来。至今，JSON 长得出新配方，长不出新的「挖」。挖仍在程序里。

<Constraint name="数据改内容，程序加动词" verdict="地基" chain="命令 / 数据包 → 关卡作者 → 新动词仍要系统">
官方河让你在不改客户端的前提下当设计师。设计师的天花板是原版动词表。要加手，就写出系统，或去第二作者席。把天花板形容成过渡，会看不懂为什么 API 始终不像 Forge。
</Constraint>

<Alternative title="真正的模组 API">
加载器把程序当接口：新方块、新维度、新动词。你得到系统。你失去「朋友点进服务器就能玩」的那种零安装——除非系统只活在服务端。官方不提供这一层的完整正统，不是因为命令已经够用，是因为这一层改的是产品边界：谁能发布、谁能审核、崩溃算谁的。边界一旦打开，Marketplace 和 Forge 就更难装成同一句话。
</Alternative>

## 这一章留下什么

- **爱好者**：你玩过的那张 RPG 图，多半还是 Minecraft 的脚在走路。命令把作者藏进方块里。藏进去之后，家和关卡只隔着一把钥匙。
- **开发者**：能抄走的是「数据层收编关卡作者」——命令焊在世界上，数据包随存档走，地图寄生同一物理。抄不走的是：玩家已经把「不用装模组」当成原版的道德；你若用脚本替代物理，得到的是强关卡工具，不是可误用的红石。新动词仍要写系统。不写系统，就不要假装已经提供了模组 API。

[^cmd]: 命令可改玩法、给予物品、传送、改 gamerule；Java 与 Bedrock 的命令方言（选择器、`execute`、组件、函数）不能当作一份复制。见 [Commands](https://minecraft.wiki/w/Commands)。

[^cblock]: 命令方块在 Java Edition 1.4.2 加入，把命令做成世界里的方块。见 [Command Block](https://minecraft.wiki/w/Command_Block)。

[^datapack]: Java Edition 1.13 加入数据包：文件夹或 zip，含 `pack.mcmeta`，可定义进度、配方、战利品、函数等；原版功能也由内置包提供。见 [Data pack](https://minecraft.wiki/w/Data_pack)。Bedrock 侧对应的是行为包 / 资源包等附加包，不是同一套文件夹合同。见 [Add-on](https://minecraft.wiki/w/Add-on)。
