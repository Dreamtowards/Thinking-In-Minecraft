卷一讲的是 Minecraft 怎样从一个小项目成长为全球性的游戏、平台与文化现象。

卷二换一个问题：**如果暂时不谈公司、销量和技术实现，Minecraft 这套玩法为什么能长期成立？**

答案不会被压成一句“少规则产生无限可能”。前面的重写已经反复证明，很多漂亮结论一旦遇到 Java / Bedrock 差异、模组生态、多人服务器、Later games 或长期兼容，就需要补条件。

所以这一卷更像一次拆解：先看世界、生存和资源怎样建立日常，再看建造、红石、命令和模组怎样扩大玩家能做的事，最后讨论多人、社区玩法，以及哪些关系目前真的值得继承。

## 这卷要回答什么

Minecraft 的特别之处，不在某一个孤立机制。

方块如果不能长期修改，只是视觉风格；合成如果不和资源、库存、探索连接，只是一张配方表；红石如果不能碰到容器、活塞和世界状态，只是一套逻辑玩具；多人如果没有持久世界、权限和玩家约定，也不会自然形成我们熟悉的服务器社会。

因此，本卷关注的不是“哪个机制最重要”，而是**系统之间怎样互相改变意义**。

同时，这一卷也会不断做反向检查：

- 这个判断只适用于 Minecraft，还是对其他沙盒也有帮助？
- 它成立需要什么条件？
- 如果把某个关系推到极端，会付出什么代价？
- Later games 为什么会主动选择不同答案？

最后一章[《Minecraft 值得继承什么？》](/design/what-to-inherit)不会给出一份固定原则清单，而会把这些问题重新收束成带条件的中间结论。

## 四部地图

### 第一部 · 世界与生存

前两章先处理最基础的关系：玩家面对的是一个怎样的世界，以及为什么进入以后会自然开始做事。

[《方块与可修改世界》](/design/modifiable-world)不把“方块风格”当答案，而是讨论可指认、可修改、可保存的空间；[《生存与玩家目标》](/design/survival-goals)则看黑夜、饥饿、庇护和死亡怎样给开放世界提供短期压力，却不替玩家规定完整人生。

### 第二部 · 资源、探索与进度

接下来的四章讨论玩家为什么愿意继续走、继续收集、继续变强。

[《物品、合成与库存》](/design/items-crafting-inventory)从资源怎样进入背包和配方开始；[《世界生成与探索》](/design/worldgen-exploration)讨论程序生成怎样制造未知；[《生物、战斗与威胁》](/design/mobs-combat)关注会主动回应玩家的对象；[《进度、维度与游戏后期》](/design/progression-dimensions)则把 Nether、The End、Ender Dragon 与长期世界放进同一个 progression 框架。

这一部最重要的变化，是成长不再只写在角色身上。工具、仓库、道路、交易、交通和基础设施都会改变玩家以后解决问题的成本。

### 第三部 · 创造与扩展

第三部开始从“使用世界”走向“设计世界”。

[《建造与空间》](/design/building-space)讨论庇护所怎样长成基地、道路和有历史的地方；[《创造模式与创作工具》](/design/creative-tools)区分逐块建造、Structure、Selection、Brush 与地图级编辑；[《红石、机器与自动化》](/design/redstone-automation)看局部信号怎样长成物流和机器。

再往后，[《命令、数据驱动与地图创作》](/design/commands-data-maps)让作者开始直接编排事件、规则和关卡；[《模组与玩法扩展》](/design/mods-expansion)则进一步讨论完整的新系统、Modpack、Loader / API 与版本依赖。

这一部的核心不是“玩家终于变成开发者”，而是：**创作意图有不同尺度，工具和扩展层也需要跟着分层。**

### 第四部 · 多人、涌现与继承

最后三章把视线从单个系统移到更大的关系。

[《多人游戏与共同世界》](/design/multiplayer-world)讨论第二个玩家进入以后为什么会出现财产、信任、grief、权限和共同约定；[《设计之外的玩法》](/design/emergent-play)区分规则提供的可能、玩家主动设计与社区传播，解释刷怪塔、Parkour、SkyBlock、Speedrun 等玩法怎样形成。

卷尾[《Minecraft 值得继承什么？》](/design/what-to-inherit)则反过来检查整卷：一米方块、弱主线、不真实物理、Java Modding、红石怪癖都不能自动升格为普遍原则；真正值得带走的关系必须说明适用条件和代价。

## 怎么读这卷

这不是攻略卷，所以不会教第一晚怎么活、某台农场怎么盖，也不会列完整配方和红石线路。每章都尽量从玩家已经见过的现象进入，再解释背后的设计关系。

如果只想抓主线，可以依次读：

1. [《方块与可修改世界》](/design/modifiable-world)：世界为什么能成为玩法状态；
2. [《进度、维度与游戏后期》](/design/progression-dimensions)：开放世界怎样拥有方向，又不必结束长期存档；
3. [《建造与空间》](/design/building-space)：资源怎样变成空间与地方；
4. [《红石、机器与自动化》](/design/redstone-automation)：规则怎样被玩家组合成工程；
5. [《多人游戏与共同世界》](/design/multiplayer-world)：共享世界为什么会变成社会问题；
6. [《Minecraft 值得继承什么？》](/design/what-to-inherit)：哪些判断目前还值得继续带到后两卷。

想先了解 MDA、Rational Game Design、心流等常用术语，可以看番外[《游戏设计理论简介》](/extras/design-theories)。它只是补充框架，不代替本卷的具体论证。
