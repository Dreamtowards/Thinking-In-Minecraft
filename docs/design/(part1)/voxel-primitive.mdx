> **本章命题**：Minecraft 的方格世界是一套供玩家共同操作和描述空间的尺度；它让不同玩法容易借用彼此的成果，但只有连同挖放、持久世界和玩家实践，才显出这种尺度的价值。

## 问题

朋友在语音里帮你修房子，说：「门往左移一格，屋顶再抬一格。」不用共享编辑器，你们也知道要改哪里。夜里怪物来了，那道门又成了掩体；后来有人在门旁装上踏板和红石，原本只供出入的两格空间开始承担机关的工作。

这些事并不神奇。很多游戏都能盖房、打怪或做机关。值得追问的是：为什么在 Minecraft 里，它们常常发生在同一处、用同一套空间说法交接？朋友报格数，玩家挖掉门框，怪物被墙挡住，红石沿着墙走。几种行为各有规则，却不必每次都重新定义「这里」。

卷一的[《从 Infiniminer 到 Cave Game》](/history/infiniminer)已经写过，世界如何从背景变成可改的对象。本章接着问设计上的后果。方块的外观很醒目，真正把上述行为连起来的，是否只是方块的样子？如果换一套高清材质，门洞仍可被数出来；如果把世界换成任意揉捏的曲面，玩家也许能造出更漂亮的门，却需要另一种方法约定门框在哪里。差别值得从画面往下看。

## 画面之外，格子仍在

Minecraft 常被叫作「方块游戏」。这个称呼抓住了外形，却容易把视觉风格和操作规则混在一起。材质可以更细，光照可以更复杂。Mojang 自己曾以资源包试验新的 Java 版贴图，征求玩家意见；方块的纹理换了，玩家仍在原来的位置挖、放和通行。[^textures] 这只能说明画面不是全部，不能据此断言画面无关紧要。辨认材质、估计距离、记住家在哪里，都离不开它。只是材质没有单独规定一格能否被挖走，或门洞要留多宽。

同一格也不总是一个填满空间的立方体。台阶、楼梯、栅栏和雪层都占有格子上的地址，形状与碰撞范围却不同。[^block] 玩家看见的角色模型和实际用于通过门洞的碰撞箱，也不是同一回事。默认玩家碰撞箱约宽 0.6 格、高 1.8 格；两格高的门可以走过，一格高的洞则需要改变姿态。[^player] 因而「一格」首先是定位和操作的单位，不保证里面每样东西都长成一米立方体。

这一区别让「体素」作为章名需要一点解释。本章不把 Minecraft 当成一堆外形完全相同的小立方体。它讨论的是一个以格子定位、允许格内形状变化的世界。玩家能指着某处说「这一格」，再对它执行挖、放、使用等动作。格子提供地址，形状决定那里如何被看见和通过；两者相互配合，不能互相替代。

如果仅把方块理解为低分辨率美术，就难以解释一张建筑图为什么能跨材质包复用，也难以解释玩家为什么能在视频里听完几句尺寸说明，就回到自己的世界试着搭出来。[《影像、教育与一代人的媒介》](/history/media-education)讨论过这种传播。这里更窄的判断是：图、口令和游戏中的动作可以落在同一组可数的位置上。它降低了讲解和接手的成本；不等于每个人都因此会设计好房子。

## 有地址的世界，连续移动的人

格子的好处在于位置容易指认。Java 版的调试屏和 Bedrock 版的坐标显示，都让玩家直接看到世界位置。[^coords] 日常协作甚至不必报完整坐标：「从门往东再挖三格」往往够用。指令有起点、方向和整数距离，对方能照着做，也能指出哪里数错了。这是一种便利，不是一种只属于 Minecraft 的数学能力；其他创作工具同样可以使用坐标、网格吸附和精确输入。

方便交流的代价，是形状不能任意连续变化。想让墙微微弯曲，玩家通常得用不同方块、台阶或楼梯近似；想把一米宽的门洞缩窄一点，也不能直接拖动门框。有人会因此觉得格子碍事，这个抱怨是对的。Minecraft 换来的是另一件事：不擅长雕刻的人，也能把「宽三格、高两格」交给另一位玩家继续施工。精细度与可复述性之间没有普遍正确的比例；Minecraft 恰好选了一种与角色身体和日常建造相称的尺度。

尺度之所以有手感，是因为玩家并不沿着格点跳动。玩家在方格世界里连续移动、转身、起跳、擦过边缘。宽约 0.6 格的碰撞箱能穿过一格宽的通道，也可能从一格宽的缺口掉下去；普通跳跃略高于一格，于是一格高的台阶和两格高的墙给出不同的行动选择。[^player] 格子使地形容易描述，连续运动则让「差一点碰到边」成为真实的经验。跑酷玩家会仔细计算这种差别，普通玩家多半只记得那次险些失足。

方块、占据和碰撞不能写成同义词：同一格中的台阶和实心石块对身体的阻挡不同；同一个玩家也可以站在多个格子的交界处。卷三的[《体素世界的数据模型》](/impl/data-model)会处理存储和状态。本章只取玩家能核对的一层：位置通常按格来指，行动在格间连续发生。把世界简单说成「三维数组」，会抹掉这种体验，也会让人误以为世界上的每个对象都恰好占满一个格子。

Java 与 Bedrock 都保留了这组关系：玩家对着格子操作，身体在其中移动。两版的触及距离、移动与碰撞细节并不完全一致，精密跑酷和对战会在意差异。[^reach] 共用地址并不意味着共用每一条物理规则。这个限度到了红石上尤其重要。

## 挖下来，带走，再放回去

空间能被指认，还不足以成为 Minecraft 的设计原语。地图游戏也有坐标，玩家却未必能动地图。这里多出一条日常循环：挖掉世界中的一部分，获得可携带的物品；把物品放回世界，它又占据一个位置。最普通的一堵墙，既是障碍，也是潜在的材料；背包里的石块，既是库存，也是尚未出现的台阶或掩体。

「世界即库存」是概括，不是技术上的恒等式。并非每种方块都原样掉落，有些东西需要合适工具，有些会给出另一种产物，有些只能通过特定方式取得。时运与精准采集正是玩家熟悉的例子：同一处矿物，挖下来的东西可能不同。游戏内部的方块状态与物品也各有规则，不能因为口语说「把方块装进背包」，就当它们在数据上是同一个对象。[《合成、物品与库存》](/design/crafting-inventory)会把转换的限制继续展开。

即便有这些例外，挖与放仍然改变了玩家看待环境的方式。石头可以堵路，也可以拿来铺路；挖出的坑可以是施工遗留，也可以在追逐时临时成为防线。方格让改变有明确的落点，物品则让改变能跨地点、跨时间延续。你今天拆下一面墙，明天可能用那堆石头修桥。存档记下的不仅是角色走到哪里，还有玩家已经把哪些地方改成了什么。

创造模式把物品数量的限制大幅放开，却仍要求玩家面对位置、形状与相邻关系。无限取材没有自动产出好建筑；它只是让试错更便宜。反过来，生存模式的稀缺让同样一格石头有了开采、运输与留存的成本。这两种经验共用可放置的空间，但并不相同。[《创造模式不是关卡编辑器》](/design/creative-mode)会专门讨论它们为何仍能在同一世界里相遇。

格子让位置容易约定，挖放让约定能变成行动，持久世界让行动的结果留给后来的人。三者合在一起，才足以解释一间房为什么可以被居住、修改和接手；只有网格，并不会自然长出这样的生活。

## 一间房如何接上别的玩法

回到开头那间房。建造时，门宽、墙厚和地板高度都是格数；玩家不需要把建筑导入另一套软件才能开始住。出门时，同一面墙又是导航条件：哪里能走，哪里会卡住，哪处落差要垫一步。怪物靠近时，门框和窗洞成为战斗中的遮挡与射击位置。后来接上踏板、活塞和红石，原先为了通行留下的空间又成为机关的一部分。

这里最值得注意的不是「四种玩法都用了方块」这个清单，而是**前一种行为留下的东西，能直接成为后一种行为的材料**。为了采矿挖出的洞可以改成通道，通道可以通向陷阱，陷阱旁的墙可以藏线路。玩家无需每次离开现场，另开一张战斗地图或电路画布。下一章[《最小动词集与手感》](/design/verbs-feel)会讨论操作为什么也能如此连续；本章只负责空间这一半。

红石最能看出共同尺度的价值，也最能看出它的限度。红石粉、活塞与门都安放在方格世界中，建房的人可以沿着墙和地板安排线路。但方格只说明元件在哪里，不能决定它们如何更新、怎样供电。Java 的准连接与 Bedrock 的红石行为就有重要差异；在两边照搬同一张机器示意图，可能得到不同结果。[《两条产品线》](/history/java-bedrock)与[《红石：把物理做成编程》](/design/redstone)分别处理产品分叉和设计后果。说两版共用空间单位，比说两版共用一套红石语言更准确。

共同尺度也帮助多人协作和二次创作。有人在服务器里说「把大厅向外扩五格」，别人可以在同一个世界接着做；教程视频标明墙与门之间的距离，观众可以在自己的存档试。Java 版的选区工具、Bedrock 版的结构方块和填充命令，也都能利用可指认的位置。不过，能够复制形状不等于能够复制体验。服务器规则、模组内容、红石语义和一起施工的人，都可能改变同一座建筑的用途。格子给出了交接点，没有替大家决定要造什么。

失败也因此常有可讨论的落点。门少留一格，别人可以指出是哪一格；机关不动，先检查线路是否真的到达元件。更复杂的故障当然仍要检查更新顺序或版本差异，绝不会数数就全明白。格子只是让一部分错误容易被共同看见。与其说它强迫玩家合作，不如说它为合作提供了一种便宜的表述方法。

## 这种尺度的边界

可数的方格不是沙盒创作的唯一道路。《Garry's Mod》提供道具、物理约束和建造工具，玩家可以选工具、输入数值、把物体焊接或连接起来；精确操作并未因为物体不按 Minecraft 的方块摆放而消失。[^gmod]《Dreams》则把雕刻作为明确的创作姿势：进入雕刻模式，选择形状，修改作品。[^dreams] 两者都可以做出值得分享的东西，也各有自己的教学和协作方式。

差别主要在默认起点。《Garry's Mod》常从一个道具及其约束出发，《Dreams》让玩家进入创作工具，Minecraft 则让人站在已能行走的世界里，直接对眼前的格子挖和放。前两者能用工具补上精度和复用，Minecraft 也能靠模组、命令或编辑器扩展创作能力。没有谁垄断「可交流」或「可精确」；它们只是把精确、自由与随手修改的成本放在不同位置。

这也限制了本章能推出的结论。不能因为 Minecraft 的格子方便协作，就说换一种尺度的沙盒无法让人住进去；也不能因为一套网格同时容纳建造与红石，就说它必然长出模组生态。方格提供的是条件和倾向，不是历史成功的充分原因。卷一记录社区如何利用这套空间，后面的设计章还要说明动作、稀缺、规则与玩家目标怎样接上它。若这些环节拿掉，只剩一张整齐的网格，房子能被量出尺寸，也未必有人想在那里住。

对开发者而言，可借鉴的不是固定的一米、某种像素大小，甚至未必是立方体本身。更有用的问题是：玩家能否轻松指出要改的对象，能否用日常操作改它，改过的结果能否留给别人继续使用？如果连续空间、吸附工具或别的形状语法能做到这些，也可能形成自己的共同尺度；如果只复制方块外观，却让建造、行动和分享各说各话，外观相似不会带来同样的体验。

## 这一章留下什么

- **爱好者**：你报出的「再往左一格」不只是施工指令；它说明建筑、道路和机关能在同一处被别人看懂、改动和接手，但好玩的世界还需要你和其他人继续使用它。
- **开发者**：能抄走的是让对象可指认、可修改、可留存的共同尺度；抄不走的是 Minecraft 已形成的身体尺度、操作习惯与社区实践，换一套尺度时必须重新验证这些关系，而不能把一米方格当作成功公式。
