很多优秀游戏根本不需要建造。

剧情游戏可以让开发者精确安排场景、节奏和叙事；动作游戏可以把注意力集中在移动、战斗和关卡；RPG 也完全可以让成长发生在角色、装备和故事里。即使是开放世界，也不意味着玩家一定要能够自己盖房子。

所以当一个游戏加入建造、编辑器或 UGC 时，最值得先问的不是“这个功能够不够强”，而是更基础的问题：

> **为什么要把一部分创造世界和内容的权力交给玩家？创造会让原本的游戏变得更有趣，还是只是让功能列表变得更长？**

Minecraft 很适合拿来研究这个问题，因为它没有把“创造”限制在一个独立编辑器里。Survival 里的第一面墙、Creative 里的大型建筑、红石机器、Adventure Map、Data Pack、服务器玩法和 Mod，看起来差别很大，却都建立在同一种关系上：开发者先提供世界、规则与工具，玩家再继续决定这个世界会变成什么。

这一章先不讨论 WorldEdit、Axiom 或 Bedrock Editor 怎样操作。那些工具留给下一章。这里更关心的是 **Why**：为什么“创造”本身值得成为玩法，以及这条路线什么时候又会变成负担。

## 为什么创造值得成为玩法

### 创造不是沙盒游戏的必需品

“沙盒”很容易和 Crafting、Building、Survival、Open World 一起出现在功能列表里，仿佛它们天然应该成套出现。但这些系统解决的并不是同一个问题。

一个以电影化剧情为核心的游戏，可能希望玩家在正确的时间从正确的方向进入场景；一个精心调过的战斗关卡，也可能依赖掩体、路线和敌人站位。如果玩家可以随时搭一座塔、封住门口或从墙外绕过去，原本的 Encounter 设计就会被重新解释。

这并不说明自由建造和剧情、战斗不能共存。它只说明**建造是一项会改写其他系统的能力**，而不是一个可以零成本附加的装饰功能。

#### 更多功能不等于更完整

如果一款游戏最有趣的部分是高速战斗，却要求玩家频繁砍树、搬材料、铺地基，建造可能只是把核心节奏切碎；如果基地除了好看几乎没有用途，大量建材、Snap、Rotation、拆除和库存 UI 也可能只是在制造维护成本。

从产品展示角度看，`Open World + Crafting + Building + Survival` 很容易显得内容丰富。但对玩家来说，真正的问题始终是：这些功能会不会互相产生新的选择，还是只是各自占据一套菜单。

因此，创造系统首先需要证明自己的结构价值。

> **如果把建造和创作删掉，这款游戏最核心的循环究竟会失去什么？**

如果答案只是“少一点装修”，它可能只是可选内容；如果资源失去了长期去向、玩家失去了主动设定大型目标的方式、空间问题无法再由玩家自己解决，那么创造才真正进入了游戏骨架。

### 创造给玩法增加了什么

Minecraft 的建造之所以重要，并不是因为“墙能挡怪”这个事实本身有多深奥，而是因为创造能力会同时改变目标、资源、空间和玩家对结果的所有权。

#### 创造会主动生成玩家目标

任务系统通常由开发者告诉玩家下一步：去哪里、找谁、拿什么奖励。

创作目标可以反过来工作。玩家只需要产生一个念头：

> “我想在这里建一座城。”

这个目标就会继续分解出一连串问题：材料从哪里来，仓库够不够，运输怎么做，地形是否需要平整，远处资源怎样运回来，夜间施工是否安全，重复部件是否值得自动化。

于是：

```mermaid
flowchart LR
  A["我想做一个东西"] --> B["需要资源"]
  B --> C["采集 / 探索 / 交易"]
  C --> D["建造 / 改造"]
  D --> E["产生新的需求"]
  E --> B
```

开发者没有写“收集 5000 块石头”的 Quest，玩家却可能因为自己的建筑项目主动做这件事。创造因此具有一种很特殊的价值：**它可以成为其他系统的目标生成器。**

这也是为什么建造不能只按“造出来的东西有什么功能”评价。即使一座城堡最终没有数值奖励，施工过程本身已经把采集、运输、探索和规划重新组织起来。

#### 创造给资源提供长期去向

资源系统需要出口。

如果木头、石头、铜和玻璃只能做几件装备，玩家很快会遇到边际价值下降：箱子越来越满，但多一组材料并不会改变什么。

建造把资源从库存数字重新写回世界。

> 石头 → 城墙  
> 木头 → 房屋  
> 铁 → 铁轨与设备  
> 玻璃 → 温室与建筑立面

材料被消耗以后并没有消失成一个瞬时数值，而是变成玩家以后仍然会经过、使用和修改的东西。这会把资源获取和世界持久性连起来。

在 Survival 中，这种关系尤其明显。建筑材料需要玩家自己取得，而 Creative 则直接移除大量材料和生存成本，把注意力更多转向设计和迭代。官方对两种模式的区分也一直很直接。[^survival-creative]

#### 创造让环境本身成为解决问题的工具

没有环境改造能力时，地图通常是题目：玩家需要学习怎样穿过开发者给出的空间。

允许建造以后，空间也可以成为答案的一部分。

过不了河，可以搭桥；重复旅行太慢，可以修道路、铁路或 Nether 交通；资源太分散，可以建设仓库和物流；怪物生成规则足够稳定，甚至可以把环境设计成自动生产设施。

这里真正值得说的不是“墙会形成内外”，而是：

> **玩家不再只能适应环境，还能重新配置环境，改变未来行动的成本。**

一条道路的价值不只是视觉上连接两地，而是以后每一次通行都更方便；一个仓库也不只是“空间获得了仓储功能”，而是材料查找、运输和组织方式发生了变化。

这就是建造从装饰进入玩法的地方。

#### 创造把一部分 Progression 写进世界

很多游戏把成长写在角色上：等级更高、属性更强、技能更多。

Minecraft 当然也有装备升级，但长期世界里还存在另一种成长：

> 洞穴 → 小屋 → 仓库 → 农田 → 交通 → 自动化基地 → 城镇

玩家角色的数字不一定变化，生活条件却已经完全不同。成长被外化成了世界状态。

这种 Progression 有一个很特别的结果：别人进入存档以后也能直接看见。道路、机器和城市不仅记录“玩家现在有多强”，还记录过去的时间被怎样投入。

它同时也带来代价：这种成长依赖长期存档、空间维护和兼容性。对于每局十分钟就重置的游戏，把大量 Progression 写进永久建筑反而没有意义。

### 创造为什么会变成表达

前面的价值即使玩家只造最丑的火柴盒也能成立。但创造还有另一层吸引力：同一个问题可以有很多答案，而答案会带着作者自己的选择。

#### 作品不需要只有一个正确解

战斗和解谜常常要求玩家找到有效解法；创作活动却可以让“有效”只成为最低要求。

同一块空地，有人会盖中世纪城堡，有人做现代住宅，有人造工厂、像素画、巨型雕塑或完整城市。Minecraft 官方长期展示社区大型建筑时，也会把这些作品直接当作艺术表达和社区创作来呈现。[^mind-blowing-builds]

这里的乐趣不再只是：

> “我解决了游戏的问题。”

而会变成：

> **“这是我决定让它变成的样子。”**

材料、比例、布局、颜色、细节和是否保留旧建筑，都开始表达玩家自己的偏好。创造因此扩大了游戏能够承载的玩家类型：不喜欢战斗的人仍可能因为建筑长期留下来。

#### 长期使用会让作品积累记忆

旧稿里“地方感”真正值得留下的部分，其实在这里。

一间早期木屋可能既不高效也不好看，但那里发生过第一次熔铁、第一次挖到钻石、第一次从夜里逃回来。后来即使玩家已经有更大的基地，也可能不愿意拆掉它。

这种价值不是墙、门或房间本身产生的，而是**创造出来的空间长期参与了玩家经历**。

因此，创作结果既可以是工具，也可以是记忆的物理索引。长期世界越重要，这种价值越容易出现。

## 从个人作品到 UGC

创造首先可以只服务作者本人。但只要作品能够被保存、复制、上传和进入，它就会发生另一次变化：**一个玩家做出来的东西，开始成为另一个玩家可以体验的内容。**

### 玩家开始成为内容作者

Minecraft 的作者能力并不是一步跳到“开发者模式”。它有一条很长的梯子：

```mermaid
flowchart LR
  A["放几个方块"] --> B["建筑 / 城市"]
  B --> C["红石 / 自动化"]
  C --> D["Adventure Map"]
  D --> E["命令 / Data Pack / Add-On"]
  E --> F["服务器玩法"]
  F --> G["Mod / 完整系统扩展"]
```

第一阶的门槛极低。玩家不需要先理解“Editor”是什么，按下放置键就已经开始改变世界；如果继续深入，后面又存在 Structure Block、WorldEdit、Editor、脚本和 Mod 等更高层工具。

这条连续性非常重要。它让“玩家”和“创作者”不必是两个完全分离的人群。

Minecraft 今天也已经拥有正式的创作者分发渠道。官方 Partner Program 明确允许合作创作者把地图、冒险、材质、Add-On 等内容发布到 Marketplace；Java Realms 同样长期接收社区地图。[^minecraft-partner][^realms-atlas]

因此，Minecraft 的内容生产并不只发生在 Mojang 内部。

### UGC 可以形成内容飞轮

只要创作者能够把作品交给其他玩家，内容生产就可能从单一开发团队扩展成整个社区。

```mermaid
flowchart LR
  A["更低的创作门槛"] --> B["更多创作者"]
  B --> C["更多作品"]
  C --> D["覆盖更多兴趣"]
  D --> E["吸引更多玩家"]
  E --> F["其中一部分人成为创作者"]
  F --> B
```

这并不意味着 UGC 会自动指数增长。一个编辑器再强，如果作品很难发布、很难找到、升级就坏、没有反馈，也很难形成稳定生态。

真正的闭环至少还需要：

> **创作 → 发布 → 分发 / 发现 → 游玩 → 反馈 → 再创作**

UGC 的价值也不仅是“免费替开发商生产内容”。社区作者会服务开发团队根本不会优先覆盖的细分兴趣：极端 Parkour、恐怖地图、技术向 Mod、特定建筑风格、角色扮演服务器，甚至非常小众的规则实验。

当这些作品彼此吸引不同玩家时，游戏的内容边界就不再只由官方 Roadmap 决定。

## 创作门槛和表达上限并不是一回事

如果 UGC 很重要，一个自然问题是：为什么不把最强的编辑器全部直接塞进游戏里？

答案没有那么简单。创作工具通常同时面对两个相反目标：**让更多人容易开始**，以及**让少数重度作者拥有足够高的表达上限**。

### Minecraft：从游戏内建造继续向外扩展

Minecraft 的特点是第一步非常低：普通游玩状态就已经可以放置和修改世界。再往后，Creative 移除生存成本；Bedrock Editor 又提供 Multiblock Selection、Brush、Undo / Redo 等面向 Creator 的工具。[^creator-tools]

这使 Minecraft 可以让“随手盖一间屋子”和“制作大型地图”共享同一种世界表示，却不要求二者使用完全相同的工作流。

下一章[《创造模式与创作工具》](/design/creative-tools)会专门拆解这一层工具问题。

### Teardown：把 Level Editor、脚本和 Workshop 放进同一套 Modding 流程

Teardown 是另一种很好的对照。官方 Modding 页面明确提供内置 Level Editor、Lua Scripting、Mod Manager 和 Steam Workshop 集成；Content Mod 可以包含完整可玩环境和任务，脚本还能继续改变玩法。[^teardown-modding]

它说明“系统沙盒 + 官方编辑器 + 脚本 + 分发渠道”可以形成非常直接的 UGC 管线。

但即使这样，编辑器仍然不是普通游玩状态里的每一个操作。作者进入的是专门的创作工作流，需要理解场景、脚本、资源和 Mod 结构。低门槛与表达上限仍然需要分层。

### VRChat：把创作建立在外部专业工具链上

VRChat 则走得更远。官方世界制作流程要求使用 Unity 与 VRChat SDK；Creator Companion 负责创建项目，作者在 Unity 中搭建 Scene，再通过 Udon / UdonSharp 增加交互，最后 Build 并上传。[^vrchat-start][^vrchat-udon]

这提高了入门门槛，却直接利用了成熟游戏引擎已有的模型、材质、灯光、动画、Prefab 和场景工具。VRChat 不需要在客户端里重新实现一整套接近 Unity 的编辑器。

因此，“如果 VRChat 有游戏内编辑器是不是一定更好”没有必然答案。

游戏内工具可能让更多普通用户随手参与共创，但要覆盖 Unity 级别的表达能力，平台就需要自己承担大量编辑器、资产导入、脚本、优化和版本维护成本。更现实的产品设计往往是分层：让低门槛工具负责快速创作，把极高上限留给专业管线。

这里真正值得比较的不是谁的 Editor 更先进，而是：

> **你希望多少玩家能够开始创作？又希望最深入的作者最终能做到多复杂？**

## AIGC 可能继续降低“想法到作品”的距离

生成式 AI 给这条创作链带来了一个很自然的未来问题。

过去，玩家脑中有一个想法以后，往往还要把它翻译成大量工具操作：搭结构、画地形、写脚本、配置数据、测试逻辑。如果自然语言、生成模型和可编辑的游戏工具进一步结合，这个翻译过程可能继续缩短。

未来一种很合理的工作流可能是：

```mermaid
flowchart LR
  A["创作者描述意图"] --> B["AI 生成可编辑初稿"]
  B --> C["人在 Editor 中修改"]
  C --> D["实际游玩测试"]
  D --> E["继续调整 / 发布"]
```

重点不在“AI 一键替人做完整游戏”。真正有价值的是，它可能把更多人从“我有想法，但不会操作这些工具”推进到“我至少有一个可以继续编辑的初稿”。

这会让创作门槛继续下降，但不会消灭创作者。

### 当生成变便宜，稀缺的东西会转移

如果地图、任务、建筑甚至简单脚本都越来越容易生成，内容供应不足可能不再是最大问题。

新的问题会变成：

- 哪些作品真的值得玩？
- 大量近似内容怎样去重和排序？
- 谁负责测试生成结果是否可通关、性能是否正常？
- 版权、来源与作者身份怎样处理？
- 多人作品怎样避免恶意脚本和安全问题？
- 一个不断生成的世界怎样长期维护和兼容？

所以 AIGC 最有可能带来的并不是“无限内容因此没有问题”，而是瓶颈转移：

> **它可能缓解内容生产的稀缺，同时制造更严重的注意力、筛选和信任稀缺。**

UGC 平台因此不会因为 AI 出现就只剩一个 Generate 按钮。发现、评价、审核、版本管理和人与人的品味判断反而可能变得更重要。

## 创造也会伤害游戏

到这里如果只写创造的好处，很容易把所有游戏都推向“平台化”。但把作者权交给玩家是一项非常昂贵的设计选择。

### 自由建造可能破坏作者精心设计的体验

如果战斗依赖地形，玩家造墙、搭高台或封路就可能让 AI 和 Encounter 失效；如果剧情依赖从某个入口进入场景，任意地形修改会破坏演出；如果探索依赖距离和路线，随时搭建万能交通也可能让地图设计失去意义。

开发团队当然可以用不可建区域、建造限制、资源成本或专门模式处理这些问题，但每加一层限制都说明同一件事：**创造能力正在和其他核心体验争夺规则控制权。**

### 建造系统本身也有巨大成本

一套真正可用的建造系统需要的不只是“Place Block”。

它通常会带来定位、旋转、Snap、碰撞检查、拆除、资源扣除、预览、Undo、存档、Streaming、联网同步、权限、版本升级和性能预算；进入 UGC 以后，还要继续处理上传、搜索、审核、依赖、版权和兼容。

如果玩家创造的结果既不会影响核心玩法，也无法被别人体验，这些成本很可能换来的只是一个宣传页上的 Feature。

### 创造还会分散玩家注意力

一个同时拥有主线剧情、刷装、基地建设、经营、制作和 UGC 的游戏，并不会自动比专注其中两三项的游戏更好。

每个系统都在争夺玩家时间，也都要求教程、奖励和内容支持。如果创造活动和核心玩法之间没有回路，玩家可能只会感到“什么都有一点，却不知道真正应该做什么”。

因此，创造的风险不是只有技术复杂度，还有**产品焦点被稀释**。

## 怎样判断一款游戏是否真的需要创造

没有必要把 Minecraft 的答案推广成所有沙盒的标准。更有用的是，在设计阶段把几个问题问清楚。

| 问题 | 它实际在检查什么 |
| --- | --- |
| **删掉创造以后，核心循环会失去什么？** | 创造究竟是结构系统，还是附加玩法 |
| **作品会反过来改变未来玩法吗？** | 建造是功能性世界状态，还是纯装饰 |
| **创造会不会主动生成新的玩家目标？** | 它是否能拉动采集、探索、生产等其他系统 |
| **为什么玩家愿意创造，而不是只消费官方内容？** | 表达、效率、社交、挑战还是收益 |
| **为什么其他玩家愿意体验这些作品？** | UGC 是否真的拥有受众价值 |
| **创作门槛应该多低，表达上限应该多高？** | 游戏内编辑器和专业外部工具怎样分工 |
| **创造会破坏哪些作者控制？** | 战斗、剧情、路线、经济和平衡需要哪些边界 |
| **平台承担得起长期创作者生态吗？** | 工具、分发、审核、兼容和维护成本 |

这些问题的答案完全可能是：

> **这款游戏不需要建造。**

那并不是设计能力不足。反而可能意味着开发团队知道自己真正想让玩家做什么。

而 Minecraft 的答案恰好相反。创造不是主循环之外的装修房间，而是不断把资源、空间、目标、表达和社区重新连起来的一种基础能力。玩家从放下第一块方块开始，就已经拥有了一小部分作者权；之后的红石、地图、命令、Mod 和服务器，只是在不断扩大这份权力。

这也解释了为什么第三部接下来会沿着一条连续的线展开：

> **怎样让创造更容易？怎样让玩家创造机器？怎样让玩家创造玩法？又怎样让他们继续扩展游戏本身？**

下一章[《创造模式与创作工具》](/design/creative-tools)就从第一个问题开始：当创作真的成为重要活动以后，普通的逐块放置什么时候不够，Structure Block、WorldEdit、Axiom、Bedrock Editor、MCEdit 和 WorldPainter 又分别解决了什么？
