> **本章命题**：这本书可以跳读，但不可跳过卷二前四章——体素、动词、生存、创造模式是后面所有判断的地基，跳过它们的人，在卷三和卷四读到的只会是一串断言。

## 这不是一本什么书

不是攻略——不带步骤。不是维基——不追求全。不是怀旧合集——2012 年的情怀在这里是研究材料，不是结论。也不是控诉信——微软和 Marketplace 会被当作可查证的商业与治理问题来写。

它是一本「为什么」的书：为什么方块是 1 米；为什么没有技能树；为什么官方修一个 bug 会让服务器连夜打补丁；为什么「下一个 Minecraft」这么多年没出现。

## 两类读者，两条走法

如果你是**资深玩家**：按卷顺序读。每章先看开头的「本章命题」和「问题」一节，感兴趣再沉进小节。开发者味道重的章节（卷三的大部分、卷二的第 8/15/16 章）可以只读命题和结尾。你要的收获是「原来如此」——把玩了十年的直觉换成说得出口的原因。

如果你是**开发者**：建议走法是 序 → 卷二全部 → 卷一第 4–6、12 章 → 卷三第 17–18 章收尾；卷三的实现细节按需再补。你要的收获是原则加不可迁移条件——每条可迁移原则旁边都写着它在什么前提下才成立，别把前提当脚注忽略。

| 读者 | 顺序 | 可跳过 |
|------|------|--------|
| 资深玩家通读 | 按卷顺序 | 开发者侧重章可只读命题与结语 |
| 玩法设计师 | 序 → 卷二全部 → 卷一第 4–6、12 章 → 卷三第 17–18 章 | 卷三实现细节 |
| 引擎/技术程序 | 序 → 卷二第 1–2、7 章 → 卷三全部 → 卷四 | 卷一第 6 章 |
| 制作人/商业 | 卷一全部 → 卷二第 11–16 章 → 卷三第 15–17 章 | 红石与渲染 |

每卷开头有一篇卷导读，写明该卷的命题和各部地图；附录提供年表、人物、双版本对照表和术语表，供查阅，不承担论证。

## 为什么正文从体素讲起

卷二第 1–4 章（体素、动词、生存、创造模式）是全书的冻结层——后面所有「Minecraft 味」的判断都回溯到这四章。它们排在历史之后、技术之前，是因为历史提供它们怎么来的证据，技术提供它们要付的代价。跳过这四章直接进卷三或卷四，后面的每个判断对你都只是断言，你既没法同意，也没法反驳。

## 从哪里开始

卷一从[《从 Infiniminer 到 Cave Game》](/history/infiniminer)讲起，那是多数读者的自然入口；关心「这套系统凭什么好玩」的可以直接进[卷二](/design)，关心引擎和规模的进[卷三](/impl)。卷四[《重写》](/rewrite)请留在最后——它是考试，考前得先上完课。如果还没读过[《全书的命题》](/prelude/thesis)和[《体例与方法》](/prelude/method)，先读那两篇：一篇说这本书在证明什么，一篇说它凭什么值得信。

## 这一章留下什么

- **爱好者**：这本书替你把「感觉」翻译成「机制」，你只需要带着玩过的经验来对账。
- **开发者**：跳读路径是设计出来的，但卷二前四章不可跳——地基章省下的三小时，会在卷四变成三倍的困惑。
